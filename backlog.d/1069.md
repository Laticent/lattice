# lint: proseWordCount counts fenced-code content as prose (wall-of-text false positive on decks with code/anima blocks)

## Summary

`proseWordCount` in `lib/authoring/review-core.js` (~line 76) strips headings and the `_class` directive when tallying a slide's prose, but it does **not** strip fenced code blocks. So the contents of a ` ``` ` block — code, JSON, an ` ```anima ` scene spec — are counted as prose words, which can trip the advisory **wall-of-text** check (`SLIDE_PROSE_BUDGET`, 70 words) on a slide whose *actual* prose is well under budget.

This is **advisory-only** (`severity: 'suggestion'`, "never blocks") — no gate or test fails. Filing it because it produces a misleading nag on legitimate, code-bearing slides.

## How it surfaced

PR #1068 gave the `scene` component's insert `skeleton` a live ` ```anima ` spec. The skeleton's real prose is ~13 words, but `proseWordCount` tallies **138** (the anima JSON keys/values — `source`, `built`, `duration`, `elements`, `rig`, `group`, …), so `npm run lint:deck` on an inserted `scene` reports:

```
ℹ slide 1 · wall-of-text — a dense slide … push the detail to speaker notes
```

pointed at a spec the author is meant to keep. On `main` (poster-only skeleton) the same slide counted 61 words and linted clean. `scene.skeleton` is the **only insert skeleton** over budget, so the insert flow is where this reads worst.

## Fix

Strip ` ``` `-fenced blocks in `proseWordCount` the same way headings and directives are already stripped, before the word tally. A code/JSON block is not prose.

Blast radius to weigh (why this is its own change, not part of #1068): this shifts the wall-of-text tally for **every** deck that contains fenced code — several existing over-budget component samples (gantt ~106, redline ~109, policy-recommendation ~99, citation-card ~89) would drop. That's a correctness improvement, but it's a shared-linter behavior change that wants its own before/after check and a maker-checker pass, so it was deliberately kept out of the content-only PR #1068 (HARD RULE #18: off-path defect → track, don't pull in).
