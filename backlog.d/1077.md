# anima: live scenes on a multi-scene DeckPreview page don't pause when scrolled off-screen

## Summary

Anima scene hydration is now wired into `DeckPreview` (Stage 6b, Present-mode), reusing the **parent-hosted** `createAnimaScenes` controller which mounts scenes **eagerly** (`docs/src/playground/anima-scenes.ts` passes `hydrateScene(section, { eager: true })`). Eager mount means no per-scene `IntersectionObserver`, deliberately — a *parent-context* IO observing an element inside a transform-scaled child `srcdoc` iframe is unreliable (the reason slice A chose eager for the Playground).

That's fine for the surfaces shipping today:
- **Studio Present** — one active, on-screen slide at a time. No issue.
- **Hidden hosts** (a `HeroPreview` flipped to its Source tab) — handled in the Present-mode PR: `DeckPreview` now tears the scene down on the falling edge of `active` and re-hydrates on the rising edge.

The **uncovered** case: a single **scrolling page that renders several `scene` specimens through `DeckPreview` at once** (a future showcase/gallery). Every scene is `active` and mounted, so each runs a parent-hosted `requestAnimationFrame` loop continuously — including the ones scrolled below the fold — with nothing to pause them. N always-on loops burning CPU/battery.

**Not a regression and not currently reachable:** before Stage 6b those surfaces showed a frozen poster, and no shipping marketing/showcase deck uses the (new) `scene` component yet. Logging per HARD RULE #18 so the multi-scene perf profile isn't a silent walk-past.

## Fix options

- A **parent-level** `IntersectionObserver` on the `DeckPreview` `<figure>` (`stageRef.current`) — that element lives in the PARENT document, so a normal IO is reliable there (unlike the cross-frame per-section IO the host avoids). Freeze the scene when the figure leaves the viewport; resume on re-entry. Needs a `pause()`/`resume()` (or freeze) surface on the `createAnimaScenes` controller (today it exposes only `rebind`/`destroy`).
- Or thread an `eager: false` option down for hosts that can guarantee a same-context observer.

## Provenance

Found by the maker-checker on the Present-mode PR (Stage 6b, slice B), finding #1. The inactive-host half was fixed in that PR; this is the off-screen-scroll remainder.
