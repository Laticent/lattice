# spike(engine): decorator-stamped intent — name the default variant so recipes are opt-in, not opt-out

## Summary

Investigate and decide the model for how universal treatments attach to slides: today a component's default recipe is selected by **structural shape**, so any variant that happens to produce that shape inherits a treatment it never asked for and must escape it — either by an `:not(.variant)` exclusion chain on the base, or by an undo block on the variant. This card produces the decision doc; it changes no CSS.

## Context

### The defect

The base recipe selects on shape, not intent:

```css
section.compare-prose:not(:has(.compare-prose-inner))
  > .cell-stage > :is(ul, ol) > li:has(> strong:first-child)
```

That reads "any card whose item begins with a bold label." The `compare-prose axis` variant (#1207) produces exactly that shape from ordinary `1. Title` + nested-body authoring, so it inherited the corner-tag chip treatment and had to undo 12 declarations to escape it.

The marker is `slotLabelLift`'s output — it means only *"this item had a title."* **46 rules across 6 components** all key on `strong:first-child` and each reads it as "therefore mine."

### Measured scale

| Symptom | Count |
|---|---|
| `:not(.variant)` exclusions in component CSS | **343** |
| rules chaining 2+ `:not(.variant)` | **87** |
| files carrying chained exclusions | **13** of 61 |
| rules keyed on the shared `strong:first-child` marker | **46** across 6 components |

Longest selectors today: `regulatory-update` 191 chars, `statute-stack` 160, `authority-chain` 145, `kpi` 139, `compare-prose axis` 130.

### Why it's worse than verbose

Cost is O(variants x base rules), and it fails **silently**. A new variant that misses one `:not()` slot, or an undo block that misses one property, produces a wrong-looking slide with no error. It is also directional: adding a property to a base recipe silently makes every existing undo block incomplete — the undo cannot know what it does not yet know.

Live example from #1207: the `axis` opt-out restored the chip's geometry but not its ink or font face, rendering the facet title near-white on a light card. Caught by eye, not by any gate.

### Leading candidate — declare the default in the MANIFEST

The manifest is the strongest candidate for where intent is declared, and the machinery already exists:

- `compare-prose.manifest.json` declares `variants: ["transition", "mirror", "chosen", "decision", "vertical", "banner-tag", "rejected", "axis"]` — and **no default field**. The unnamed default is the same root defect one layer up from the CSS.
- **Manifest-to-generated-CSS is already shipped**: `tools/build-css.js:220` generates per-family slicing CSS from each Frame manifest's `slicing` block (emitted at line 554). So a `defaultVariant` field driving generated selectors/stamping is an existing pattern, not a new mechanism.
- It keeps one source of truth per HARD RULE #1, sits next to the `variants` array it belongs with, and gives `checkVariantDeclaration` a natural place to enforce "every component with variants names its default."

Spike should confirm: whether the generated output is a stamped class, a generated selector prelude, or both; and whether the schema addition is additive for the 61 existing manifests.

### Rejected as stated — "do it in a transformer instead of CSS"

The pipeline is **already** decorator-driven: the `<strong>` the recipe keys on is created by `slotLabelLift`. A transformer that decorated by the same structural heuristic would reproduce the bug exactly — it would stamp `axis` cards too, and the opt-out list would move into JavaScript where `build:check` and the cascade gates cannot see it. Strictly worse. The axis is **shape vs intent**, not CSS vs JS.

### Direction to evaluate

Give the default a name. Transformers already stamp classes (`chart-frame`, `form`, `lat-pill`, `lat-focus`, and `proof`/`cat-N` from #1207), so the stamping mechanism exists — it just is not used for "the default variant." Base rules would become `section.compare-prose.cards > ...`; a variant simply does not match. No exclusion chain, no undo, no silent incompleteness.

Open questions for the spike: deck-level vs slide-level opt-out; what happens to an author who wants the default treatment *and* a variant; whether the stamp belongs in the shared kernel (HARD RULE #1) or per-component; and whether naming defaults interacts with the frozen layer activation (HARD RULE #26).
