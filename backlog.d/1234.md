# Adaptive ADR audit — the gaps left open by #1220

## Summary

A two-ADR conformance audit ran alongside #1220. Six findings were fixed in that
PR; these are the ones deliberately left open, with the reason each was deferred.

## A. The split ADR contradicts itself

- [ ] **§0a / R9 say "cover always"; the shipped code deliberately does not.** A
  title-less enrolled slide splits with **no cover** at all four portrait-family
  sizes. §9's P-envelope note 1 explicitly sanctions that, so the absolute wording
  in §0a is what is wrong, not the code. Decide which is authoritative and make one
  match the other.
- [ ] **§0c completeness is stale three ways.** It claims "every one of the **59**
  components"; the catalog is **61**. `matrix-grid` and `premise` appear nowhere in
  the prose — their placement exists only in `lib/core/split-facts.js` `TREATMENTS`.
  `roadmap` is recorded *atomic* where the code has moved it to *read-across*.
- [ ] **R11 says the oracle "records a verified default, never mints one"** — but
  `bless-split-oracle.js` / `checkSplitOracle` only diff recomputed manifest facts.
  There is no demo-deck or sign-off precondition, so a new component's split
  behaviour is minted by whoever runs `--bless` first.
- [ ] **§0b's "one body type size across every portrait preset" is false.**
  `orientationFor` ramps `--canvas-scale` by aspect, and the same `glossary` run
  renders a table at portrait/story/square but a stacked, header-less form at mobile.

## B. The two ADRs disagree with each other

- [ ] **The two blessed oracles record opposite terminals for the same slides.**
  `family-overflow.json` blesses 22 components as *clipped* at portrait; **16 of
  those** are recorded in `split-oracle.json` as enrolled and splittable — they fit
  once `autosplit: on` is set. Mitigated in #1220 (the record now states its own
  semantics inline), but **neither ADR says that "never a truncation" is conditional
  on the author opting in.** That belongs in the prose, not just in a JSON note.
- [ ] **§0c cites an `@container (aspect-ratio <= 0.9)` mechanism for `matrix-2x2`
  that the reflow ADR deleted** — and added a unit test specifically to keep deleted.
- [ ] **`premise`'s split treatment was decided in the reflow ADR's slice**; the split
  ADR never places it.
- [ ] **§0b's one-bucket "portrait presets" vs the reflow ADR's four families.** The
  audit showed why this matters concretely: `portrait` and `story` are the same
  family but clip 22 vs 9 components.

## C. Render defects, deferred with reason

- [ ] **`premise`'s lede repeats on every split body page** instead of hoisting to the
  cover, contradicting §0a's masthead spec. Reproduced at portrait, story and mobile.
  Arguably introduced by #1220 (that PR gave `premise` its split), but the fix is in
  the shared split envelope rather than in `premise`, so it was not pulled into a
  reflow PR.
- [ ] **`--row-mark` hue restarts across a split.** `premise`'s ordinals now continue
  correctly (`01–04` then `05–08`) because they moved to the built-in `list-item`
  counter, but the colour cycles on `nth-child` *within each `<ol>`*, so page two
  restarts at the first hue. Cosmetic. The robust fix is a transform stamping each
  row's absolute index; `premise` has no transform today.
- [ ] **`list-steps` losing two of six members at square — UNCONFIRMED, worth a second
  look.** Reported as the audit's highest-severity finding, but it does **not**
  reproduce: the component's own gallery at `size: square` with `autosplit: on`
  renders 27 pages with zero overflow. The reporter measured a synthetic probe deck.
  A synthetic deck that loses content is still evidence of *something*.

## D. The capacity numbers are still not grounded

- [ ] **`inventory` declares `adapt.capacity.tall.hard: 8` against a measured ceiling
  of 3**, which is why its four-item gallery slide clips 594.6px at portrait
  (identical on `main` — pre-existing). Deliberately not corrected in #1220: the tool
  holds words at the declared `density.soft` of 14 while inventory's own skeleton
  writes "a name and one clause", so replacing 8 with 3 swaps one unverified number
  for another.
- [ ] **The real fix is the basis.** Per the reflow ADR's capacity section, ceilings
  should be measured against each component's **own skeleton**, not a declared
  density nobody writes to. That is a derivation, not another hand-maintained number.
  `stats` is the worked example: declares `density.soft: 8` with the note "a metric
  label, not a sentence", while its own skeleton uses **two** words.

## E. Audit coverage the audit itself did not reach

- [ ] **~97 of 265 cells in the reflow-ADR table are UNVERIFIED.** That is a scoping
  failure on my side, not a code problem — the maker was given exhaustive
  render-verification with no budget and no stopping rule, ran for hours, and had to
  be interrupted. The cells are honestly marked rather than inferred. Re-run with a
  render budget if the coverage is wanted.
