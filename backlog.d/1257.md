# studio(front-matter): the lexicon: / acronyms: writers still rebuild the whole block

## Summary

#1256 moved all 27 **flat-scalar** front-matter writes onto the lossless `writeFrontMatterLine` and deleted `setFrontMatter`. Two writers were explicitly scoped out by that card and still call `parseFm` + `emitFm`, i.e. still rebuild the entire block:

- `setFrontMatterBlock` — the `lexicon:` writer (Deck setup → **Speech** → Lexicon)
- `setFrontMatterAcronyms` — the `acronyms:` writer (same tab)

Both are reached by real deck-scope controls, so **editing a deck's lexicon or acronym registry still destroys everything `parseFm`'s grammar does not model** — exactly the losses #1256 fixed everywhere else:

- YAML comments — gone
- `_`-prefixed keys (`_class:`, which the engine accepts and `parseFm` does not) — gone
- `style: |` block scalars — corrupted to the literal `"|"`, CSS body deleted
- flow sequences (`tags: [alpha, beta]`) — stringified
- key order — rewritten; CRLF — normalized to LF
- on a deck whose leading `---` is a slide separator — the swallowed slide deleted outright

## Repro

Paste this into the Studio, then add one lexicon entry:

```markdown
---
# legal signed off on this footer
theme: indaco
_class: lead
style: |
  section.title h1 { color: red; }
tags: [alpha, beta]
---

# Q4
```

## Why it wasn't fixed in #1256

The card scoped these two out on the grounds that they "legitimately own a whole nested block", and that half is true — a nested-block writer really does re-emit its own block. What does *not* follow is that it may re-emit everything **around** it. Fixing this needs a nested-block **span** finder (the `frontMatterKeySpan` equivalent for a bare `key:` header plus its indented children), so the block writer can splice its own region and leave the rest of the file alone. That is a different piece of work with its own edge cases — blank lines inside a block, a dedent that ends it, a block that is the only content — and folding it into #1256 would have doubled an otherwise mechanical diff.

Logged rather than pulled in, per HARD RULE #18 (pre-existing, off the path of #1256).
