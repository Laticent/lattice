# studio(panel): one settings row, so the keyboard pin is a property of the row and not of one file

## Summary

#1258 made the row you type in pin itself above the keyboard on a phone (`PINNED_FIELD_ROW`). It reaches exactly one component: `Field` in `StudioShell.tsx`, which is **not exported**. So it covers that file's 25 rows and nothing else — and the sharpest uncovered case is one tap away.

Make the pin a property of "a settings row" by giving the Studio **one** shared row primitive in `panel.tsx`.

## What's actually wrong

**The Slide tab, beside Deck in the same sheet, has the identical defect.** `SlideContext.tsx` defines its own `Row` (line 80) with near-identical geometry, and its **three `<textarea>`s** sit in an `overflow-y-auto` body (line 483). Same shape, same sheet, no pin.

Two near-duplicate primitives, differing only in ways that are all expressible as props:

| | `StudioShell.Field` | `SlideContext.Row` |
|---|---|---|
| block margin | `my-2` | `my-1.5` |
| row | `flex items-center justify-between gap-2.5` | `flex flex-wrap items-center justify-between gap-x-2.5 gap-y-1.5` |
| label | `<label htmlFor>` (shrink-0) or `<span>` | `<span>` only |
| inline hint after label | — | yes (`ml-1.5 text-[11px]`) |
| help line below | identical styling | identical styling |
| pins on focus | **yes** | no |

`flex-wrap` is deliberate on `Row` and must survive: it lets a segmented control drop below the label when the Settings panel is dragged narrow. So it becomes a prop, not a casualty.

## ★ Scope correction — this is 2 → 1, not 3 → 1

`PrintOptionsPanel.tsx` also defines a `Field` (line 457) and it is **not** the same animal: `space-y-2` rather than a block margin, `items-baseline`, a **semibold `--text-heading`** label, the hint on the *right* of the row, and children **below** the row rather than beside it. That is a stacked group heading, not a label-left/control-right row. **Do not fold it in** — forcing it would flatten a shape that is correct for that panel. Rename it (`PrintGroup`?) so it stops colliding by name, and leave its markup alone.

An earlier framing of this work said "collapse the three into one". That was wrong, and inspecting them is what corrected it.

## Done when

- One exported row primitive in `docs/src/components/ui/panel.tsx` carries `PINNED_FIELD_ROW`; `StudioShell.Field` and `SlideContext.Row` are both gone, replaced by it.
- `flex-wrap`, the inline `hint`, the `htmlFor`/`descId` pair, and both block margins are reachable through props — no call site loses behavior it has today.
- **A test asserts the Slide tab's speaker-note textarea pins**, in the same shape as the existing `PINNED_FIELD_ROW` declaration tests.
- `PrintOptionsPanel`'s row is renamed and its rendered markup is byte-identical.
- Measured on the built site at 390px: the Slide tab's note row goes `static` → `fixed` at the sheet's bottom edge on focus → `static` on blur, and every other row stays `static`.

## Out of scope

The panels that use **bare `<input>` with no row primitive at all** — Fabricate, MotionStudio, FinishStudio, TtsSettings, SlideComments — cannot adopt a shared row without redesigning their forms. They need a different mechanism and are tracked separately (see the sibling card). The gate that would catch a *new* unpinned input belongs with that work, not here: added now it would fail immediately against a large allowlist.
