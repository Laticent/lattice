---

## Step 1: Bootstrap the NPM Package

1. Create a temporary `.npmrc` file in the project root containing:
   `//registry.npmjs.org/:_authToken=${NPM_TOKEN}`

2. Build the project:
   `pnpm build`

3. Execute the initial public publish to register the package name on npm:
   `pnpm publish --access public --no-git-checks`

4. Immediately delete the temporary `.npmrc` file once the publish completes.

---

## Step 2: Configure Repository Architecture

1. Setup Changesets:
   - Install `@changesets/cli` as a root dev dependency:
     `pnpm add -D @changesets/cli`
   - Initialize changesets: `pnpm changeset init`
   - Update `.changeset/config.json` to ensure:
     - `"access": "public"`
     - `"baseBranch": "main"`
     - `"commit": false`
     - `"updateInternalDependents": "patch"`

2. Add Package Scripts:
   - Add the following script commands to root `package.json`:
     - `"changeset": "changeset"`
     - `"version-packages": "changeset version"`
     - `"release": "pnpm build && changeset publish"`

3. Create GitHub Actions Release Workflow:
   - Create `.github/workflows/release.yml` with the following configuration:

~~~yaml
name: Release Pipeline

on:
  push:
    branches:
      - main

concurrency: ${{ github.workflow }}-${{ github.ref }}

jobs:
  release:
    name: Canary & Stable Release
    runs-on: ubuntu-latest
    permissions:
      contents: write       # Required to create Git Tags and GitHub Releases
      id-token: write       # Required for npm OIDC Trusted Publishing
      pull-requests: write # Required for Changesets to open/update PRs

    steps:
      - name: Checkout Source
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node.js & pnpm
        uses: actions/setup-node@v4
        with:
          node-version: 22
          registry-url: 'https://registry.npmjs.org'

      - name: Install pnpm
        uses: pnpm/action-setup@v3
        with:
          run_install: true

      - name: Build Project
        run: pnpm build

      # Track 1: Canary Publishing (Runs on every merge to main)
      - name: Publish Canary to @next
        run: |
          pnpm changeset version --snapshot canary
          pnpm changeset publish --tag next
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      # Track 2: Stable Weekly Release (Runs when Changeset Release PR is merged)
      - name: Create Release PR or Publish Stable
        id: changesets
        uses: changesets/action@v1
        with:
          publish: pnpm changeset publish
          version: pnpm changeset version
          title: "chore: release weekly version"
          commit: "chore: update package versions"
          createGithubReleases: true
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
~~~

4. Verification:
   - Verify that all modified JSON, Markdown, and YAML files pass syntax validation.

## Done when

* npm Publishing: Artifacts and libraries are published automatically to npm using OIDC Trusted Publishing.
* Canary Deployments: Every pull request merge to main publishes a snapshot pre-release tagged as @next.
* Stable Releases: The @latest npm tag points to the current stable release version.
* README Badges: README.md at the project root displays badges/tags showing the current @latest version, @next version, and CI build status.
* GitHub Releases & Tags: Each weekly stable release automatically creates a Git tag on main and publishes a GitHub Release containing changelog notes.
* True Semantic Versioning: Release versions follow strict SemVer rules (MAJOR.MINOR.PATCH) based on API impact rather than arbitrary calendar schedules:
  * PATCH: Bug fixes, refactors, and non-breaking internal changes.
  * MINOR: Backward-compatible new features.
  * MAJOR: Breaking API changes.
* Pre-Generated Changesets: Claude Code reasons about versioning during feature development, determines the SemVer impact, and pre-generates a Changeset file (.changeset/*.md) prior to merging.
