# The chart categorical cycle has no curated ink — charts still run the live color-mix the --cat-* tier retired

## Summary

Give the chart categorical cycle (`--chart-cat1..8`) a curated, generated ink the way `--cat-1-ink … --cat-12-ink` already has, and delete the render-time `color-mix(… 65%, var(--text-heading))` the charts use to make a graphical ink safe for text.

## Swimlane

`engineering/decisions/2026-07-15-categorical-token-contract.md` — **Track 4** already proposes factoring the two derivations into one shared CSS partial "imported by both chart-family and the cat block (no drift, #1/#15)". This card is the ink half of that.

Method to copy: `tools/derive-cat-ink.js`, whose header documents this exact problem for the other tier.

## Background — two tiers, only one curated

- **`--cat-N-*`** (theme, 12 slots). `--cat-N-ink` is **generated** by `tools/derive-cat-ink.js` and committed per palette: keep the mark's hue and chroma exactly, move only lightness by binary search until it clears AA against **both** `--bg` and `--bg-alt` (solved to 4.65:1 for rounding headroom). Consumed by `roadmap`, `premise`, `split-panel`, `statute-stack`, `authority-chain`, `obligation-matrix`, `math` as `var(--cat-N-ink, var(--cat-N-mark))`.
- **`--chart-cat-N-*`** (chart family, 8 slots, seeded by a theme's `--chart-catN`). `--chart-cat-N-ink` is **derived in CSS** — `light-dark(hue, color-mix(hue 78%, white))` — which is the *graphical* tier, gated at the 3:1 WCAG 1.4.11 floor for dots, strokes and borders. There is no text-safe ink in this cycle.

The two cycles are genuinely different hues, so the curated tier cannot simply be borrowed. In `indaco`:

| slot | `--cat-N-mark` | `--chart-catN` |
|---|---|---|
| 2 | `#863236` dark red | `#9C3F00` rust |
| 3 | `#7B772D` olive | `#2E6F00` green |

## The consequence, measured

Where a chart needs to paint **text** in a categorical color, it makes the graphical ink safe at render time:

```css
/* quadrant.styles.css:233 — .quadrant-label (the four region names) */
fill: color-mix(in oklab, var(--cell-ink, var(--quadrant-label-ink)) 65%, var(--text-heading));

/* matrix-grid.styles.css:174 and :233 — the same recipe, twice */
color: color-mix(in oklab, var(--row-ink, …) 65%, var(--text-heading));
```

That is precisely the recipe `derive-cat-ink.js`'s header records as tried and replaced for the other tier ("contrast-correct and measurably OFF BRAND"). Measured over **all 14 palettes × 2 modes × 8 slots = 224 pairs** (166 of them chromatic, source chroma ≥ 0.05 — hue is meaningless below that):

| | chart tier today | what motivated the `--cat-*` generator |
|---|---|---|
| worst hue shift | **18.1°** (`crepuscolo` light slot 8) | 14.9° |
| mean hue shift | 4.0° | — |
| mean chroma kept | **66%** (a third mixed away) | 72% (28% away) |
| worst chroma kept | **45%** (`burgundy` light slot 6) | — |
| contrast vs `--bg` | 4.99:1 … 18.58:1 | — |
| pairs below AA | **0** | — |

**This is not a contrast defect.** Nothing fails AA, and `check-viz-render` gates it. It is over-correction: the mix sits as high as 18.6:1 against a 4.5 floor and pays up to 55% of the chroma and 18° of hue for headroom it does not need. The theme author curates a hue; the reader sees it sheared toward the heading ink, unevenly across slots.

## Done when

- `--chart-cat-N-ink` is a **committed, per-palette** value in `themes/*.css` (not a CSS derivation), produced by a generator run inside `npm run build` in write mode, with `--check` for CI — same shape as the existing ink block, so a hand-edit is regenerated over rather than silently kept.
- The generator and `derive-cat-ink.js` share one recipe (Track 4's shared partial or a shared module) — two copies of the solve is the drift this card exists to prevent.
- `checkCatContrast`-equivalent gating covers the new block: AA against `--bg` and `--bg-alt` in both modes, all 8 slots, all palettes.
- The `65%` mixes are **deleted** — `quadrant.styles.css:233` and `matrix-grid.styles.css:174,233` read the curated ink directly.
- Re-measured fidelity: mean chroma kept ≥ 90% and worst hue shift ≤ 3° across the same 224 pairs (the generator moves lightness only, so this should be near-perfect; the numbers above are the baseline to beat).
- Visual sweep at both modes across the palettes — **this change is not visually neutral by design**, so the diff wants eyes, not just a green gate.
