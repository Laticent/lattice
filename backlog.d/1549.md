# math: three variants centre the MASTHEAD with the body, dropping the title ~150px off the top berth

## Summary

`math compare`, `math matrix` and `math matrix decompose` apply `align-content: center` to the **whole `<section>`**, so the eyebrow + `h2` are centred along with the body. The title lands ~150px below the top berth with a void under the running header, while plain `math` — and every non-sovereign component — anchors its framing at the top.

## Swimlane

`engineering/decisions/2026-07-30-masthead-framing-fills-the-band.md` § The principle — *"On every other component the framing text frames someone else's content. It is chrome."*

Related model docs: `engineering/decisions/2026-07-14-one-frame-model.md` (the `flow` / `canvas` / `sovereign` partition), `engineering/decisions/2026-06-26-frames-as-flex-cell-trees.md` § 6.

## Measured evidence

Real Studio (`astro preview` build, Chromium 1440×900), offsets are from the section's top edge to the element's top edge:

| slide | `display` | `align-content` | eyebrow top | `h2` top |
|---|---|---|---|---|
| `math` | `grid` | `start` | **92px** | **154px** |
| `math compare` | `block` | `center` | **242px** | **284px** |
| `math matrix decompose` | `block` | `center` | **243px** | **281px** |

Patching only `section.math.compare { align-content: start }` in the live frame moves it back to 92 / 134 — i.e. the masthead offset is entirely this declaration, nothing downstream.

## Root cause

Three declarations centre the entire section rather than just the body region:

- `lib/components/math/math/math.styles.css:443` — `section.math.compare { display: block; align-content: center; }`. The comment states the intent as *"pull the columns to the vertical middle"*, but on a block container `align-content` centres **all** in-flow children, and `h2` is a `column-span: all` spanner, so the title rides down with the columns.
- `lib/components/math/math/math.styles.css:609` — `section.math.matrix { align-content: center; }` on the 3-row grid (`auto auto 1fr`), so rows 1 and 2 — eyebrow and title — are centred too.
- `lib/components/math/math/math.styles.css:654` — `section.math.matrix.decompose { display: block; align-content: center; }`. Its own comment is explicit that it centres *"the whole group (title → lead eq → divider → subhead → component row)"*.

## Why this is a defect and not a variant style

`math` is classified `sovereign` in `lib/forms/cell/masthead/stage-catalog.generated.js:39`, so it is chrome-exempt: it never gets `.cell-masthead` / `.cell-stage` and drives its own title grid (`section.math > h2 { grid-row: 2 }`). The `sovereign` exemption exists for the **bookends** — `title`, `closing`, `divider` — where the framing *is* the content and a bespoke composition is theirs to make. On `math` the framing frames an equation: it is chrome, and the 2026-07-30 principle says a component does not compose its own chrome.

The exemption is also what makes this invisible to the shared machinery: `section:not(.math)` is written explicitly into `lib/base/base.modifiers.css:212` and `lib/base/base.accent-finish.css:156`, so no `.cell-stage` rule can reach these slides.

Grep counts, for scale: `masthead`/`cell-stage` references — `lib/components/math/math/math.styles.css` **0**, `lib/components/chart/_chart-family/chart-family.css` **21**.

## Open question for whoever takes this

Two shapes are available and they differ in blast radius:

1. **Local** — keep the sovereign frame, move `align-content: center` off the section and onto a body-only wrapper (or restore the 3-row grid on `.compare`/`.decompose` and centre only row 3). Small, contained, no cross-component risk.
2. **Structural** — reclassify `math` out of `sovereign` so it takes the shared `.cell-masthead` / `.cell-stage` frame like the chart family. Removes the whole class of drift, but touches the stage catalog, its drift test (`test/unit/forms/stage-catalog.test.js`, which pins the historical partition exactly), and every `:not(.math)` carve-out above.
