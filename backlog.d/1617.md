# verify(studio): the crash report on real iOS Safari — discoverability, layout, and the missing memory trend

## Summary

The Studio crash sentinel (#1584) ships with iOS Safari marked **UNVERIFIED**. No device is reachable from the build sandbox, so what was actually done is: the panel was read at a 390px viewport in a desktop Chromium. That is a layout check, not a device check (HARD RULE #23).

Three things specifically need a real phone:

1. **Discoverability.** The entry point was moved to Workspace → **General** during #1584 precisely because it was reported missing on a phone — the original placement was on a tab the reporter never reached. Whether General is genuinely the first thing a thumb finds has not been tested on a real device.
2. **Layout.** Sheet height, safe-area insets, and whether the breadcrumb trail and the "What gets shared" block scroll inside their own boxes rather than pushing the page wide.
3. **The empty memory trend.** `performance.memory` does not exist on Safari, so an iOS report carries no memory trajectory at all. The panel is written to say so rather than imply a healthy heap — that copy has never been read on the device it is written for.
