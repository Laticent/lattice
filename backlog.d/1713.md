# feat(export): write a slide background into PPTX so a rounded deck can keep its corner

## Summary

#1711 classifies `pptx` as a format that cannot hold a rounded corner, so a `corners: rounded` deck exports square to PowerPoint. That is correct **today** but it is not a property of the format — it is a consequence of an implementation gap, and the capability table currently records it in a way that will read as a measured fact a year from now.

Raised by the Munger inversion lens during #1711's adversarial review, which put it plainly: *"a table row reading `pptx | … | SQUARE`, sitting next to `jpeg | no alpha channel exists in the format`. In twelve months those two rows read identically as measured truths, and nobody reopens the one that was actually a TODO."*

## The actual situation

A PPTX slide image is a PNG and **can** carry alpha. The reason the corner cannot be trusted is that neither exporter writes a `<p:bg>`, so the transparent corner shows the theme background of whoever opens the file — the corner color becomes a property of the recipient's software. Verified in `ppt/slides/slide1.xml` on both exporters during #1711.

But that is fixable. Setting the slide background to the deck's own canvas color would make the corner show **the deck's ground**, which is strictly better than square:

- CLI: `lib/export/pptx-export.js`
- Studio: `docs/src/components/studio/export/deck-export.js` (the `pptxgenjs` path, ~line 1120 — `pptx.defineLayout` / `addSlide`)

pptxgenjs supports a per-slide background; the CLI path builds its own OOXML. Roughly ten lines each, plus deciding what color to use when a slide carries its own canvas (an `image` backdrop, a finish layer, a per-slide `_class: light` in a dark deck).

## Swimlane

`engineering/decisions/2026-08-17-corner-export-capability.md` — the capability rule and its per-format measurements. This card is the `pptx` row's escape hatch.

## Done when

A `corners: rounded` deck exported to `.pptx` from **both** exporters opens with rounded slide corners over the deck's own background color, on a PowerPoint template whose theme background is something else (test with a dark template and a light one). The `pptx` row moves from SQUARE to ROUNDED in `lib/core/corner-export-capability.mjs` with its measurement, and the decision note is updated. If the investigation concludes it genuinely cannot be done well, the row stays SQUARE and the note records *why* — so the question is closed rather than forgotten.
