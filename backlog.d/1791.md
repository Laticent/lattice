# ai(eval): the four AI faculties are only tested against fake replies — stress-test theme/component/finish/motion across Haiku, Sonnet and Opus

## Summary

Stress-test the four AI authoring faculties — **theme, component, finish, motion** — against Haiku, Sonnet and Opus on a frozen prompt set; measure structural determinism and usability, not just "it parsed"; fix what the matrix exposes.

## Swimlane

`engineering/decisions/2026-06-29-ai-component-generation.md` § 10 (PROTOTYPE-FIRST — the frozen, held-out, adversarial prompt set + falsification harness) and `engineering/decisions/2026-06-29-studio-theme-ai.md`. This card generalizes the §10 harness from one faculty and one model to **four faculties × three model tiers**, and adds the two axes §10 never measured: run-to-run stability, and a usability bar distinct from the structural gate.

## Done when

A single command produces a **4 × 3 matrix** (faculty × model) over the frozen prompt set, and every cell reports four measured rates:

| metric | what it means | today |
|---|---|---|
| **parse** | the reply yields the expected object at all | measured for `component` only |
| **gate** | the coerced result clears its deterministic disposer | measured for `component` only |
| **usable** | it clears a *quality* bar, not just a structural one (per-faculty, defined below) | **never measured** |
| **stable** | N repeats of the same prompt produce the same *structure* (same keys / same vocabulary choices; colour values may differ) | **never measured** |

Plus: a committed baseline of those rates that a re-run can be diffed against, the run is HARD RULE #24-compliant (opt-in spend, cost printed, nightly/dispatch only — never per-PR), and every failure the matrix surfaces is either fixed in a follow-up or recorded with its number.

### Why — what is and isn't tested today

**Every faculty is unit-tested against a hand-written fake reply.** Four coercers, four test files:

| faculty | proposer | disposer | unit test | tests a **real** model? |
|---|---|---|---|---|
| theme | `lib/theme/ai.js` `askMessages` | `coerceEssentials` → `deriveTheme` → `auditBoth` | `test/unit/palette/theme-ai.test.js` | no — "Tested end-to-end with a fake model reply" |
| component | `lib/layout/ai.js` `askComponentMessages` | `coerceComponent` → `gateComponent` | `test/unit/layout/component-ai.test.js` | no |
| finish | `docs/src/components/studio/finish-generate.ts` `parseFinishReply` | `coerceRecipe` (closed vocab) | `docs/src/components/studio/finish-ai.test.ts` | no — `vi.mock` of the model module |
| motion | `parseSceneReply` | `parseScene` (closed vocab) | `docs/src/components/studio/scene-ai.test.ts` | no — `vi.mock` of the model module |

Those tests prove the **coercer survives a known-shaped reply**. None of them proves a real model *emits* one. That's the whole gap.

**Exactly one faculty has a live-model eval, and it tests one model.** `tools/component-gen-eval.mjs` — the §10 harness — runs the frozen adversarial set through the real component kernel and gate. It has no sibling for theme, finish, or motion, and its default pin is `anthropic/claude-sonnet-4.5` (`:34`). Same shape, same stale pin, in `tools/intent-bakeoff/judge-eval.mjs:32`.

**Nothing anywhere asks for a schema.** Every AI call in the product uses freeform JSON mode:

- `docs/src/components/studio/ai/architect-model.js:158` (WebLLM) and `:405` (OpenRouter) — `response_format: { type: 'json_object' }`
- `tools/component-gen-eval.mjs:67` — same

`json_object` says *"emit valid JSON"*. It does not say *which* JSON. Shape is recovered **after the fact** by four forgiving coercers, and forgiveness is exactly what hides a bad model: `coerceEssentials` is documented as falling back on anything "missing or malformed", so a model that returns three of ten essentials produces a palette that renders fine and isn't what the author asked for. Requesting a **strict JSON schema** where the provider supports it is the direct answer to "determinism in the structure they output" — it moves shape from *repaired* to *constrained*.

**Closed vocabularies clamp silently.** `finish-generate.ts` and `parseScene` snap an out-of-vocab reply to a legal value. That is the right runtime behavior and the wrong thing to be blind to: a model that never learns the vocabulary produces a *valid, wrong* finish every time, and no counter anywhere goes up. Clamp rate needs to be its own metric.

**Structural pass ≠ usable.** `docs/src/components/studio/Fabricate.tsx:275` runs `auditBoth(map, { level: 'full' })` and then applies the palette **regardless of `audit.ok`** — the failing branch just notifies "Generated a palette — a couple of pairs need review". So a theme can be structurally perfect and ship AA failures. The eval must report `audit.ok` rate as a first-class number, not fold it into "passed".

### Determinism — the specific known hazard

`tools/component-gen-eval.mjs:67` sends `temperature: 0.4`. On the current Claude models (Opus 5, Sonnet 5, Opus 4.8/4.7, Fable 5) the sampling parameters `temperature` / `top_p` / `top_k` are **removed from the API and rejected with a 400** on direct Anthropic calls. Whether OpenRouter strips or forwards them is **unverified from here** and must be pinned before the matrix runs — if it forwards, the harness 400s on precisely the models this card exists to test, and the fix (drop the parameter) also removes the only knob currently pretending to control determinism.

The replacement for "turn temperature down" is a **strict schema plus a measured stability rate**: run each prompt N times and report how often the *structure* is identical. Value drift (a different hex, a different word) is fine; key drift and vocabulary drift are not.

### The usability bar, per faculty

"Correct results every time" needs a bar per faculty that is measured, not asserted:

- **theme** — `auditBoth(map, { level: 'full' }).ok` is true (every pair AA in both canvases), and all ten essentials came from the model rather than a coercer fallback.
- **component** — clears `gateComponent` with zero errors, **and** `auditComponentDesign` raises no adapt/capacity finding; the three §10 adversarial cases behave (dedup fires, portrait reflow declared, out-of-scope request **declines** instead of faking).
- **finish** — `coerceRecipe` clamps nothing (the model chose in-vocabulary), and both faces emit — RICH and the OPAQUE export fallback — clean under the no-`mask-image` / no-`url()` / no-hex / no-margin rules the generator already enforces.
- **motion** — `parseScene` validates with zero repairs, and the scene references only elements the target slide actually has.
