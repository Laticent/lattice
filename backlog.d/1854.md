# feat(export): the .html player carries no lenses — a shipped deck has one reader view

## Summary

The exported single-file `.html` player already switches between three reader views, but it has **no lens awareness at all**. A deck with five approved lenses exports as one undifferentiated deck. The recipient — the person the lenses were built for — is the only reader who cannot use them.

## Swimlane

`engineering/decisions/2026-07-13-lente-reader-lenses.md` — extending the projection to the delivered artifact.

Sibling of **#1853** (no `--lens` CLI flag), and the two are genuinely different asks:

| | #1853 | this issue |
|---|---|---|
| shape | export **one** lens as a **flattened** artifact | export **all** approved lenses **inside one** artifact |
| recipient sees | a deck | a deck **with a view switcher** |
| use | "send the board their cut" | "send one file; each reader picks their own view" |

Both are wanted. This one is the higher-leverage half, because it makes the artifact match how the Studio already behaves.

## Why this is a natural fit, not a new subsystem

Three pieces already exist and currently do not meet:

1. **The player already has a view switcher.** `lib/export/player-core.mjs` drives `data-lp-view` across `present` / `read-slides` / `read-article`, with the CSS, the nav chrome and the aria labels already built (`:1146-1279`). A lens is another axis on the same control, not a new mechanism.
2. **`_lens` is already a registered `FLAG_DIRECTIVE`** (`lib/engine/directives.js:76`), so lens tags are stripped from exported bytes today. The membership information is *deliberately discarded* at the export boundary — that discard is the whole gap.
3. **The envelope already carries the deck's source byte-exact** (`lib/core/lattice-doc.js:107`), so the lens definitions in front matter physically survive the round trip. Nothing needs to be invented to carry them; they are already in the file and simply unread.

Grep confirms the gap: `lens`/`lente` appears **zero** times across `lib/export/**` and `lib/core/lattice-doc.js`.

## Design questions to settle before implementing

Not blocking the filing, but these are the real forks:

- **Fail-closed must survive the export.** `lensEligibility` (`docs/src/lib/lente/project.ts:68-81`) refuses on five reasons — `unknown`, `hidden`, `unapproved`, `empty`, `drifted`. An offline player has no Studio to fall back to, so what a refusal *looks like* in a file someone emailed needs deciding. It must not silently fall through to the full deck.
- **`approved` is a content hash over what the reader would see.** If the player ships all slides and hides some with CSS, the hash's meaning changes: a recipient can read the DOM. If instead each lens ships as a pruned slide set, byte size multiplies. This is the central tradeoff and it should be measured, not assumed. (A 16-slide deck is currently ~602 KB with CSS pruned to 196 of 3,234 rules.)
- **`full` is the implicit identity lens** and cannot be removed — so the switcher always has at least one entry, and a deck with no lenses must render exactly as it does today, to the byte.
- **Interaction with `--strip-notes`** and with the existing three views: is a lens orthogonal to the view axis (5 lenses × 3 views) or does it replace it?
- **`prunePlayerCss` re-wraps CSS**, so HARD RULE #22's serializer arm applies to anything that re-emits a `<style>` on a per-lens basis.

## Done when

A deck with ≥2 approved lenses exported via `--player` produces one `.html` in which:

1. a reader can switch lenses without a network request, and the slide set changes accordingly;
2. an unapproved / drifted / hidden lens is **not** reachable in the artifact, and cannot be reached by editing the DOM;
3. a deck with **no** lenses exports byte-identical to today (a golden diff proves it);
4. the size cost of N lenses is recorded in the PR's `## Performance` section against the single-lens baseline;
5. `engineering/pipeline.md` and the Lente README document the exported behavior, with a `changelog.d/` fragment.

## Grace note

Filed as a **known-and-intended gap**, not a defect. The lens system shipped Studio-first by design; the artifact half is the natural next step and the architecture already leans toward it.
