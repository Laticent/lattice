# fix(runtime): verdict-grid/pricing badge mirror drops the last badge and prints raw markdown to the reader

## Summary

The browser runtime's `applyToDom` mirror of `verdictGridBadges` carries a positional rule the engine does not have. On a **lint-clean** verdict-grid or pricing card whose last nested item also carries a state marker, the engine renders the badge and the runtime prints the raw `[x] …` markdown to the reader.

Found while adversarially probing the "one core engine, two hosts" claim. The engine/CLI/PDF path is correct; only the live-DOM runtime path is affected.

## The divergence

`lib/runtime/index.js:1364-1365`:

```js
// Last item is body text — skip it; all others are badge items
const badgeItems = innerItems.slice(0, -1);
```

`lib/integrations/markdown-it/plugins.js:822` (`verdictGridBadges`) walks the token stream and badges **every** nested item matching the marker regex. There is no positional exclusion — I grepped the function body for `slice` / `pop` / `length - 1` and there is none.

So the runtime assumes "the last nested item is always body text." The engine assumes nothing.

## Observed

On a lint-clean pricing deck:

| path | result |
|---|---|
| engine (`lib/engine/index.js`) | 6 badges |
| runtime (`dist/lattice-runtime.js`, jsdom) | 4 badges + `[x] Community support` and `[x] Priority support` as **raw literal markdown** |

`npm run lint:deck` passes the deck (exit 0). No committed deck trips it today — this is latent, not live in our own corpus — but a card with a trailing marker item is a shape the component's own docs describe.

## Root cause of it shipping: the mirror gate is a name check

`lib/core/marp-fidelity.js` certifies `verdictGridBadges` as `coverage: 'mirrored'`. The test that holds that ledger honest, `test/unit/core/marp-fidelity.test.js:104-107`:

```js
assert.ok(RUNTIME_SRC.includes(`${e.via}(`),
  `${e.plugin} claims to be mirrored by ${e.via}, which lib/runtime/index.js never calls`);
```

That asserts a **function of that name is called somewhere** in the runtime source. It renders nothing and compares nothing, so it cannot fail for the right reason. **7 of the 9 `mirrored` entries have no behavioral test anywhere.** Tracked separately — this issue is the concrete instance.

## Scope note

This is **not** a CLI-vs-browser gap. The CLI and the browser Playground share one render shape and one import graph (115 of 117 `lib/` files in the browser bundle are the same source files the CLI bundles; 225 of 234 committed decks render byte-identically through both). The divergence is in `lib/runtime/index.js`, a **third** render shape that never imports `lib/engine` and instead upgrades already-rendered DOM — the Marp export path.

Adjacent, same file, same class: `stateClassesFor` is implemented twice (`lib/integrations/markdown-it/plugins.js:804` and `lib/runtime/index.js:1314`) with a comment saying the two "must stay in sync", and only the engine copy has a test — there is nothing under `test/unit/runtime/` covering the runtime copy.
