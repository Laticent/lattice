# fix(test): `equiv:check` has been red on main since the corpus grew — stale baseline, and no parity harness runs anywhere

## Summary

`node tools/slice-equivalence.mjs --check` **exits 1 on clean `main`** (verified this session, tree clean). The baseline was last blessed 2026-08-17 and the corpus has outgrown it:

```
baseline 99.2%  ->  now 96.7%  (-2.5)
FAIL — decks:     baseline 126,  now 154
FAIL — slides:    baseline 1223, now 1504
FAIL — preludes:  baseline 0,    now 9
FAIL — positions: baseline 1223, now 1496
```

Nobody noticed, because the harness runs only on demand.

## The wider finding

`grep -rn "slice-equivalence\|equiv:check\|emulator-engine-parity\|geometry:check\|check-geometry-parity" .github/workflows/` returns **zero hits**. All three named parity harnesses have npm scripts and no caller:

| script | wired into CI? |
|---|---|
| `equiv:check` | no |
| `geometry:check` | no |
| `emulator-engine-parity` | no |

**Correction to a stronger claim made during the investigation that produced this issue:** it is *not* true that nothing in CI compares render paths. `test/integration/parity/*.test.js` — 16 tests — runs per-PR via `test:integration:pr` (`.github/workflows/ci.yml:298`), and several exercise the real bundled runtime in jsdom (`runtime-overflow-marker`, `runtime-frontmatter-refire`, `runtime-mode-geometry`); `deck-logo.test.js` explicitly asserts "three render paths must agree."

The accurate statement is narrower and still worth acting on: **the per-PR parity tier is a set of targeted regressions, not a corpus-wide equivalence check**, and none of them would have caught #1858.

## Explicitly NOT in scope — a decision for a human

Whether to wire `equiv:check` (or any parity harness) into CI is a **CI-contract change**: every future PR pays its cost, and a wall-clock-sensitive gate in the merge train has its own failure mode. Per CLAUDE.md's decision filter that is the maintainer's call, not an agent's. This issue only asks that the gate be **green and honest** where it is; whether it becomes blocking is a separate decision that should be taken with measured runtime in hand.
