# fix(theming): `--cat-N-fill` overrides are silently inert on every textured theme — the documented paint path is falsified

## Summary

On any theme that wires `--cat-N-texture`, a deck-level or theme-level `--cat-N-fill` override **does nothing at all**, silently. The categorical color stops being a token and becomes a literal baked into an SVG `<pattern>`.

This ships today on the 9 themes that carry the channel (`a11y-base` + 4 a11y variants, `concrete`/`concrete-dark`, `onyx`/`onyx-dark`).

## Measured

A deck-level `<style>` setting `--cat-1/2/3-fill`, rendered on the shipped `a11y-deuteranopia` with **zero** scratch markup:

## Mechanism — by construction, not a regression

`lib/core/accessibility-textures.js:118-127` bakes the fill as a literal hex inside each `<pattern>` deliberately, for a documented iOS reason (`var()` inside a `<pattern>` does not resolve there). The consuming rule is `fill: var(--cat-N-texture, var(--cat-N-fill)) !important` — once the texture token is set, the `--cat-N-fill` fallback is **never reached**, and the pattern's own baked hex wins.

So the design is internally coherent; what is wrong is that two canonical documents say the opposite:

- `engineering/decisions/2026-06-16-cvd-redundant-encoding.md` states the color "still comes from `--cat-N-fill`".
- `design/theming.md` documents that paint path.

Both are false on every textured theme. Per HARD RULE #18 this is logged, not fixed in place, because the correct fix is a design decision (below).

## Why it matters beyond the docs

This is the single strongest argument against ever turning textures on by default: a universal default would silently disable per-deck categorical recoloring **on all 32 themes at once**, and the failure is invisible — the author writes the override, sees nothing happen, and has no error to read.

## Candidate fixes (a decision, not a mechanical repair)

1. **Re-derive the pattern from the live token** at render time rather than baking a literal — needs a solution to the iOS `var()` limitation the baking exists to work around.
2. **Make the override a first-class input** — a deck that overrides `--cat-N-fill` regenerates its own pattern set. `lib/core/texture-ramp.js` already derives a full `{lightFills, darkFills, lightArm, lightInk, darkArm, darkInk}` set from a theme's ramps and has **zero production callers**; this is close to what it was built for.
3. **Fail loudly** — detect an override that cannot take effect and report it, rather than swallowing it.
