# feat(theme): `derive.js` emits no `--cat-N-texture` — every AI / Studio / Fabricate theme silently loses the channel

## Summary

`grep -c texture lib/theme/derive.js` → **0**.

The derive kernel fans 10 author essentials into the full token contract and never emits `--cat-N-texture`. `REQUIRED_TOKENS.categorical` (`derive.js:177-190`, 41 entries) covers `cat-N-fill` / `cat-N-mark` / `cat-N-ink` / `cat-on-fill` / `cat-on-mark` and nothing else.

So every theme produced by the Studio's Theme Studio, by the AI theme path, or by Fabricate **silently loses the non-colour categorical channel** — with no warning, no gate, and no way for the author to notice.

## The supply half already exists and has never been called

`lib/core/texture-ramp.js` derives, from a theme's own `--cat-N-fill` ramps, exactly what a per-theme texture set needs: `{mode, slots, lightFills, darkFills, lightArm, lightInk, darkArm, darkInk}`. Its constants are measured off the four shipped sets rather than invented — `LIGHT_ARM_DELTA -0.20` (between onyx's -0.141 and concrete's -0.251), `DARK_ARM_DELTA +0.50` (the three shipped dark arms agree at +0.465…+0.560), and the 32-theme corpus splits cleanly on chroma (chromatic 0.047–0.087, achromatic 0.000–0.003, nothing between).

**It has zero production callers** — only its own test. Its docblock says it deliberately stops short of emitting patterns because `texturePatternDefs()` is byte-locked against a golden, making emission a separate sign-off-bearing step.

This issue is that step.

## Why this is the right shape

The architecture already separates the two halves correctly: **the engine owns the geometry** (12 generic tiles in `lib/core/accessibility-textures.js`, emitted on every render at `lattice-emulator.js:817` and `lib/runtime/index.js:1905`), and **the theme owns the colouring** (each pattern paints `var(--cat-N-fill)` and overlays geometry in the paired ink). A theme never authors a texture — it wires one. `texture-ramp.js` is what makes that wiring derivable instead of hand-tuned.

Confirmed working in a rendered prototype: `deriveTheme` on an invented warm-brand essential set returned 107 keys; adding the texture arm via `textureSetFrom` returned 119; serialized through the real `lib/theme/serialize.js` and rendered, light mode read as a considered chart treatment (derived whisper ink `#98a19c`, label-vs-texture-ink 9.53–9.78:1).

## Known hazards to design around

- **A dangling `url()` paints nothing.** The consuming rule is `fill: var(--cat-N-texture, var(--cat-N-fill)) !important` (94 rules, all in `lib/integrations/mermaid/mermaid.css`). Once the token is set, the fallback can never be reached — so a token pointing at a pattern id that was not emitted renders **blank**, not "flat fill". Emission and declaration must ship in one commit.
- **Dark mode is the weak arm.** Derived dark ink `#ece2df` against white labels collapses label-vs-ink to **3.15–3.42:1** (from 8.09:1 on the bare fill). Needs a floor.
- **Polarity pins are owed.** The `<defs>` sit outside any `<section>`, so a per-slide `_class: dark` takes wrong-polarity chips — the #1323 failure (17.14:1 → 1.55:1). That triples the per-theme pattern count.
- **Two emission sites must agree byte-for-byte.** `lattice-emulator.js:817` computes from theme chain files; `lib/runtime/index.js:1905` runs in the live document. A disagreement makes `paletteUsesTexture` differ across render paths, and `test/unit/mermaid/diagram-look.test.js:131-142` asserts the declaring set over `themes/` only — it would not catch a divergence introduced engine-side.
- **`diagram-look.js:172`** — `if (paletteUsesTexture) return 'classic'` is rule 1, ahead of a per-slide `_class: sketch` pin. Any theme declaring the channel loses `mode: sketch` unconditionally. 21 files affected, including `examples/mermaid-sketch-labels.md`.
- **Contract count 107 → 119.** `lib/theme/ai.js:51` interpolates the number rather than hardcoding it, and the skill-freshness marker sources `contractTokenCount()` = 97 from token-parity's CONTRACT, not `requiredTokenList()` — so the gate can stay green while docs drift. Check both.
- **12 stale fallback sanctions fire.** `fallbackOnlyTokens` (`check-ownership.js:4070`) skips contract tokens, so all 12 `--cat-N-texture` rows in `SANCTIONED_FALLBACK_READS` drop out of the population and the stale arm errors.
- **`engineering/decisions/2026-08-10-fallback-exit-ledger.md:129-142`** keeps `--cat-N-texture` out of `REQUIRED_TOKENS` **solely** because a generated theme could only point at someone else's colours. That blocker is what this issue closes — update the record rather than working around it.

## Scope note

This closes the **supply** gap only. Whether textures are ON for a given theme is a separate question — see the `texture:` directive issue and #1864 (the fill-ramp root cause). The narrow form recommended here changes **nothing shipped**: no committed deck uses a derived theme, so 0 of 362 committed PDFs move a byte.
