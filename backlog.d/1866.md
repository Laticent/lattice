# feat(authoring): give categorical texture an author-visible switch — today there is no clean way to turn it on OR off

## Summary

Categorical texture is currently all-or-nothing per **theme**, chosen by which theme you pick. An author who wants texture on a brand palette must abandon the brand for the greyscale `a11y-*` family; an author on a textured theme who wants it off has **no reliable way to say so**.

Both directions need an author-visible control. This issue is that control.

## The off-switch does not exist, and the obvious spellings are traps

Measured on the real shipped path:

- **A deck-level `:root` override works on one slide and silently reverts** the moment that slide carries `_class: dark`. The `section.dark:not(.print)` polarity pins that a *correct* texture implementation requires (#1323) outrank any author `:root` override. The author tests one slide, sees it work, and ships a deck where half the slides ignored them — the worst possible failure shape.
- **`--cat-N-texture: none` destroys data.** It resolves to `fill: none`. Rendered: setting slots 1–3 to `none` blanked the 28% / 19% / 14% pie wedges — **61% of the chart** — to white, while their legend swatches stayed coloured.

So the two things an author would naturally try both fail, one silently and one destructively.

## The on-switch does not exist either

The only way to get texture on a brand palette today is to edit the theme. There is no deck-level request, which is why the choice currently reads as "pick the accessibility theme and lose your brand."

## Proposed shape

A front-matter register — `texture: on` / `texture: off` — resolved once for the deck, in the same family as the existing `finish:`, `mode:`, `class:` and `logo:` registers (`lib/engine/directives.js:41`), so it inherits their compose-not-replace semantics and their three-render-path resolution.

**Default OFF.** This is deliberate: it converts the one genuinely irreversible move — flipping a default that establishes generic hatching as what texture *means* across 23 brand palettes, retiring `mode: sketch`, and rewriting `lib/base/base.docs.md:1613-1615`'s settled "an accessibility need is met by choosing the theme" policy — into a reversible author-visible option.

## Why not just flip the default

Measured during the design pass; recorded here so the question is not reopened without new evidence:

| finding | measurement |
|---|---|
| net accessibility **regression** on the pie | wedge→own-swatch matches 11/12 → 3/12 under deuteranopia; texture's drift (ΔE 0.0184) exceeds the between-category signal (0.0154) — see #1862 |
| kills `--cat-N-fill` overrides | 199,580 px → **0 px** — see #1861 |
| export bytes | 7.26x–14x on an isolated same-theme control (38,799 B → 281,532 B for one 8-wedge pie) |
| blast radius | 39 tracked `.md` with categorical Mermaid; 26 with committed PDFs totalling 17.38 MB, incl. `baseline-decks/gallery.pdf` (5.54 MB) → collides with HARD RULE #8 |
| coverage is partial | gantt, journey rects, native SVG charts and pie legends diff **0 px** — teaching a reader that pattern means category and then showing them a flat bar is worse than never starting |
| retires a shipped feature | `diagram-look.js:172` makes `paletteUsesTexture` outrank a per-slide `_class: sketch`, unconditionally, across 21 files |

And the strongest argument *for* flipping was checked and fails: the docs do **not** overclaim. `principles.md`, `features.astro` and the README all scope correctly to the status-shape channel and the four a11y palettes. Only `docs/src/pages/comparison.astro:376-379` generalizes — a copy edit, not a reason to move 362 PDFs. **That line should be corrected as part of this issue.**
