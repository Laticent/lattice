# decision: retire the live-DOM mirror render path, or pay for it properly

## Summary

A decision, not a task. Parking it so the analysis is not lost.

Lattice has **three** render shapes, not two. The CLI and the browser Playground share one — same engine, same import graph, measured below. The third, `lib/runtime/index.js`, **never imports `lib/engine`**; it upgrades already-rendered DOM via `registry.applyAllToDom`. That is the Export-to-Marp path — a render path HARD RULE #1 declares retired.

**The architecture is paying rent on a host it has already evicted**, and the rent is the only genuine duplication in the arrangement.

## What the shared half actually is (for contrast)

| measurement | value |
|---|---|
| `lib/` files in the browser Playground bundle that are the same source files the Node CLI bundles | **115 of 117** (diff: the browser entry + a KaTeX stub) |
| `lib/` files in all three bundles | 93 |
| committed decks rendering byte-identically through the shipped browser bundle vs the Node engine | **225 of 234** (the 9 divergences trace to two deliberate documented bundle aliases) |
| bytes shipped to the browser: design vocabulary vs markdown parsing | 788,715 B vs 76,485 B — **10.3 : 1** |
| `lib/` that is host-neutral | ~77% of lines; the 8 Node-coupled files are all file loaders |

That half is self-maintaining and safe. Seven freshness gates rebuild every committed bundle byte-identically and all pass.

## What the third path costs

- **13 hand-written `applyToDom` mirrors.** 16 of 17 registry transformers expose both `applyToHtml` and `applyToDom`; only 3 (`below-note`, `premise`, `scene`) delegate both to one kernel. The rest are kept equal by comments — `lib/transformers/split-panels.js:16` ("stay in lock-step"), `masthead-lift.js:25` ("must match the kernel's element selection exactly").
- **Four chart transforms** (`roadmap`, `journey`, `quadrant`, `radar`) carry three-way "must stay in sync — three-renderer parity" headers.
- **An unguarded twin:** `stateClassesFor` at `lib/integrations/markdown-it/plugins.js:804` and again at `lib/runtime/index.js:1314`, with a comment saying they must stay in sync, a test on the engine copy only, and nothing under `test/unit/runtime/` covering the runtime copy.
- **It has already drifted, visibly** — #1858: the runtime hard-codes `innerItems.slice(0, -1)` where the engine has no positional rule, so a lint-clean pricing card renders 6 badges through the engine and 4 plus raw `[x] …` markdown through the runtime.
- **The gate certifying these mirrors is a substring name match** — #1859: 7 of 9 `mirrored` entries have no behavioral test.

`engineering/marp-independence.md` §5 Cost 3 already charges this cost to Marp.

## The two decisions

**1. Retire the live-DOM mirror arm?**

- *For:* it serves a retired render path; it is the only real duplication; every mirror is a standing drift liability; retiring it deletes 13 hand-maintained copies and the three-way sync headers.
- *Against:* it is what makes Export-to-Marp work at all, and `dist/marp-kit` ships today. Retiring it is a **capability removal**, externally visible, and needs a statement about what Export-to-Marp becomes.
- *Middle:* keep the path, but make the mirrors derived rather than hand-written, or attest them behaviorally (#1859) so drift is caught rather than reviewed for.

**2. Wire a parity harness into CI?**

Currently: `equiv:check`, `geometry:check` and `emulator-engine-parity` all have npm scripts and **zero** callers — `grep` over `.github/workflows/` returns nothing. `equiv:check` has been red on `main` since the corpus outgrew its baseline (#1860).

To be fair to what does run: `test/integration/parity/*.test.js` — 16 tests — runs per-PR via `test:integration:pr` (`ci.yml:298`), and several exercise the real bundled runtime in jsdom. They are targeted regressions, not a corpus-wide equivalence check, and none would have caught #1858.

- *For:* a whole-corpus cross-host diff is ~20 lines (one was built ad hoc during this investigation and ran all 234 decks); it would have caught #1858 on the commit that introduced it.
- *Against:* **this is a CI-contract change** — every future PR pays the cost, and a wall-clock-sensitive gate in the merge train has its own failure mode. Per CLAUDE.md's decision filter this is explicitly a maintainer call, and it should be taken with measured runtime in hand, not on principle.

## What this issue asks for

A decision recorded in `engineering/decisions/`, not an implementation. The dependent work (#1858, #1859, #1860) can proceed either way — they repair what exists. This issue is about whether what exists should keep existing.
