# test(a11y): no gate reads the exported PDF's tag tree — the structure is emitted and never checked

## Summary

The exported PDF **is** tagged — `pdfinfo` on a rendered `examples/video.md` reports `Tagged: yes` with `StructTreeRoot` and `MarkInfo` present — but nothing in the repo ever looks at it.

Every PDF assertion in the test tree is either `pdfinfo` for page count / page box, or `pdftotext` for text presence. `grep` for `StructTreeRoot` across `test/` and `tools/` returns exactly one hit, and it is the disclosure comment saying the gap exists:

`test/integration/invariants/axe-a11y.test.js:61`
> · the exported PDF's tag tree, which no gate in this repo reads at all — that gap is how a `/Figure` regression once passed everything here (ADR §18.3)

So structure is being emitted correctly-or-not with no feedback loop, and a regression in it has already shipped once.

## Why it matters

The PDF is the artifact most likely to reach a board, a regulator, or a procurement accessibility review. The axe gate covers the **HTML** export shell and the **HTML** player at budget 0 — real coverage, but it stops at the format nobody forwards.

## Related coverage limits (same gate, disclosed in its own header)

Worth deciding on together, since they define what "green" currently means:

- `color-contrast` is disabled in axe and delegated to `tools/check-slide-contrast.js`, which does run per-PR. That delegation is deliberate and documented — not a hole, but it means "axe green" never spoke to contrast.
- Axe runs on **one deck** (`test/integration/baseline-decks/gallery.md`), **one viewport** (1280×720), and the player's **Present** view only. `Read·Slides` and `Read·Article` — reached by a real reader in one click, and where the prose projection clones and re-hosts content into a different DOM — are never visited.

The gate enumerates all of these itself, under a heading saying the green should not be read as more than it is. That is the right posture; this issue asks whether the scope should widen.

## Correction to a claim made elsewhere

An earlier assessment paired this with "`--raster` PPTX is image-only." That is wrong: `--raster` is a **PDF-only** flag (the CLI warns and ignores it for other formats). PPTX is image-per-slide on every path by design, and it does carry speaker notes as text.
