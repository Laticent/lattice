# test(export): nothing detects a bounded wait added before capture — the deferral fix traded that coverage away

## Summary

`test/integration/export/author-script-deferral.test.js` can no longer detect a **bounded author-timer wait added before capture**. Inject `await sleep(5000)` ahead of the probe read and `page.pdf()` and every case in the file stays green. The 400 ms fixture caught exactly that regression — as a side effect of being racy, which is why it had to go.

This is a **deliberate, already-shipped trade, not a regression to revert.** It is filed because the only record of it today is prose in a docblock, and a known gap that lives only in prose is one nobody can be assigned.

## Swimlane

`engineering/decisions/2026-08-16-render-format-cost-assessment.md` §2a-ter — the decision that the export declines to wait on author timers because *"there is no finite wait that is correct."* That is precisely the property now unguarded.

Caused by #1835/#1843, which sized the fixture's timer against the suite's own 120 s timeout so runner load could not decide the verdict — the right fix for the flake that ejected #1824. Surfaced while hardening it in #1870, where an adversarial checker **proved** the loss by injecting the 5 s wait rather than arguing it.

## Done when

A test fails when a bounded wait is inserted before capture, **without any assertion reading a clock.**

The shape that works is a **census**, and the precedent is in-tree: `test/unit/export/style-guard-census.test.js` pins guard call-sites *by count, per file*, precisely because "no behavioral test kills this" was a real hazard there too — its docblock says so outright. Applied here: pin the await sequence in `lattice-emulator.js` between the `load` event and `page.pdf()`. An added `await sleep(…)` changes the sequence and fails structurally.

Done when:

1. Inserting `await new Promise(r => setTimeout(r, 5000))` before the probe read makes the new test **RED**, and removing it makes it green — paired runs pasted in the PR.
2. No assertion in the new test compares a duration. If it can be lost by a slow runner it is the bug this issue exists to avoid re-introducing.
3. The legitimate awaits already on that path (`settleFonts`, `settleDeferredMedia`, the overflow check) are enumerated with what each is for, so the census documents the capture path rather than merely freezing it.
4. The docblock's **WHAT THIS FILE CAN NO LONGER FALSIFY** section is updated to say what now *does* cover it.
