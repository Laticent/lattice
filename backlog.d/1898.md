# spike: the pick surface has never been tested on briefs its author did not write — and the `see also` fix cannot be verified on the briefs that produced it

## Summary

Two limits the pick-surface note states about itself and does not resolve: the `see also` edge added after the confusable bake-off is unverified and cannot be verified on the same twelve briefs, and both brief sets were written by whoever owns the surface under test.

## Swimlane

`engineering/decisions/2026-08-17-component-pick-surface.md` § "What this result does NOT establish".

## The two limits, in the note's own terms

**1. The fix is circular against its own evidence.** The confusable bake-off's single miss was brief 12 — both pick agents chose `regulatory-update`, both full-catalog agents chose `timeline-list` after reading an antiPattern requiring a citation on every row. Neither component's `see also` named the other, so the column the experiment existed to test never fired. The missing edge was added both ways. Re-running those twelve briefs now would only confirm that a pointer added because of brief 12 helps on brief 12.

There is a second, sharper limit on that fix which is easy to lose: the pick row renders neighbor **names** only. The `when` clause landed in the two `.docs.md` files, so the failing condition — an agent with the pick surface and nothing else — gets a pointer, not the discriminator. Rendering every `when` on the row was measured and rejected (+2,883 tokens, 3,844 → 6,727, +74%, past the 24 KB pin in `build-pick-list.test.js`). So the honest open question is not "does the edge help" but "can a one-line row carry a required-sub-element discriminator at all" — and the note's answer is no.

**2. Same-author bias is not retired.** Stated plainly in the note, with a partial mitigation (discriminators were read out of each manifest's `whenToUse`, text the FULL condition can see and the PICK condition cannot, so where it biases it biases toward the full catalog) and an explicit statement that this is not an independent-author design.

## Done when

A brief set the surface's author did not write — drawn from real authoring requests, or from the shipped example decks by working backward from the component each slide actually uses — is pre-registered with its ground truth before any agent runs, and the bake-off is re-run through `npm run intent:pick-agents` against it. The note records the result whichever way it goes, and either retires the same-author caveat or states why the new set does not.

## Notes

- Working backward from `examples/**` is the cheapest independent source in the tree: the component is ground truth by construction, and nobody wrote those decks to exercise a pick row.
- Do this **after** the harness re-run (tracked separately) — otherwise the new numbers are hand-transcribed too.
- Recommend low priority: this hardens a claim that two independent experiments already agree on, in opposite directions (the lexical proxy was pessimistic by 17.8 points, the agents were not). It is worth doing before anyone builds a recommender on top of the surface, not before that.
