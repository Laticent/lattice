# glyphs: two engine-JS sites still TYPE a shape, so HARD RULE #29's first sentence is an objective, not a description

## Summary

HARD RULE #29 opens "A typed glyph never reaches a rendered surface; we draw the shape." That is currently an **objective**, not a description of the tree — and the rule says so explicitly, because two engine-JS sites still type one:

- `lib/core/chart-family.js` — `AXIS_ARROW`, the matrix-grid axis arrows
- `lib/transformers/state-chart.transform.js` — the transition chips

#1888 converted all 18 engine-**CSS** occurrences to `--shape-*` masks and took shipped decks to zero. It deliberately stopped at these two: both write into an HTML **attribute** or a **text node**, so drawing them is a markup change to a shared chart transform that must stay in parity across all three render paths (HARD RULE #1) — not a token swap. That was too much to ride along on a PR already at 132 files.

The harm is the ordinary #29 harm and it is live today: the deck's type family carries no glyph for these, so each machine substitutes a different font, a color emoji (which stops taking the element's color and blows a palette-blind layout open), or a hollow `.notdef` box.

Closing this is what lets #29's first sentence read as true, and removes the reason the content pin in `test/unit/core/shape-glyphs.test.js` exists.

## Swimlane

`engineering/decisions/2026-08-25-typed-glyphs.md` — see § 5 "What is still typed, and why".

## Done when

1. Both sites paint a `--shape-*` mask instead of typing a character; the shape comes from us and the color from the element (HARD RULE #3).
2. Parity holds across all three render paths — the markdown-it plugin path, `lib/runtime`'s mirror, and the export path.
3. The content pin in `test/unit/core/shape-glyphs.test.js` is **updated to the new state, not deleted** — it is what stops a third site appearing quietly.
4. HARD RULE #29's text and § 5 of the decision record are updated to say the tree now matches the rule.
5. Evidence, per HARD RULE #23: a rendered PDF of a `matrix-grid` deck **and** a `state-chart` deck, light and dark, sent via `SendUserFile`, plus `tools/pixel-check.js`. Unit tests are not evidence for a rendered mark.
