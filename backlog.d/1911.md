# export(player): player-prune drops every runtime-injected selector, so the scene replay control ships with the wrong icon

## Summary

`player-prune` drops every CSS rule whose selector matches nothing in the **export-time** DOM. The Anima scene transport control is mounted by `hydrate.ts` at runtime, and at export time it exists in exactly one mode — `pause`, because the scene is playing. So these rules are pruned out of **every** `--player` export:

- `.anima-live .scene-control[data-mode="replay"]::before`
- the `.anima-live .scene-control[data-mode="optin"]` rules

The replay control therefore ships with the wrong icon in every exported webpage. Measured, not inferred — the same control, same slide, three builds:

| build | what the replay control shows |
|---|---|
| `origin/main` (pre-#1888) | an **empty circle** — the base `::before` carried no `content`, so with the per-mode rule pruned nothing was generated |
| after #1888, `--player` export | a **play triangle** — the base rule now carries a mask, so the pruned state shows the wrong shape rather than nothing |
| after #1888, docs Playground | **correct** — `--shape-refresh` |

The Playground row is what makes this diagnosable: same `hydrate.ts` host, same stylesheet, and the only difference is that the Playground's CSS is not pruned. **The CSS is right; the export loses it.** Pre-existing, and #1888 changed the failure from "blank puck" to "wrong but visible control" without addressing the cause.

The hole has a purpose-built hook that has never been filled — `PLAYER_PRUNE_SAFELIST` in `lib/export/player-prune.js`, whose own comment reads: *"this is the hook for a future runtime-injected class the static DOM wouldn't show."*
