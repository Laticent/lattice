# spike: red-team the typed-glyph gate — a text matcher with hand-rolled escape decoding that nobody has attacked

## Summary

`checkTypedGlyphs` (#1888) holds engine CSS at budget 0 and shipped decks on an exceed-only ratchet at 0. It has never been adversarially tested. It is a **text matcher over CSS** with hand-rolled escape decoding, and the repo already knows what a gate with a hole costs: #1852, where a ratchet sitting 29 units above the real number let five new British spellings walk through the US-English gate. A ratchet with a hole is a ratchet in name only.

The surfaces worth attacking, in rough order of suspicion:

- **`decodeCssEscapes`** — written in response to exactly one crash (`content:"\2192abc"` parsing past U+10FFFF and throwing a `RangeError` that aborted `build:check`). One bug found, one fix applied; nobody asked what else the `\` grammar admits. CSS escapes take 1–6 hex digits with an optional single trailing whitespace, and there are also non-hex escapes.
- **`CSS_CONTENT_RE`** — `/(?<[\w-])content\s*:\s*([^;}]*)/g`. The lookbehind was added by hand to skip `--content:`. What else spells the property, or hides a value past a `;` or `}`?
- **The comment-blanking pass** — comments are blanked before matching. Does the blanker's idea of a comment match the CSS parser's?
- **`isGlyphDeck` / the deck scope** — roots ∪ `*.gallery.md` ∪ marp front matter. A rendered deck outside all three is invisible to the gate.
- **Both allowlists** — `SANCTIONED_GLYPH_CHROME` and `SANCTIONED_GLYPH_DECKS` are supposed to fail on a **stale** entry. Do they, on every shape of staleness?

## Swimlane

## Done when

Either:

- **no evasion found** — recorded in the decision record with what was tried, so the next person does not repeat it; or

An evasion claim counts only if it comes with a file that **passes `npm run build:check`** while carrying a typed shape glyph on a rendered surface.
