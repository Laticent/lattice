# docs(gotchas): prose in a deck fixture ships — an HTML comment becomes a speaker note, a PDF annotation, and lint narration

## Summary

A test fixture under `test/fixtures/` is a **deck**, so explanatory prose written into it is not inert — it ships. An HTML comment above a `<script>` parsed as a **speaker note**: it became an `<aside class="lattice-notes">` in the exported sidecar and a PDF text annotation, and it moved `lint:deck` from 4 narration acronyms to 7 plus a new `wall-of-text` suggestion.

Moving the same prose to `//` comments *inside* the `<script>` fixed the note and the annotation but **not** the lint noise — `narration-acronyms` still read it, and went to **23** tokens. The only thing that actually works is keeping the prose out of the deck entirely.

## Swimlane

No governing note; the nearest record is `engineering/gotchas/ci.md`. Found in #1870 while documenting a fixture's timer, and caught by an adversarial checker rather than by review — measured with a real render, not reasoned.

## Done when

An entry in `engineering/gotchas/` (topic: authoring or CI) that a future agent finds *before* writing prose into a fixture. Done when it carries:

1. **The symptom** — a fixture edit that adds no code changes the exported artifact: `<aside class="lattice-notes">` appears, the PDF grows a text annotation, `lint:deck` grows acronyms and a `wall-of-text` suggestion.
2. **The measurement** — asides 0 → 1, `narration-acronyms` 4 → 7 as an HTML comment, and **4 → 23** when moved inside the `<script>`, which is the counter-intuitive half.
3. **The near miss, because it is the reason this matters.** The comment did not happen to contain the string `LATE ARRIVED`. Had it — the most natural thing in the world when writing prose *about* that test — the `--player` case asserting `!html.includes('LATE ARRIVED')` would have failed, or worse, been satisfied by the wrong text. The suite passed on luck of wording, not isolation.
4. **The rule** — fixture prose goes in the *test file's* docblock, with at most a one-line pointer in the deck. Verify with `grep -c 'lattice-notes'` on the exported `.html` (count `<aside …>` elements, not lines — a CSS rule matches the string too, which cost a false "not fixed" reading).
