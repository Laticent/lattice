# narration: a shared deck has no voice — `share-export` writes captions only, and the ladder floors a keyless recipient to silent

## Summary

`share-export.ts` writes **captions only — "No audio, no TTS key"** — and the voice ladder reads the *viewer's* own key. So a shared deck opened by someone with no key floors to `silent`: **the self-presenting shared deck has no voice today.**

Everything the audio-pacing work optimizes is the path where the author rehearses with their **own** key. The recipient path — which is the whole point of sharing a self-presenting deck — produces a silent artifact.

Making a shared deck speak means baking prepared audio into the artifact, which is a separate feature with export-format consequences and needs its own design pass.

## Swimlane

`engineering/decisions/2026-08-03-present-instant-audio-pacing-guide.md` — see § "Still open, and bigger than this PR".

## Done when

This is a design pass first, not an implementation ticket. It is done when there is a record that settles:

1. Whether prepared audio is baked into the exported artifact, fetched alongside it, or neither (captions stay the answer, stated as a product decision).
2. The export-format consequence — what this does to `.html` player size, and whether it changes the `.lattice` envelope.
3. How it interacts with the existing narration encode path (#1503, #1509, #1511) rather than duplicating it.
4. What a keyless recipient hears, stated explicitly, whichever way it goes.
