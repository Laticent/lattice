# test(e2e): `build:e2e` skips the post-build passes, so the e2e artifact does not carry the stylesheet hoist it is meant to prove

## Summary

`npm run build:e2e` skips the post-build passes — it already skipped `inject-modulepreload`, and it now also skips the stylesheet hoist that fixed the Studio FOUC. **The artifact the e2e suite exercises is therefore not the artifact we ship.**

The divergence predates the FOUC change and was left consistent rather than quietly widened, which was the right call for that PR. But the consequence is that a regression in either post-build pass is invisible to e2e by construction: the suite cannot fail on a defect in a step it never runs.

## Swimlane

`engineering/decisions/2026-08-16-studio-fouc-stylesheet-order.md` — see § 5 "What is not covered".

## Done when

One of two outcomes, stated either way:

1. `build:e2e` runs the post-build passes, so the e2e artifact matches the shipped one — and the e2e suite gains a check that would fail if either pass is dropped; **or**
2. the divergence is deliberate and documented in `engineering/development.md`, naming what e2e consequently cannot catch, so nobody reads a green e2e as covering the shipped bundle.

If (1), the cost matters: the post-build passes lengthen every e2e build, so measure it before adopting.
