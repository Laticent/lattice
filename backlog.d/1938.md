# studio(library): the workspace backup carries no asset version history, and making it true is a workspace FORMAT change

## Summary

`asset-history.js` claimed the workspace backup "carries it separately from `library.zip`". **It never did.** The docblock was corrected rather than made true, because making it true is not the two lines it appears to be:

- a version is keyed on `assetId`;
- the bundle format carries no asset ids;
- restore upserts by **NAME**.

So versions restored as-is would point at ids the receiving browser never minted, and `pruneOrphanVersions` would correctly delete every one of them.

Doing it properly means the backup carries a **name→id map** and restore rewrites `assetId` against the ids it actually resolved. That is a change to the workspace **format**, and belongs in its own change with its own review.

## Swimlane

`engineering/decisions/2026-08-25-hand-editing-generated-assets.md` — see § "Precondition 3 is still open, and is bigger than it looks".

## Done when

1. A backup taken in browser A and restored in browser B preserves asset version history — the actual round trip, not a unit assertion about the map.
2. `pruneOrphanVersions` does not delete restored versions.
3. The format change is versioned, and an older bundle still restores (without history) rather than failing.
4. `asset-history.js`'s docblock is made true, and the decision record's precondition 3 is closed out.
