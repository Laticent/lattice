# anima(security): the Motion inspector renders an invalid scene, so an inline-style color swatch must gate on `validateColor` before Director mode or a library load

## Summary

The Motion inspector **renders even when the scene is invalid**, and it paints a colour swatch using an inline style. Today that value comes from a scene the author built in the Studio, so it is effectively trusted. Two planned changes break that assumption:

- **Director mode (Stage 7c)** — describe → AI-generate, so the scene comes from a model.
- **A library load** — a scene imported from a saved or shared artifact.

Either can feed an **untrusted `Scene`** into a component that writes its colour straight into an inline style without passing `validateColor` / `valid` first.

This was flagged in a code comment and in the maker-checker fold, and never became a card. It is latent rather than live, which is exactly why it needs a ticket: the trigger is a *future* feature, so nothing will re-surface it at the moment it starts to matter.

## Done when

1. The colour swatch gates on `validateColor` / `valid` before any inline style is written — regardless of scene provenance.

3. A test feeds a hostile scene value (a `url(...)`, an unbalanced construct, a CSS escape) and asserts nothing reaches the style attribute.
