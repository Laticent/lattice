# theme(derive): `validateEssentials` accepts any hex for the light-surface `bg`/`bgAlt` slots — a dark `bg` derives an out-of-contract palette

## Summary

`validateEssentials` accepts **any** hex for the `bg` / `bgAlt` **light-surface** slots, with no lightness sanity check. Supplying a dark `bg` therefore derives an out-of-contract palette.

The categorical three-layer fix made this more visible — the audit now rejects such a palette rather than shipping it — but the *input* is still accepted, so the failure surfaces late, as an audit rejection, instead of at the point where the wrong value was supplied. A lightness guard was correctly judged separate hardening rather than part of that fix (HARD RULE #18, off-path), and was never ticketed.
