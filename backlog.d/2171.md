# chart: a dropped label is still silent for an author — the census only covers decks we ship

## Summary

When a chart cannot fit an item name, it draws nothing and says nothing. #1605 called this "the real defect — a chart quietly misrepresenting the author's data, invisibly to every gate in the repo." PR #2170 closed **our** half of it. An author rendering their own deck still gets silence.

## What is already fixed

`placeLabels` returns `{ svg: '', hidden: true }` when a name will not fit (`lib/components/chart/_chart-family/svg-label.js`). Nothing downstream reads the flag, so the name simply is not on the slide — no warning, no overlap, no error.

`test/unit/components/chart-label-drop-census.test.js` (PR #2170) now fails if any deck **in this repo** silently drops a name. It instruments `placeLabels` and `buildCategoryLabels` before `chart-family` is required, so it sees every caller regardless of when that caller destructured.

That is a CI gate over our corpus. It is not a diagnostic.

## What is still missing

Three surfaces, none of which the census reaches:

1. **`lattice-emulator.js` on someone else's deck.** The CLI already prints an overflow warning; a dropped label is the same class of finding and prints nothing.
2. **`lint:deck`.** The right home under HARD RULE #29's warn-and-coach posture — name the item that will not fit, and say what to do (fewer items, a shorter name, a different component).
3. **The Playground.** A live preview is where an author is most likely to be iterating on exactly this.

## Why it needs a channel, not a `console.warn`

`placeLabels` is called from the transform layer, which is shared by the CLI, `validate()` and the browser (HARD RULE #7's constraint on the lint kernel is the same shape). A `console.warn` from inside a pure transform reaches whichever host happens to be listening and is invisible in the other two. The kernel needs to **return** what it dropped, and each host decides how to say it.

Note the counting subtlety the census had to learn, because a diagnostic will hit it too: per-slide label sizing means `placeLabels` runs up to nine times for the same slide as the fit search descends the ladder. Only the **last** attempt is real. Counting every attempt reported 141 false losses on a corpus that drops nothing.

## Suggested shape

- `placeLabels` returns the dropped items alongside the placements (it already computes them).
- The chart transforms thread that up to a per-slide diagnostic the way overflow already travels.
- `lint:deck` warns and coaches; the CLI prints it; the Playground surfaces it inline.
- A gate is not the goal here — the gate exists. This is the author-facing half.
