# epic(components): one construct for naming a set's members — four override grammars ship today, and the same four markers are named five ways

## Summary

`heatmap` shipped the **label set** in #2238 — one normalized entry `{key, label, detail?}`, derived from the chart's own data, overridable by the author in an inline-code span. It is the only adopter. The decision record named the rollout but nothing was filed, so this epic is that tracking card.

### Four override grammars already ship

1. **Inline label set** — `` `[{1, Cold}, {3, Warm}]` `` (`label-set.js:69`) — `heatmap` only.
2. **A list group heading** — `fromGroup || MAGIC_DEFAULT_NAMES[i]` (`quadrant.transform.js:1082-1085`, defaults `:70`, `:76`).
3. **A CSS custom property register** — `--insight-label` (10 members, `base.variants.css:490-499`) and `--stance-label` (4 members, `policy-recommendation.styles.css:42-47`). Opted into by a modifier class; neither carries a detail field, neither is documented as author-overridable.
4. **An unparsed prose paragraph** — `matrix-grid` (the kernel only *wraps* the author's `<p>`, `matrix-grid.transform.js:114-121`) and `obligation-matrix` (an optional trailing `<p>` nothing reads, slot at `obligation-matrix.docs.md:19`, mandated at `:43`).

### The cohort the decision doc named is the wrong one

Its open question asks whether "the other 19 `series`-substance components" adopt the construct. Every strong candidate is **`structure`** substance: `matrix-grid`, `roadmap`, `journey`, `obligation-matrix`, `verdict-grid`. Substance is the wrong axis. The right test is *does the engine fix the words for a closed set the author cannot rename?*

`journey` is the closest structural twin to heatmap's ramp — five steps, hard-coded poles — and it **asserts a polarity** that Decision 3 argued is unknowable for a ramp. The decision record did not name it.

**Tier 2 — the set exists and the author writes the word, but the grouping or the meaning is fixed and unstated.** `verdict-grid`, `pricing`, `checklist`, `state-chart` (prints the status verbatim, no description, first-appearance order), `gantt` (10 frozen words folded onto 5 fills, `GANTT_STATUS_FILL:261-270`), `kpi` (the engine never reads the pill text; color comes from row position, `kpi.docs.md:47`), `redline` (OLD/NEW/WHY as literal CSS `content:`), `list-steps` (`--step-prefix`), `regulatory-update` (`TIER n`), `policy-recommendation` (`--stance-label`), `split-compare` (`--insight-label`), `word-cloud` (`size = frequency` / `more` / `less` literals).

**Tier 3 — weak.** The Cartesian charts (`bar`, `line`, `piechart`, `stacked-bar`, `radar`, `map`, `quadrant`) take legend labels straight from author data, so renaming already works. Only `detail` is missing — and that is blocked for everyone (see below).

**Not candidates.** `scatter` and `word-cloud` size keys encode continuous magnitude, not a closed set. `funnel` has no set at all.

**Seven components render no key for a set they have**: `bullet` (zones), `kanban` (lanes + statuses), `progress`, `timeline-list`, `waterfall`, plus the un-keyed halves of `bar` (`diverging`), `slope` (`signal`) and `word-cloud` (`spectrum`).

## Blockers — prerequisites, not per-component work

Tracked in the kernel-prep sub-issue.

1. **`liftLabelSet` is in the wrong place.** It is defined at `heatmap.transform.js:712` and exported from the *component*. Adopter #2 either imports across components (against HARD RULE #1) or re-derives it — and it carries a hard-won trap: scan *every* one-code paragraph, because the eyebrow sets in the same shape.
2. **Two legend substrates.** Eight charts call `buildSvgLegend` (`bar:613`, `stacked-bar:550`, `map:313`, `quadrant:1361`, `heatmap:741`, `piechart:84`, `line:974`, `radar:559`); `roadmap:67` and `state-chart:568` emit HTML `<ul>`/`<ol>`. **Every Tier-1 candidate is table-based**, so the rollout needs an HTML legend path the kernel does not have.
3. **Form 3 (REGISTER) has no caller anywhere.** `parseRegisterBlock` is tested (15/15 green) but unreached, because a chart transform receives `{cls, classTokens, orientation, utils}` and front matter never arrives. **Consequence: no component can attach a DESCRIPTION to a set member today, heatmap included.**
4. **No coaching channel.** `unboundKeys` output reaches the chart's `<desc>` only (`heatmap.transform.js:622-625`), never `lint:deck`. HARD RULE #29's "we warn, we coach" posture is unwired for label sets.
