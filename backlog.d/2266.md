# chart(caption): .chart-caption is a flex COLUMN, so any inline element in caption prose becomes its own row

## Summary

`section.chart-frame .chart-caption` is `display: flex; flex-direction: column` (`lib/components/chart/_chart-family/chart-family.css:1113-1123`). Every child is therefore a flex ITEM on its own line — including **inline** elements. A caption reading

```markdown
No cell here is `[-]` or `[ ]`, so neither gets a chip.
```

renders as five stacked rows: the text before, a disc, the word "or", a disc, the text after. On a landscape roadmap that pushed the slide past the frame and it exported with a **"Content clipped"** tag.

The flex column is deliberate and documented in place — it centers the `::before` hairline via `align-items` and spaces it with `gap` rather than a margin (HARD RULE #20). The defect is that it was reasoned about for the hairline and the caption *text*, and an inline element inside that text was never considered.

## Swimlane

`engineering/decisions/2026-06-27-stage-flow-no-margins.md` (why the caption is a flex column at all, and why `gap` rather than `margin`). The inline state-mark grammar is `lib/core/state-marks.js` → `lib/core/inline-code-directives.js:33`.

## Done when

1. **A caption mixing text and an inline element renders as ONE line that wraps normally.** The repro below is the arm: `` No cell here is `[-]` or `[ ]`, so neither gets a chip. `` in a roadmap caption must not stack, and must not clip the slide.
2. **The hairline still centers and still spaces by `gap`, not `margin`.** That is what the flex column bought; a fix that reintroduces a margin fails HARD RULE #20 and the `checkMarginDiscipline` gate will say so.
3. **No visual diff on the committed chart galleries.** Every shipped caption today is plain text, so a correct fix changes none of them — that is the cheap proof the fix is scoped.
4. Gates green: `npm run lint`, unit suite, `npm run build:check`.

## Repro

```markdown
---
marp: true
theme: indaco
---

                        

## Caption with an inline mark.

| Workstream | Sprint 12 | Sprint 13 |
| --- | --- | --- |
| Checkout | [x] Apple Pay | [x] Gift cards |
| Search | [x] Typo tolerance | [/] Voice input |

No cell here is `[-]` or `[ ]`, so neither gets a chip.
```

`node dist/lattice-emulator.js <deck>.md <deck>.pdf` reports `⚠ OVERFLOW … CLIPPED`.

## Likely shape of the fix

The caption wants a column for its two BLOCKS (hairline, then text) but the text itself is inline flow. Wrapping the caption text in its own element, or giving the text child `display: block` so its inline children lay out normally, both do it without touching the hairline's centering. Neither has been measured — the fix is not the part this card is confident about.
