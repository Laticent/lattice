# Studio export: tell the author when a deck's Mermaid fences ship as source because the plugin is off

## Summary

When a deck holds ```` ```mermaid ```` fences and the Mermaid plugin is not on for that deck, the Studio's exports ship each diagram as its source text, and nothing tells the author before or after the export. The Webpage panel already does this for another opt-in, other sites' pictures. Diagrams need the same treatment.

### What happens today

Found by the owner while testing #2739. A deck with Mermaid fences and the plugin off exports from Share → Webpage with every diagram shown as highlighted code. The export panel and the completion toast are silent, so the author learns about it only on opening the file.

### What it should do

The same pattern the panel already uses for web pictures (`docs/src/components/studio/WebpageOptionsPanel.tsx`, `deckHasWebPictures`, a row shown only when the deck needs it):

- Detect that the deck has Mermaid fences and that the plugin is off for it. Admission is deck-wide: `admitPlugins` / `pluginAdmission` in `lib/playground/index.js`, and the Plugins tab in `docs/src/components/studio/PluginsSettings.tsx`.
- Show one plain line in the export panel, for example "4 diagrams will ship as source: Mermaid is off for this deck", with an action that turns the plugin on. The action writes the deck's `plugins:` list, which is how the Plugins tab already does it.
- Cover every Studio export that draws diagrams, not only Webpage: PDF, PNG and PowerPoint, the Marp bundle, and print.
- Keep it generic. The rule is "a fence whose plugin is off", read from the plugin registry, so it covers any drawn plugin (function-plot, state-chart, math) without naming Mermaid in the panel.

### Questions to settle in the PR

- Does the live preview already show anything for an off-plugin fence, and should the export notice reuse that wording?
- Panel row (before export), toast (after), or both? The web-pictures row is before-only.

engineering/decisions/2026-09-27-plugin-system.md (§9, the Plugins tab); engineering/decisions/2026-10-16-player-as-library-audit.md §11.9 (export parity).

## Done when

- A deck with Mermaid fences and the plugin off shows the notice in the Webpage export panel and in every other Studio export that draws diagrams. Its action turns the plugin on, and the next export draws the diagrams.
- A deck with no fences, or with the plugin on, shows nothing.
- An e2e spec drives both arms, notice and no notice, through the real Share sheet.
