# Turning a plugin off in the Studio leaves its diagrams drawn; the fences should come back as source

## Summary

In the Studio, turning the Mermaid plugin on draws a deck's diagrams. Turning it off again leaves them drawn, when each fence should go back to its source code. The plugin state and what the author sees have come apart. **This card needs investigation and a design decision before any code.**

### What happens today

Found by the owner while testing #2739:
1. A deck has Mermaid fences and the plugin is off. The fences show as source.
2. Turn the plugin on in the Plugins tab. The diagrams draw.
3. Turn it off again. The diagrams stay drawn.

Unverified so far: whether exports made after step 3 draw the diagrams or ship source. If the preview and the export now disagree, that is its own defect.

### Likely mechanism, to confirm

- The browser Mermaid pass keeps drawn SVGs in `mermaidSvgCache` (`lib/plugins/mermaid/mermaid.hydrate.js`), keyed by scope and source. A settle from that cache can re-insert a drawing without asking whether the plugin is still admitted.
- The live frame may also keep its already-drawn DOM, because an admission change may not re-render the slides or reset the fences' settle state.
- Admission is deck-wide and comes from `admitPlugins` / `pluginAdmission` (`lib/playground/index.js`). `pluginDefaultsKey()` exists so render caches change when the defaults change. Check whether the preview's caches, and the runtime's, key on a deck's own `plugins:` list as well as the defaults.

### Questions to vet before building

1. Which layer holds the stale state: the engine render cache, the frame DOM, the runtime pass's SVG cache, or the export path?
2. Turning a plugin off should restore each fence to its highlighted source, and the next turn-on should draw again. Should the turn-on reuse the cache (fast) or redraw (always honest)?
3. Does turning off need to purge the cached SVGs, or only stop the cache from being used while the plugin is off? Purging costs a redraw on the next turn-on; gating keeps a cache entry nobody may ask for again.
4. Does the same hold for every drawn plugin (function-plot, state-chart, math), so the fix lives in the plugin host rather than in Mermaid?
5. Exports: confirm that an export after turn-off ships source in every format, matching the preview.

## Done when

- In the Studio, a plugin turned on, then off, puts every fence back to its source in the preview. Turned on again, they draw.
- Every export made while the plugin is off ships source, matching the preview.

- The decision on purging versus gating the cache is recorded in the plugin-system decision note.
