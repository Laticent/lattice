# [Idea] Site Optimization for Discovery

## Summary

Optimize our GitHub Pages site for **SEO (Search Engine Optimization)**, **LLM/AI agent readability**, and **static security**. By combining clean semantic structure, explicit machine discovery files, and strict deployment hygiene, we can improve search rankings, ensure accurate AI citations, and protect our static infrastructure.

## Core Concepts
1. **Shared Foundations (SEO + LLMs):** Search engines and LLMs both rely on fast, clean, semantic HTML, clear metadata, and structured data to understand what a page is about.
2. **Low-Noise AI Discovery:** Beyond traditional HTML, LLMs perform best when given dedicated plain-text or Markdown entry points free of visual clutter.
3. **Static Security Boundaries:** Because GitHub Pages serves every file in the deployment output publicly without a backend server, security relies on strict artifact hygiene, browser-enforced policies, and crawler rules.

## Implementation Checklist

### 1. Search Engine Optimization (SEO)
- [ ] **Optimize Page Metadata & Social Previews:**
  - *Concept:* Every page needs a unique title, concise description, canonical URL (to prevent duplicate content issues), and Open Graph tags for rich link previews.
  - *Example (`<head>`):*
    ```html
    <title>Page Title | Site Name</title>
    <meta name="description" content="A clear, 150-character summary of the page content.">
    <link rel="canonical" href="https://example.com">
    <meta property="og:title" content="Page Title">
    <meta property="og:description" content="Summary for social and link previews.">
    ```
- [ ] **Publish an XML Sitemap (`sitemap.xml`):**
  - *Concept:* Provide search engines with a complete list of all public URLs and their last-modified dates so new or updated pages are indexed quickly.
  - *Example (`/sitemap.xml`):*
    ```xml
    <?xml version="1.0" encoding="UTF-8"?>
    <urlset xmlns="http://sitemaps.org">
      <url>
        <loc>https://example.com</loc>
        <lastmod>2026-11-14</lastmod>
      </url>
    </urlset>
    ```
- [ ] **Prioritize Core Web Vitals & Mobile Responsiveness:**
  - *Concept:* Search engines rank fast, mobile-friendly pages higher. Optimize image sizes, avoid layout shifts, and include a proper viewport meta tag.
- [ ] **Use Descriptive URLs & Internal Linking:**
  - *Concept:* Use clean, readable URL slugs (`/guides/getting-started` instead of `/p?id=123`) and link related pages together with descriptive anchor text.

### 2. LLM Readability & AI Discovery
- [ ] **Provide a Machine-Readable Site Summary (`llms.txt`):**
  - *Concept:* Give AI agents a single root file that summarizes what the site does and links directly to your most important pages.
  - *Example (`/llms.txt`):*
    ```markdown
    # Project Name
    > A concise one-sentence summary of what this site or app does.

    ## Core Pages
    - [Getting Started](https://example.comstart.md): Setup guide and core concepts.
    - [Reference](https://example.comreference.md): Detailed specifications and examples.
    ```
- [ ] **Expose Clean Text / Markdown Twins:**
  - *Concept:* Offer distraction-free Markdown versions of key pages alongside HTML pages, and link them in the `<head>` so bots discover them automatically.
  - *Example (`<head>`):*
    ```html
    <link rel="alternate" type="text/plain" href="/llms.txt" title="LLM Summary">
    <link rel="alternate" type="text/markdown" href="/guide.md" title="Markdown Version">
    ```
- [ ] **Use Semantic HTML & Static Pre-rendering:**
  - *Concept:* Both search crawlers and AI scrapers parse static HTML more reliably than heavy client-side JavaScript. Wrap core content in meaningful tags (`<main>`, `<article>`, `<h1>`–`<h3>`) with a single `<h1>` per page.
- [ ] **Anchor Facts with Structured Data (JSON-LD):**
  - *Concept:* Embed standardized `schema.org` metadata to earn rich search snippets and help LLMs extract exact facts without hallucinating.
  - *Example:*
    ```html
    <script type="application/ld+json">
    {
      "@context": "https://schema.org",
      "@type": "WebSite",
      "name": "Your Site Name",
      "url": "https://example.com"
    }
    </script>
    ```
