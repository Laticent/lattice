# Custode: a storage and sync library with bring-your-own connectors

## Summary

**Name: Custode** (Italian for keeper, guardian; chosen by the owner 2026-11-25). It lives at `docs/src/lib/custode/`, beside Tavola and Vetrina. Its promise, in one line: **a person never loses their work, wherever it lives.**

Design a general-purpose storage and sync library, with bring-your-own storage connectors, that joins the libraries under `docs/src/lib/`. It is not Lattice-specific; the Lattice Studio is its first user.

## Swimlane

None yet. This issue's first deliverable is the design note (`engineering/decisions/YYYY-MM-DD-storage-library.md`). Related: #3525 (what the Studio stores today, and the measurements), #3526 (persistent storage, fixed first in the current code).

### Why

Today no one owns stored data. The Studio keeps a person's work across about nine IndexedDB databases (some named for retired products), about 200 `localStorage` keys read by 91 files, and Cache Storage, with contradictory rules (one store avoids Blobs in Safari, the photo store depends on them) and nothing asking the browser to keep any of it (#3525, #3526). Every new feature adds its own store.

The product direction is **bring your own storage**: a person keeps their work in the browser, on their own disk through the Laticent desktop app, in their Google Drive, or later anywhere a connector exists. The app should not care which.

### What the library owns

- **One connector contract.** Every place data can live is a plug-in that meets it. A connector says what it can do (for example: holds large files, keeps versions, notices outside changes, has a quota) and the library adapts to it.
- **Connectors.** First: the browser (IndexedDB for records, the Origin Private File System for large media), the desktop file system (through the Tauri app), and Google Drive. The contract is public so others can be added (iCloud, Dropbox, S3, WebDAV, a person's own).
- **Local first.** The app always reads and writes the browser layer, so it works offline and never waits on a network. The library syncs that layer with whatever connector the person chose (see "The browser is always the first layer").
- **Sync and conflicts.** Changes made on two devices, or in two tabs, merge without losing either. Documents that people edit together reuse the merge model Tavola already uses (Yjs); whole files (photos, videos) keep versions and never silently overwrite.
- **Durability.** Ask the browser to keep data, notice when it refused or deleted something, tell the app so it can tell the person, and always offer export.
- **One owner of the schema.** Versions and migrations in one place; a migration is proven on a copy of a real stored workspace before it ships.
- **Safe across tabs.** Two open tabs do not overwrite each other (the browser's `BroadcastChannel` and `navigator.locks`).
- **Credentials stay with the person.** A connector signs in with the person's own account (Google Drive by the person's own OAuth sign-in); tokens are stored the way `lattice-secrets` already stores keys; no Laticent server sits in between.

### The browser is always the first layer

Owner direction (2026-11-25): **the browser is always the first layer of storage**, for the best experience, and it syncs to whatever connector the person chose. This is the local-first pattern: every read and write hits the browser immediately, and sync runs behind it. The design note must hold to the following, because "the browser is a cache" is only half true:

- **Unsynced changes are the only copy, not cache.** An edit made offline, or in the seconds before a connector confirms it, exists nowhere else. The library tracks "not yet synced" per item and **never evicts or clears an item until its connector confirms it holds it.** Durability (#3526) protects exactly this.
- **Synced data is a true cache.** Once a connector holds it, the browser copy may be dropped and fetched again. Decks and their history stay fully local; large media (photos, videos) stays local while recently used, so a big library fits within browser storage limits.
- **With no connector, the browser is the only copy.** A browser-only person needs durability and an easy export most of all.
- **Sync status is always visible**, in plain words: saved on this device, synced to Google Drive, or not synced yet with a count. A person never has to guess where their work is.
- **Offline edits from two devices meet on reconnect** under the merge rules above: decks merge, media keeps both versions, and nothing is overwritten silently ("last write wins" is not a rule here).
- **The desktop app does not store large media twice.** On desktop the file system holds the media and the browser layer refers to it.
- **Signing out of a connector can clear the local copy**, for shared computers, and warns first when anything is not yet synced.

### What it does not build

- Not a database engine, and not its own merge algorithm: it reuses proven ones (Yjs through Tavola; a small IndexedDB wrapper such as `idb`), per HARD RULE #15. Its value is the policy and best practices on top.
- No Laticent-run server or account system. A hosted connector could be added later as one more plug-in.
