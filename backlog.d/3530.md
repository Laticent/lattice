# Audit and optimize the base and component CSS without changing how any slide looks

## Summary

Audit and optimize the engine's base and component CSS as a whole: one way to respond to slide size instead of two, no specificity escalation, no copied rule blocks, and a smaller stylesheet, with every slide looking exactly as it does today.

## Swimlane

`engineering/cascade.md` (the cascade and its rules), HARD RULES #3, #4, #11, #20, #26. Desks: ⚡ optimization (`/desk-optimize`) and 〰️ jank (`/desk-jank`), with ✨ polish (`/desk-polish`) for the visual review.

### Why

Measured on `main`'s tree, 2026-11-25:

| Measure | Value |
|---|---|
| The shipped stylesheet, `dist/lattice-min.css` | **1,192,288 B minified, 147,750 B gzipped** |
| Source | 53 component CSS files (17,602 lines, 1.05 MB) and 17 base files (13,047 lines, 0.87 MB) under `lib/` |
| Size responsiveness, two systems | **260 selectors on the `data-family` size stamp** and **64 `@container` queries**. #2988 began moving layouts to container queries (they answer the width actually available); most still use the stamp |
| Specificity escalation | 330 selectors repeat a class twice, **28 repeat it three or more times** (one repeats it five times, `list-tabular`) |
| `!important` | 103 |
| Copied rule bodies (3+ declarations, identical) | **78 distinct bodies repeated, 114 extra copies**, in component CSS alone |

The stylesheet is downloaded and parsed by the Studio, and every slide preview frame applies it. Its size and selector count cost memory and main-thread time on a phone, which ties this to #3525 (Safari's page process reached about 1 GB in the iOS Simulator).

### The floor: what may not get worse

1. **Pixels.** Every gallery and demo deck renders the same at every venue and in both color modes (`tools/pixel-check.js`); any changed page goes to the owner as before and after.
2. **Fit.** Page counts per deck and venue unchanged; `fit-readable` and the parity tier give the same verdicts.
3. **Jank.** `npm run check:jank` no worse than baseline on any layout.
4. **Themes.** Every theme still drives every layout through tokens (#3); no hex literal, no margin (#20), no partial `@layer` (#26).
5. **Gates.** `build:check` and every ownership gate stay green, with no new `SANCTIONED_` entry added to make a cut pass.

## Done when

1. **Baseline**, committed: stylesheet bytes (minified and gzipped), selector count, the highest specificity per component, `!important` count, copied-body count, `data-family` versus `@container` counts, and the cost of applying the stylesheet in one preview frame (parse and style time, measured in Playwright WebKit with a phone profile).
2. **An audit note** in `engineering/decisions/`: each finding with file, line and measured cost, marked keep, merge or delete. At least:
   - **One size system.** Move the remaining `data-family` selectors to container queries (or record why one cannot move), then retire the stamp's CSS role.
   - **Specificity.** Replace repeated-class escalation with an ordered design (source order, `:where()` to lower weight, or one documented layer of variants) so no rule needs `.x.x.x` to win.
   - **`!important`.** Each one justified or removed.
   - **Copied blocks.** Shared rules move to `lib/base` or one shared selector list.
   - **Dead rules.** Selectors no component, variant or modifier can produce.
   - **What ships where.** Whether every slide preview frame needs the whole stylesheet, or only the components a deck uses (the Studio's on-demand styles work, `engineering/decisions/2026-10-17-on-demand-styles-brief.md`, is the starting point).
3. **Optimizations, one PR per finding or tight group**, each with before and after numbers and the five floor checks, cheapest and lowest risk first. Bytes freed come off any related route-budget ceiling in the same PR.
