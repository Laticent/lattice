# chart(kanban): per-card detail reveal (Tier-2, on the HTML-mark path)

## Summary

Extend the per-mark interactive detail reveal to **kanban** — a card's detail (owner, notes, blockers) as an optional authored level — reusing the HTML-mark path established for state-chart. Child of #466 (Tier-2 umbrella). state-chart shipped in #473.

## Swimlane

`engineering/decisions/2026-06-20-chart-detail-reveal-family.md` (§ Tier 2). Tier-1 substrate: `lib/components/chart/_chart-family/mark-detail.js`.

## What #473 already established (reuse it — don't rebuild)

- **HTML-mark reveal path** in `docs/src/playground/drawing-board-chart-interact.js`: chart-root selector matches HTML figures; dim + popover are chart-agnostic; the active mark lifts perpendicular to the flow (`liftVec` `translate` sized by `offsetHeight`, survives the fit-scale). Usually **zero** reveal-layer changes needed for a new HTML chart.
- **The re-measure-under-transform guard.** If any kanban layout pass re-measures `getBoundingClientRect` on mutation, it must bail while a reveal transform is live — otherwise a reveal-triggered redraw under the Drawing Board's fit-scale collapses the layout (the mobile garble #473 fixed for state-chart).
- **Kernel pattern**: tag each card with `data-mark="i"` (+ invisible `data-label`/`data-value`), emit `markDetail.detailPayload(...)` as a **sibling** of the figure (not a descendant — it'd be miscounted as a mark) and `markDetail.detailNote(...)` after it. Byte-identical when no detail authored.

## Scope / grammar problem

kanban is HTML → **reveal only, no tilt**. Cards are already ~3 levels deep, so a card's detail needs a **deeper authored level** — decide the grammar first (see #466's per-chart notes). This is the deepest-nesting of the three Tier-2 charts.
