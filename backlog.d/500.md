# feat(legal): obligation-matrix cover-paginate — a split that survives a wide matrix

## Summary

`obligation-matrix` was deliberately **left out** of the cover-paginate batch (#496) because a six-column matrix overflows **horizontally** in portrait — `partitionAxis(row)` can't fix that. Give it a split path that actually fits.

## Swimlane

`engineering/decisions/2026-06-23-read-across-carousel.md` § "On deck" — *"obligation-matrix — a column-aware split (or the `asymmetric` card-per-row variant) so a wide matrix can cover-paginate without futile row-splitting."*

## Done when

A dense `obligation-matrix` with `autosplit: on` splits to fit **without clipping or ballooning**, verified in a committed demo (light + dark). One of:
- (a) the `asymmetric` (card-per-row) variant is auto-applied/recommended on overflow so it becomes vertically splittable, **or**
- (b) a column-aware split, **or**
- (c) row-split in landscape with a deliberate, documented portrait fallback.

## Context
- **Shares the wide-table question** with `compare-table` (see that card) — settle the strategy there first; this card applies it to obligation-matrix.
- The measure gate (`CAROUSEL_NAMES` in `lattice-emulator.js`) marks **any** overflow splittable for a layout that declares a `split` recipe. A wide table's horizontal overflow is never fixed by `partitionAxis(row)`, so naive wiring re-splits every pass and **balloons the deck** until the render times out. Any solution MUST guard against that (this is exactly why obligation-matrix was excluded, not an oversight).
- Today obligation-matrix has no `split` recipe and falls to the ring (clips) when it overflows.
