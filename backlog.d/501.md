# fix(inventory): glossary range pill is stale on cover-paginate split pages

## Summary

When a `glossary` cover-paginates, **every split body page shows the whole glossary's range pill** (e.g. "A – Z") on its heading, instead of that page's own sub-range (e.g. "A – F"). Recompute the pill per split page.

## Swimlane

`engineering/decisions/2026-06-23-read-across-carousel.md` § "On deck" — *"glossary's split-aware range pill (recompute per page instead of once pre-split)."* Shipped in #496 with this documented limitation.

## Done when

In a committed demo, each split glossary page's `.range-pill` shows the first→last term initials of **that page only**; the cover carries the full range. Verified visually (the existing `examples/cover-paginate.md` glossary already splits — extend/inspect it).

## Context
- The pill is injected into the `<h2>` by `glossaryRange` (`lib/integrations/markdown-it/plugins.js`, ~L771) **before** the split, so `partitionAxis(row)` repeats the same full-range pill on every body page.
- The fix belongs in the cover-paginate body emission — `coverPaginateSections` (`lib/core/carousel.js`): derive each page's range from its own `<tbody>` rows and replace the pill text. Keep it glossary-specific enough that it doesn't touch other layouts (only glossary carries `.range-pill`).
- Cosmetic / low priority — the rest of the glossary split (cover, native rows, repeated `<thead>`, rail) is correct.
