# Verify + fix debug-overlay touch reveal on real iOS Safari (PR #658)

## Summary

The debug-overlay touch-to-reveal (PR #658, branch `claude/debug-bbox-front-matter-xi4mdu`) is **UNVERIFIED and likely broken on iOS**. Every "verified under mobile emulation" claim was true only of a synthetic Puppeteer harness (`applyDebug` on a bare iframe), never the real Playground/Studio preview, and never a real device. Everything else in #658 (engine `debug:` directive, export-strip, Studio control, desktop render) is trustworthy — only the touch reveal is at issue.

**Prime suspect (unconfirmed):** `position:fixed` inside an iframe on iOS Safari — the `#lattice-debug-capture` / `#lattice-debug-overlay` fixed layers don't track the iframe's internal scroll, so taps land on the deck and chips mispositioned. Passes on desktop Chromium, fails on iOS — matches the symptom.

**Likely fix direction (evaluate on real iOS):** stop relying on `position:fixed`-in-iframe — either size the capture layer to full scroll content + position chips via `getBoundingClientRect + scroll{X,Y}`, or drop the covering capture div and attach **capture-phase** pointer/touch listeners on the iframe document + hit-test with `elementFromPoint` (capture phase fires before the chart-interact/SYNC bubble handlers, so `stopImmediatePropagation` still gives debug precedence). Owner directive: in debug+hover, debug takes precedence over everything; swipe may stay, other gestures off.

Code: `docs/src/playground/debug-overlay.js` (the agent), wired in `PlaygroundApp.tsx` / `drawing-board-render.js` / `single-slide-render.ts` (Studio); real preview iframe CSS in `docs/src/styles/playground.css` (`#preview` fixed height + internal scroll).
