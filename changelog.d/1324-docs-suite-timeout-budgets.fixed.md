- The docs Vitest suite no longer fails at random on `main`. Its two wall-clock budgets were library defaults sized for an idle machine — vitest's 5 s `testTimeout` and Testing Library's 1 s `asyncUtilTimeout` — while the Studio component tests cost 1–2 s each and the suite runs its own files in parallel. Contention killed whichever test was scheduled against the worst of it, a different one each run, every one of them passing in isolation. Both budgets now live in `docs/test-budgets.js` with the measurements that sized them.
- A required check that fails at random ejects PRs touching zero files under `docs/` from the merge queue, so this was a tax on every change in flight, not just docs work.
- New `npm run test:report` (the suite plus a JSON reporter) and `npm run check:test-margin` (how close each test is running to its budget — report-only), and a `Docs suite flake nightly` workflow that runs the suite three times over and opens a rolling issue if any run disagrees.
