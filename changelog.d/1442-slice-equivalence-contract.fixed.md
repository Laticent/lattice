- **Preview fidelity:** a deck using `logo-on: title` no longer paints its logo on every slide rendered through the single-slide (slice) route — the slide-overview grid and any other surface that renders one slide alone — on any deck whose slide index the position guard can trust. (The main slide preview renders the whole deck and narrows to one section, so it never showed this.) `logo-on: title` selects the deck's first slide, and a sliced slide is its own document's first section, so the preview showed a mark the export did not. The engine now hands the deck position down to the logo pass, the same way it already did for the SVG accessibility names. A deck the position guard declines (a `_focusSteps` deck, or one whose slide count disagrees with the render) gets no position, so it is not repaired there yet.
- **`npm run equiv:check` compares the corpus baseline directionally instead of exactly.** Deck and slide counts may grow (adding an example deck is not a regression) but may not shrink; the equivalence, refusal, prelude and skip *rates* are what get pinned. The old exact comparison failed on ordinary corpus growth with a message that read like a real regression, and — with nothing invoking it — sat red and unread from 154 decks to 158.
- **The sweep now runs in the unit tier** (`test/unit/diagnostics/slice-equivalence-baseline.test.js`), so `npm test` reads the gate that nothing was reading.
- **Every equivalence residual now reports a named cause.** The 27 previously `unclassified` residuals were 25 instances of the logo defect above plus 2 of the position guard correctly refusing, which now reports under its own name. Refusals are counted, rated and listed per deck as a baseline field.
