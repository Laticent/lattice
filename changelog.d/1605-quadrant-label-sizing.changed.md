- `quadrant` now sizes its item labels **per slide** instead of from one constant shared by every quadrant in every deck. That constant had to be the largest size the most crowded slide in the corpus could carry, so a sparse chart printed at a size a fourteen-dot chart needed. The kernel takes the largest size the slide's own geometry can carry: measured across the 25 quadrant slides in the tree, 22 print larger than before and 5 reach the house's smallest type tier, where none did. A slide that cannot be lifted renders byte-identically to before.
- The size search will not buy type with attribution. Its first cut accepted any size at which every name still placed, and on the gallery's own headline slide that took the top rung and pushed seven of eight names off their dots — the worst by about 15% of the plot width — stacking three into a column that reads as a list, with one name parked on a neighboring quadrant's fill. Every name was present, so nothing objected; the render showed it. A rung is now accepted only while no more names travel, and none travels further, than at the size the slide already rendered at.
- `quadrant`'s label width budget scales with the chosen type size, so a bigger name keeps the same characters-per-line instead of wrapping to three lines and breaking mid-word.
- The `--quadrant-dot-size` custom property is new, and is the floor rather than the size — themes can retune it, and the kernel writes the per-slide choice onto the label group.
