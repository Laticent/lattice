- **Fixed: the backlog mirror had been green and dead for three weeks.** `sync-backlog.yml` ran nightly, regenerated `BACKLOG.md`, force-pushed and reported success — but its PR never merged, so the committed mirror froze at 2026-08-10 claiming "167 open · 8 need triage" against a live queue of 271. `actions/checkout` writes the repo token into git config as an Authorization extraheader, and that header overrides the `AUTOMATION_PAT` credentials in the push URL: every nightly force-push was attributed to `github-actions[bot]`, and a bot-attributed event's CI run is created and then parked in `action_required` with zero jobs ever started — so the required `ci` check never reported and auto-merge could never fire. Parked, not absent: a human could have approved any of the twenty runs, and nobody knew to look. The checkout now sets `persist-credentials: false`.
- `release.yml` carried the same bug latently and now carries the same fix. It survived only because a release always cuts a fresh branch, so its PR's first event is an `opened` raised over REST by the PAT; the first release needing a second push to an already-open PR would have frozen identically.
- `test/unit/tools/workflow-push-identity.test.js` pins the invariant: a job that pushes with its own embedded credentials must not let the checkout persist the repo token over them. Two jobs are exempt because they push from a working tree they build themselves in a temp directory, and the exemption verifies that claim rather than trusting the label.
