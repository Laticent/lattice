- Slide layering is now a model instead of a habit. A slide is six named planes (`lib/base/base.tokens.css`): `--z-canvas` and `--z-atmosphere` sink below the words, content rests at the natural flow, and `--z-chrome`, `--z-mark` and `--z-alarm` rise above it. Every layering decision at slide scale names one. This executes the plane model the Form manifests have always declared: every Cell and Tile carries a `z`, and until now nothing read it.
- Every `section` is a stacking context unconditionally. It used to be gated on `.form`, so a sovereign frame (`title`, `math`, `divider`, `image`) formed none at all and its `z-index` values escaped to the page root, where they were ordered against *other slides*. The stage Cell likewise isolates unconditionally, instead of only when the deck happened to set a `finish:`.
- **Fixed:** the section-number watermark painted *under* a finish backdrop rather than above it — its manifest declares the atmosphere plane while its CSS said `z-index: -1`. On patterned finishes the texture ruled straight across the ghost numeral.
- **Fixed:** running chrome (header, footer, logo, progress rail) shared one plane with body content under a `finish:`, so which covered which was decided by DOM order. Chrome now sits above content by definition.
- The `.below-note` hairline now paints a solid accent rule in exports where the screen keeps its gradient fade — the same rich-on-screen / safe-on-export split the finish presets use. A gradient *image* at hairline scale does not survive Chromium's print path once a slide carries a few stacking contexts.
- Two new gates. `checkZPlanes` (`npm run build:check`) rejects any `z-index` outside the local `0–9` band that does not name a plane token, plus plane tokens nothing reads and tokens nothing defines. `test/integration/invariants/slide-planes.test.js` renders a corpus and asserts every real direct child of every section lands on a plane. The Form manifest ↔ CSS check (§4.3) is now an equality test — the manifest plane and the CSS plane must be the same plane — where it was only a monotonicity test that the watermark defect passed.
- **Removed:** `base.finish.css`'s blanket `section.finish > *:not(.backdrop)` rules, their `:where(…)` frame-chrome exclusion list, and the `checkFinishChromeExclusions` gate that kept the list honest. With planes there is nothing to exclude.
