- **Fixed:** a directive value could inject a CSS declaration into a slide's inline `style`, setting arbitrary CSS — including a slide plane, which erases the deck body under a `finish:` backdrop. Three earlier fixes each closed one spelling and left the class open: `footer: 'url(a"b);--z-canvas:9'` beat the first, `footer: "'url(';--z-canvas:9"` and a `url(` inside a CSS comment beat the second, and the third was beaten by a raw newline in the value, by an odd run of backslashes, and — with no special characters at all — by any slide carrying a `![bg]` image.
- Directive values are no longer parsed to judge them safe. A custom property (`--header`, `--footer`, …) is emitted as a CSS **string**, which cannot terminate its declaration whatever it contains — so the author's text is preserved in full rather than dropped, including the ordinary prose semicolons that the earliest fix silently discarded from 20 shipped decks. Quoting is now unconditional: the previous "this value already looks like a string, leave it as written" shortcut was the only unquoted path and therefore the whole attack surface. Characters a CSS string cannot hold literally — the newline above all — are escaped rather than passed through.
- The six real declarations an author can reach (`color`, `background-color`, `background-image`, `background-position`, `background-repeat`, `background-size`) cannot be quoted, so they are validated against a narrow allowlist with a carve-out for `url()` — quoted, unquoted, and data URIs. Two things are newly rejected there, each of which used to run to the end of the attribute and delete every declaration the engine writes afterwards: a comment opener, and a raw newline inside a *quoted* `url()`, which is tokenized as a function plus a string rather than a URL and so never closes its own parenthesis.
- A slide's style is built once and reused, instead of being re-parsed out of the attribute the engine had just written. The background-image pass used to rebuild it from that serialization, and the round trip split a safely quoted value back apart into live declarations. That guard is now held by a test driving the real engine end to end, because the unit test pinning it exercised a hand-made token and left the module that actually had the bug free to regress with every suite green.
- **Note for anyone reading `--background-image`:** it is now a quoted CSS string (`"url(\"…\")"`), not a `url()` token, so it can no longer be fed to `background-image: var(--background-image)`. Nothing in the engine reads it — the real `background-image` declaration beside it is what paints — but this diverges from marp-core's output, which the file previously claimed to mirror exactly.
- `checkZPlanes` also verifies each plane's `@property` `inherits` descriptor, the one the fallback semantics depend on and the only one with no cross-check.
