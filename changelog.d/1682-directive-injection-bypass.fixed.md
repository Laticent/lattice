- **Fixed:** a directive value could still inject a CSS declaration into a slide's inline `style`, despite the guard added in #1648. That guard tracked quote state before checking whether the quote sat inside an unquoted `url(`, so `footer: 'url(a"b);--z-canvas:9'` slipped a live `;` through — CSS reads `url(a"b)` as a bad-url-token ending at `)`, making the rest a new declaration at the highest cascade tier. On a `finish:` deck that lifted the backdrop over every word and rendered the deck with its body erased. The scanner now tracks only `url()` token boundaries, which is all that decides whether a `;` terminates a declaration, and the contract is held by `test/unit/engine/directive-style-injection.test.js` rather than by prose.
- A `;`, `}` or `<` outside a `url()` still drops the declaration — including in ordinary prose, so a `footer:` containing a semicolon loses its `--footer` custom property (the rendered footer text is unaffected). Three example decks are affected. An apostrophe or quote in prose is now untouched, which the first cut of this fix got wrong.
- `checkZPlanes` also verifies each plane's `@property` `inherits` descriptor. It is what makes an invalid value fall back to the declared plane rather than the initial one, and it was the only descriptor with no cross-check.
