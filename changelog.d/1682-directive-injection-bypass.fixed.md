- **Fixed:** a directive value could inject a CSS declaration into a slide's inline `style`, setting arbitrary CSS — including a slide plane, which erases the deck body under a `finish:` backdrop. Three earlier fixes each closed one spelling and left the class open: `footer: 'url(a"b);--z-canvas:9'` beat the first, `footer: "'url(';--z-canvas:9"` and a `url(` inside a CSS comment beat the second, and the third was beaten by a raw newline in the value, by an odd run of backslashes, and — with no special characters at all — by any slide carrying a `![bg]` image.
- Directive values are no longer parsed to judge them safe. A custom property (`--header`, `--footer`, …) is emitted as a CSS **string**, which cannot terminate its declaration whatever it contains — so the author's text is preserved in full rather than dropped, including the ordinary prose semicolons that the earliest fix silently discarded from 20 shipped decks. Quoting is now unconditional: the previous "this value already looks like a string, leave it as written" shortcut was the only unquoted path and therefore the whole attack surface. Characters a CSS string cannot hold literally — the newline above all — are escaped rather than passed through.
- The three real declarations an author can reach (`color`, `background-color`, `background-image`) cannot be quoted, so they are validated against a narrow allowlist with a carve-out for `url()` — quoted, unquoted, and data URIs. A comment opener is now rejected there; it used to run to the end of the attribute and delete every declaration the engine writes afterwards.
- A slide's style is built once and reused, instead of being re-parsed out of the attribute the engine had just written. The background-image pass used to rebuild it from that serialization, and the round trip split a safely quoted value back apart into live declarations.
- `checkZPlanes` also verifies each plane's `@property` `inherits` descriptor, the one the fallback semantics depend on and the only one with no cross-check.
