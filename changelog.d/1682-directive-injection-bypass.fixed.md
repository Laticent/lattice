- **Fixed:** a directive value could inject a CSS declaration into a slide's inline `style`, setting arbitrary CSS — including a slide plane, which erases the deck body under a `finish:` backdrop. Two earlier fixes each closed one spelling and left the class open: `footer: 'url(a"b);--z-canvas:9'` beat the first, `footer: "'url(';--z-canvas:9"` and a `url(` inside a CSS comment beat the second. Both tried to decide whether a given `;` was inert by approximating CSS tokenization.
- Directive values are no longer parsed to judge them safe. A custom property (`--header`, `--footer`, …) is emitted as a CSS **string**, which cannot terminate its declaration whatever it contains — so the author's text is preserved in full rather than dropped, including the ordinary prose semicolons that the previous fix silently discarded from 20 shipped decks. A value that is already a well-formed CSS string is left as written. The three real declarations an author can reach (`color`, `background-color`, `background-image`) cannot be quoted, so they are validated against a narrow allowlist with a carve-out for `url()` — quoted, unquoted, and data URIs.
- `checkZPlanes` also verifies each plane's `@property` `inherits` descriptor, the one the fallback semantics depend on and the only one with no cross-check.
