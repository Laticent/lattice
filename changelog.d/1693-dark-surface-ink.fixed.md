- **Fixed:** text on a title, closing, or divider bookend could render in light-canvas ink on the dark field — bold body text measured 1.61:1 against a 3:1 floor, effectively invisible. Those bookends painted `--surface-inverse` without declaring `color-scheme: dark`, so every `light-dark()` token on the slide resolved to its light side and anything the base layer had not named explicitly inherited the wrong ink. The scheme is now declared in the same rule that paints the surface, which fixes the whole class rather than the elements someone happened to notice: four hand-written per-element rebinds existed before this, each added after a bad slide was spotted, and bold text was simply never on the list.
- **Fixed:** every theme's inline-code ink was being ignored. `--code-inline-fg` had an engine default of `var(--accent)`, and because `packTheme` relocates a theme's `:root` onto `section`, the two declarations collided at equal specificity where source order decides — the engine bundle wins. Fourteen themes carry an ink deepened so the chip clears AA on a *card* and not merely on the canvas, each with its measured ratios recorded, and none of them reached the page; the chip shipped `--accent` at 4.36:1 against a 4.5 floor.
- `--code-inline-fg` is now a derived, required token (`lib/theme/derive.js`, `ink` group), repaired against both the canvas and the card. It was ink falling back onto `--accent`, an area token held to the 3:1 graphical floor rather than a text contract — the same shape as the `--cat-N-ink` defect. Generated palettes get a correct value instead of inheriting the gap.
- Measured on the rendered DOM with `tools/check-slide-contrast.js`: `examples/accent-finishes.md` goes from 14 sub-AA text runs to **0**, in `indaco`, `a11y-base` and `indaco-dark` alike.
- The `bookend-ink` integration invariant now sweeps the ordinary inline vocabulary — plain body, bold, italic, links, inline code — across all three dark bookends, instead of checking the one label that had broken before. Verified by mutation: removing the `color-scheme` declaration fails it. The previous per-element rebinds each had their own passing test and none of them would have caught the reported bug.
