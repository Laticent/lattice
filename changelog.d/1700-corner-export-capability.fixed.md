- `corners: rounded` now degrades to a square corner in any export format that cannot carry a transparent background, instead of shipping four pale notches. PNG and WebP (both the CLI and the Studio, slides and thumbnails) keep the real rounded corner as transparency; JPEG, PDF and PPTX render square.
- **Fixed:** a PowerPoint export of a rounded deck no longer ships transparent corners that pick up the color of whoever opens the file — neither exporter writes a slide background, so the corner was taking the recipient's PowerPoint theme.
- **Fixed:** the CLI's PNG and WebP exports of a rounded deck baked white into the corner instead of leaving it transparent, so the same deck exported square from the CLI and rounded from the Studio.
- A deck with no rounded **slides** renders byte-identical images and PDFs — the transparent capture is gated on a slide actually carrying the corner, not on the front-matter key, so a deck that opts in per-slide with `_class: corners-rounded` does get the new alpha channel. (The `.html` sidecar gains the print rule, so it grows slightly for every deck.)
