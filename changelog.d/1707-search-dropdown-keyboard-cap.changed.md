- The Studio's inline ⌘K search now caps its dropdown against the **visible** viewport rather than the full one, so a software keyboard can no longer crowd it. The list's height was `min(60vh, 420px)` — both arms blind to a keyboard, since `vh` does not shrink for one — and at an iPad Pro 11" landscape geometry (1194×834 with a ~350pt keyboard) that put the list's last row within a pixel or two of where the keyboard begins. It takes a third arm from the visual viewport, the same measurement every mobile sheet already caps against, so the list shortens whenever the visible band does. At 100% zoom with no keyboard the geometry is unchanged at every width; under **page zoom** the list now shortens too, which is deliberate — a list taller than the visible band would have to be panned to read.
- The inline dropdown gains a regression test for the invariant that took three attempts to land: it paints **below** the header rather than clipped inside the 54px bar. Two ancestors can clip it away — the `Command` widget's own base-class `overflow-hidden` and the header's `overflow-x: auto` scroll valve — and clearing only one paints nothing; the test fails if either comes back.
