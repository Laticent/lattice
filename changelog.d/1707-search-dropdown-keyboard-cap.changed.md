- The Studio's inline ⌘K search now caps its dropdown against the **visible** viewport rather than the full one, so a software keyboard can no longer crowd it. The list's height was `min(60vh, 420px)` — both arms blind to a keyboard, since `vh` does not shrink for one — and at an iPad Pro 11" landscape geometry (1194×834 with a ~350pt keyboard) that put the list's last row within a pixel or two of where the keyboard begins. It takes a third arm from the visual viewport, the same measurement every mobile sheet already caps against, so the list shortens whenever the visible band does. At 100% zoom with no keyboard the geometry is unchanged at every width; under **page zoom** the list now shortens too, which is deliberate — a list taller than the visible band would have to be panned to read.
- The inline dropdown gains a regression test for the invariant that took three attempts to land: it paints **below** the header rather than clipped inside the 54px bar. Two ancestors can clip it away — the `Command` widget's own base-class `overflow-hidden` and the header's `overflow-x: auto` scroll valve — and clearing only one paints nothing; the test fails if either comes back.
- Opening the Studio's inline ⌘K search no longer empties the right-hand side of the header. The row still reclaims that width for the field — at tablet widths it has 0px of spare, so it has to — but the controls it displaces now collapse into a single hamburger at the row's right edge instead of disappearing, and everything they reach is inside it: Present, Share, feedback and Workspace settings at every width, plus Coach, Chat, Settings, Library and Reader views at tablet, where the row's own ⋯ menu is displaced too. Running any of them closes the search on the way out.
- **Breaking (behavioral): the Studio header is now one width ladder instead of three device tiers.** The search pill was suppressed below 1100px and `display:none` below 1024px, so a tablet — and any desktop window resized narrow — had no visible way to search, while Coach, Chat, Settings and the dark-mode toggle stayed in the row and crushed the deck title to 42px (measured at 700px, where the row also overflowed by 20px). The row now keeps one persistent set at every width — logo dropdown · deck dropdown · posture dial · search — and everything else overflows into a permanent "More controls" menu in row order, first to leave being theme and tours, then feedback, then Present and Share. A resized desktop window and a tablet at the same width now draw the same row; the logo is a dropdown at every width and stop, where the slim Read/Write header used to draw a bare mark. Measured at 1440/1280/1100/1024/900/834/768/700 across Write and Craft: search present everywhere, no overflow anywhere, deck title never below 230px.
