- **Breaking:** `--text-muted` now carries a 4.5:1 AA floor on `--bg` and `--bg-alt` across every palette, and the decorative half of what it used to do moved to a new `--muted-mark` token at the 3:1 graphical floor. A deck or consumer theme that reads `--text-muted` for a rule, hairline, empty mark or low-alpha wash should read `--muted-mark` instead; a consumer theme that DECLARES `--text-muted` must now declare `--muted-mark` too. It does NOT fall back: all 73 engine reads are bare `var(--muted-mark)` and the engine base declares no `:root` default, so on a theme that omits it those declarations are invalid at computed-value time and the decoration DISAPPEARS — rendered and confirmed on `checklist`, where the descoped `[/]` row loses its status disc and slash mark entirely, which is the component's own color-blind-safe channel. Themes exported from the Studio before this change are in that population.
- `--text-muted` was below AA on 44 of 72 palette-mode-surface pairs, worst 2.11:1, while 53 engine-CSS sites painted real text with it — captions, table headers, the CodeMirror gutter and completion detail, the docs chrome. All 36 palette-modes now clear AA on both surfaces.
- Finish vignette rims (`finish-halo`, `finish-nimbus`) painted in the brand accent instead of a neutral ink. They read `var(--ink, var(--accent))`, and `--ink` was declared nowhere in any palette, so the fallback won on every theme. The rims now read `--text-heading`. Studio-fabricated finishes, the Finish Studio's placement handles and `examples/finish-override.md` carried the same phantom.
- A highlighted mark in a chart→anima scene took its emphasis stroke from the same phantom `--ink` with no fallback at all, so it resolved to whatever text color it inherited rather than to an emphasis color.
- The four `a11y-*` palettes inherited `onyx`'s syntax colors for slide code panels — green strings beside red keywords, the red-green axis those palettes exist to avoid. Each now has its own family, spaced on the axes its own condition leaves; worst separation under the condition improves 6x to 8x. These paint on the engine's own composed CSS and on the live slide preview (Studio and docs site). They do NOT reach an emulator-exported PDF: `lattice-emulator.js` loads the base after the theme, so the base's syntax colors win there until that order flips (#1527).
- The Studio's Markdown deck editor applied no syntax highlighting at all, so deck source rendered as untokenized plain text while both sibling editors highlighted.
- New `build:check` gates: `checkPhantomTokenReads` (a token read in engine CSS or a slide-bound emitter that no palette declares and nothing writes at render time), `checkMutedTierFloors` (each half of the muted tier against its own floor), and `checkHljsSeparation` (a11y syntax colors measured through a color-vision simulation, not just for contrast).
- `lib/theme/cvd.js` gained an achromatopsia simulation; it previously modeled only the three dichromacies, so the condition one shipped palette is named for could not be measured.
