- Every nightly watch can now **close its own rolling issue** when the condition clears. Five of the six could file an alarm and none could stand one down, so a thread's first firing — likelier a harness failure than a real regression — turned it into "the flaky nightly", and a genuine regression months later arrived as a comment nobody reopened. A stand-down closes only on evidence: the measuring step must have SUCCEEDED and reported an explicit `false`, never merely "not `true`", which is satisfied by the empty output a canceled or timed-out job leaves behind.
- The two `studio-e2e-nightly.yml` jobs additionally require a non-zero passed count before closing anything. With `OPEN_ROUTER_KEY` unset the live-AI spec skips every test and exits 0, so step outcome and output both read green while nothing at all was tested.
- `perf-nightly.yml`'s `watch` job comments on a measured-green night and deliberately does **not** close: it compares head against a base ~24h old, so a clean night cannot tell "fixed" from "the base now carries the regression too".
- Every rolling-issue lookup across the six workflows moved off GitHub's `--search "in:title [marker]"`, which tokenizes on brackets and hyphens and matches human-authored issues, onto a client-side title match. A filing step and a stand-down step in the same job now provably search for the same issue.
