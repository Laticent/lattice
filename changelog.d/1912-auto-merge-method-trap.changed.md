- `engineering/workflow.md` § Merging now explains `auto_merge.merge_method` correctly: it records what was *requested*, and when a merge queue governs the branch the **queue's** method decides. A stored `"merge"` on a queue-governed PR is a stale label, not a pending merge commit — `git rev-list --count --merges origin/main` is `0`, including from a PR whose `auto_merge.merge_method` has read `"merge"` for weeks. The field still matters on a branch the queue does not govern, where it *is* what lands and defaults to the repository default.
