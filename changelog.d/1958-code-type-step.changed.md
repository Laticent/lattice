- **Code slides read one type step larger.** The `code` layout now sets its block at `--fs-body-compact` instead of `--fs-meta` — the same canonical role its `compare-code-block` sibling already used — so code is no longer set at the deck's smallest chrome size. The step is not one ratio: measured **+19.7%** at landscape, **+17.1%** at square and **+33.1%** at portrait/reel, because the two roles are spaced differently per family.
- The capacity that follows from it is now MEASURED rather than asserted: a landscape `code` pane holds **14 lines**, where it held 16 before this change and the docs claimed 20. The line-width budgets were re-measured to **102/58/36/36** columns (wide/square/tall/strip), down from 122/68/49/48. `whenToUse`, `commonMistakes` and the stress sample all carry the real numbers.
- **A `tall` budget now takes the tighter of its two @sizes.** `portrait` fits 37 columns and `reel` fits 36, so the table carries 36. At the old size both floored to 49 and one number was free; the wider columns split them, and the guard test measured `portrait` only — so a 37-column line on a `size: reel` deck would have linted clean and exported clipped. The guard now measures **every** canvas in a family and asserts the budget is the family minimum.
- `compare-code` is deliberately unchanged: its panes are half-width, and two shipped gallery slides would have started clipping.
