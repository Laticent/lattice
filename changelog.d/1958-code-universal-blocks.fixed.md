- **`code` slides now take all three trailing-paragraph registers** — Key Insight, below-note and the italic annotation. Two separate things were withholding them, and only the first was known when this change started.
- **The below-note** was blocked by a coda claim. `code` reserved its trailing paragraph for a caption whose CSS selector the markdown path never produces (`section.code > .cell-stage > em`, while a markdown italic-only line is always wrapped in a `<p>`), so the reservation bought nothing and cost the block. A trailing paragraph had been rendering as unstyled body text inside the code stage; it now docks in the coda band under its hairline, where the same block already lands on `content` and `compare-code`.
- **The annotation** needed more than dropping that claim. Unlike below-note, which is opt-out, the annotation register is an opt-in union hand-enumerated in `lib/base/base.modifiers.css`, and `code` was not in it — so an italic trailing paragraph on a `code` slide rendered as an ordinary note, with no `✦` and no dotted rule. `code` is now in all three of those unions (hairline suppression, type/color, and the `✦` mask), verified on a real render.
- `lib/base/base.docs.md` said the annotation covered the "same set as Below-Note". It never did — one is opt-out, the other opt-in — and that line is now corrected with the real list and the three-union rule for extending it.
