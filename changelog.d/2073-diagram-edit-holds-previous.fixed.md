- Editing a Mermaid fence in a live preview now keeps the diagram already on screen until its replacement is rendered, instead of emptying the slot for the ~200ms the render takes (~460ms on a loaded machine). Typing inside a fence changes the source, so no cached SVG can answer it — the runtime carries the outgoing diagram into the fence that replaced it, and the render swaps it out when it lands. Layout shift stays 0.
- Arriving on a diagram for the first time no longer waits out the 150ms render debounce, which exists to coalesce an author's keystrokes and has nothing to coalesce for a diagram that has just appeared: 214ms of empty slot down to 75ms.
- `npm run bench:flash` grew an `edit` arm (typing INSIDE the fence, which no cache can answer) and an `edit-broken` one, counts held frames separately from blank and source ones, counts `mermaid.render` calls, and refuses to run against a server it did not start.
