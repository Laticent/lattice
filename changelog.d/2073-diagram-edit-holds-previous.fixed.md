- Editing a Mermaid fence in the Studio now keeps the diagram already on screen until its replacement is rendered, instead of emptying the slot for the ~200ms the render takes (~490ms on a loaded machine). Typing inside a fence changes the source, so no cached SVG can answer it — the runtime now carries the outgoing diagram into the fence that replaced it, and the render swaps it out when it lands. Measured layout shift stays 0.
- `npm run bench:flash` grew a `--scenario edit` arm — the case that types INSIDE the fence rather than in the slide's heading — and now counts held frames separately from blank and source ones, so a run that holds the previous diagram can no longer be scored as an instant render.
