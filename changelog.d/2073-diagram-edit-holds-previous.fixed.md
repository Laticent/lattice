- Editing a Mermaid fence in a live preview now keeps the diagram already on screen until its replacement is rendered, instead of emptying the slot for the ~200ms the render takes. The hold survives a run of keystrokes, not just the first: each swap carries the last ink forward, so typing at speed no longer blanks the diagram for the rest of the burst. Layout shift stays 0.
- A diagram is held only when the preview host declares the swap to be the same slide edited in place, and that declaration now means what it says. It used to compare slide POSITION, so deleting a slide, reordering, restoring a checkpoint or opening a different deck of the same length could each paint the outgoing slide's diagram over the one that replaced it. It now requires that everything except the slide on screen is byte-identical to the last render, plus the deck's own identity where the source cannot settle it (a one-slide deck compares nothing, because the shown slide is the one excluded). Navigating between slides, or to another deck, shows an empty slot rather than another slide's drawing.
- `npm run bench:flash` grew `edit`, `edit-burst` and `edit-broken` arms (typing INSIDE the fence, which no cache can answer — one character, a run of eight, and a run that leaves the diagram unparseable), counts held frames separately from blank and source ones, reports which diagram is on screen so another slide's ink cannot score as a hold, counts `mermaid.render` calls, and refuses to run against a server it did not start.
