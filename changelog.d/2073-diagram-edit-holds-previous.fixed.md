- Editing a Mermaid fence in a live preview now keeps the diagram already on screen until its replacement is rendered, instead of emptying the slot for the ~200ms the render takes. The runtime carries the outgoing diagram into the fence that replaced it, and holds it only when the arriving source is a REVISION of the one on screen — so navigating to a different diagram, or replacing one wholesale, shows an empty slot rather than the previous slide's drawing. Layout shift stays 0.
- Arriving at a diagram from a slide that had none no longer waits out the 150ms render debounce, which exists to coalesce an author's keystrokes and has nothing to coalesce for a diagram nobody has seen yet: 236ms to 207ms.
- `npm run bench:flash` grew an `edit` arm (typing INSIDE the fence, which no cache can answer) and an `edit-broken` one, counts held frames separately from blank and source ones, reports which diagram is on screen so another slide's ink cannot score as a hold, counts `mermaid.render` calls, and refuses to run against a server it did not start.
