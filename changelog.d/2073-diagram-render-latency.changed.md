- Editing a Mermaid fence redraws the diagram faster. A diagram that is cheap to draw — under ~50ms of render — updates live on every keystroke instead of waiting behind a fixed 150ms debounce. A costlier diagram takes the path it always took: the same 150ms trailing wait, with nothing added in front of it, so it cannot be slower than before.
- A diagram that does not parse *while you are still typing* no longer blanks the slot and shows you raw source on every keystroke. The previous drawing stays on screen, and the error box appears once you stop (about 450ms of quiet). The `mermaid.parse` check that makes this cheap runs only for diagrams that are cheap to draw — it costs ~1.8ms on a small fence but 45-61ms on a large one, which is a cost a large diagram never paid before.
- A diagram that has already failed to parse keeps its error box on screen while you edit a different diagram on the same slide, instead of blinking off every time you type. A failure that is *not* the fence's fault — a stalled icon-pack fetch, a render that never settles — is no longer remembered, so it can no longer pin an error box permanently on a surface with no way to edit the fence.
- Exporting a deck now waits for diagrams to stop making progress rather than for a fixed four seconds, so a slow deck can no longer bake a blank space into the PDF where a diagram should be.
