- **`CHROME_PATH` now actually selects the browser the renderer launches.** It never did: `detectChromeExecutable()` read `PUPPETEER_EXECUTABLE_PATH`, then puppeteer's cache, then `which` — while the SessionStart hook, `AGENTS.md`, `engineering/gotchas/ci.md`, `design/skills/deck.md`, `README.md`, `engineering/pipeline.md` and `test/benchmark/engine-bench.mjs` all set or documented `CHROME_PATH` as the way to fix "no browser". Measured both directions: `CHROME_PATH=/nonexistent/chrome` rendered a deck fine, and with the puppeteer cache made undiscoverable a *correct* `CHROME_PATH` failed while `PUPPETEER_EXECUTABLE_PATH` to the same file rendered. The variable looked load-bearing on every machine that already worked and did nothing on the one machine that did not.
- The two variables are deliberately not symmetric. `PUPPETEER_EXECUTABLE_PATH` stays first and unconditional — a pin that quietly renders on a different browser is worse than one that fails, and `overflow-nightly.yml` pins a specific Chromium precisely so its baseline stays comparable. `CHROME_PATH` is accepted only if the file exists, so a stale or decorative value falls through to the cache scan exactly as before. No configuration in the repo resolves a different binary than it did before this change.
- **Fixed:** `engineering/gotchas/ci.md` blamed browser auto-detection for not knowing about the puppeteer cache. The owned emulator scans that cache itself, so the entry's own "removable when the launcher adds puppeteer-cache discovery" exit had already been met. That half is true of marp-cli, not of the owned engine.
