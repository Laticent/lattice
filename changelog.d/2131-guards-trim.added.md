- **`guards:` front-matter register** — `guards: strict` lets TRIM cut text that overflows a box and leave a visible ellipsis, instead of letting the slide clip. `loose` is the default and changes nothing, so a deck that omits the key renders exactly as before. A per-slide `<!-- _class: guards-loose -->` opts one slide back out.
- TRIM only cuts prose: body copy, list items, captions and notes. Headings, KPI values, code, math, citations, legal text and footers are never trimmed, and an unclassified slot defaults to never — an ellipsis on a sentence says "there is more", but on a number it states a different one.
- TRIM declines rather than cutting where the ellipsis would land off-screen, and discards any plan that cannot make the box fit — so it never removes content and leaves the slide overflowing anyway. It plans against the box's measured content bottom, not just the text it can classify, so a card's own padding and border are counted: a cut that would leave the card sheared by a few pixels is not a cut it will take.
- A trim records what it removed (`data-lattice-trim`). The existing content-clipped probe can see a clamp but not a removal, so the record is the signal rather than an inherited one. The overflow ring, the "Content clipped" tag and the type-floor warning are all unchanged.
- The player's Read view shows the full text. Trimming fits a slide's fixed cell; the Read column scrolls, so the clamp is lifted there rather than truncating a reader who opened it to read.
- `npm run lint:deck` gains `unknown-guards`, which catches a typo silently resolving to the baseline — including one carrying a trailing comment.
