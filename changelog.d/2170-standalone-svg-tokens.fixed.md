- **A standalone chart SVG now carries its own color definitions.** The export bakes `fill:var(--token)` for every paint that matches a scheme-varying token, so the player can re-theme a chart when its toggle moves. A detached `.svg` file has no host to define those tokens: the `var()` resolved to nothing and the paint fell to the SVG initial, which for `fill` is **black**. Measured on the real files — a `map` export painted **172 of 184 shapes black**, and a `heatmap` export put 3 of its 5 ink stops below WCAG AA (worst `1.98:1`). Both are now 0.
- The exporter resolves every token the file references — through the computed-style bake, through an element's own inline style, and through a presentation attribute like `fill="color-mix(in oklab, var(--chart-cat-1-hue) 88%, …)"` — and writes them into the file's own `<style>` block. The third route is why a first cut still left one token undefined: `map` carries 16 of those and a sweep that read only `[style]` could not see them. The player's inline path never calls the finalizer, so its re-theming is unchanged.
- This reaches all 12 keyed chart layouts, not just the one that surfaced it.
