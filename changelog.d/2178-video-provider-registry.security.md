- **Security: a video URL is matched on its parsed host, so a foreign origin can no longer wear a provider's badge.** The `video` component resolved its provider by testing the whole URL for a substring, so a provider name anywhere in it counted — including in a fragment or a query. `https://evil.example/#instagram.com/reel/X` resolved as Instagram, and because TikTok and Instagram use the author's URL verbatim as their watch target, the slide rendered a "Watch on Instagram" badge and a **QR code encoding the attacker's origin**. Provider rows now declare their hostnames as data and the parsed host is matched against them. A player `src` was never affected — those have always been rebuilt from the parsed video id.
- **Changed: the video provider table is one registry, `lib/core/video-providers.mjs`.** The static render (poster link, provider badge, QR target) and the parent-hosted playback lightbox each carried their own table with their own id regexes, so adding a provider meant two edits in unrelated trees and missing the second silently degraded playback to "opens a tab". Adding a provider is now one row, read by every consumer. Merging the two also folded in what each knew separately: a YouTube `live/` link now plays in the lightbox, and a `youtube-nocookie.com/embed/` or `instagram.com/reels/` link now resolves on the static path.
- **Security: a video URL's watch target is re-serialized, so a QR scanner cannot reach a different host than the one we checked.** A backslash ends the authority under the WHATWG URL standard (every browser) but is userinfo under RFC 3986, so `https://instagram.com\@evil.example/p/X/` passed the host check and was then used verbatim as the poster link **and the QR payload** — which a phone parses with its own URL library. The target now comes back out of the parser that validated it.
- **Fixed: a video URL with no id in it no longer renders a dead link and a dead QR.** A channel page, playlist or profile built a truncated `…/watch?v=` target. It now falls back to the URL the author wrote, which the verified host makes a real link to that provider. A mixed-case hostname (`https://YouTube.com/watch?v=…`) hit the same truncation and now resolves, as does a fully-qualified name with a trailing dot.
