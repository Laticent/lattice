- **The deck's language now reaches the voice.** `lang:` was parsed, used to gate the English say-as rules, and then dropped — nothing downstream knew what language a deck was in. It now travels to the two surfaces that take one: the Web Speech path sets `utterance.lang` (without it, the browser picks a voice by system default, so an English deck could be read in whatever language that machine prefers), and the Stage document declares `<html lang>` like its two sibling builders already did.
- **New `voiceLanguageMismatch()` API** reports when a deck's declared language and the chosen voice disagree. Neither speech engine takes a language parameter — the OpenAI-compatible speech route does not have one, and the on-device model derives its language from the voice id — so the voice *is* the language control. This shipped the check as a tested function with no caller; it is wired now, in the Studio's webpage-export panel — see `changelog.d/narration-track-validation.fixed.md`.
