- **Breaking:** a chart's axis is now ONE bracketed list in its own paragraph, replacing the two- and three-code-span form `matrix-grid` and `scatter` used — `` `[Wider reach, Deeper cognition]` `` and `` `[Annual cost, Teams adopting, Seats]` ``. Quotes are optional, single or double, and protect a comma inside a name, so `` `["Cost, excluding tax", Value]` `` is two axes. The grammar also ACCEPTS a member carrying its range and threshold — `` `[{Effort, 0..10, 5}]` `` — but no component reads those parts yet; only the name is used, and the rest is ignored rather than honored.
- **Breaking:** POSITION now says which construct a bracketed span is. A list ABOVE the chart body names the axes; a list BELOW it renames the label set. `matrix-grid` decks that authored their key above the grid must move it below. The retired rules — an axis discriminated by holding exactly two code spans, a label set by holding exactly one — are gone, along with the constraint that made one construct's grammar a hostage of the other's.
- Axis names are never invented. Range and threshold still derive from the data, but where no name can be derived the axis renders unnamed; the editable starter wording lives in each component's scaffolder skeleton instead.
- `scatter`'s scaffolder skeleton no longer hands the author the placeholder `` `X measure` `Y measure` ``.
