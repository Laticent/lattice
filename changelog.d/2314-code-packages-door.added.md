- **Code packages run in the CLI, after you approve their code.** A component package that carries a `transform.js` now installs (`lattice packages add`), shows what the code is and what contains it, and asks. Your answer is recorded against the SHA-256 of the code and the OS sandbox layer you were shown, so changed code asks again, and a render that could only run it less contained is refused. `--trust` answers yes without a prompt, and `lattice packages trust` / `untrust` give and withdraw the approval later. A render that uses a code package you have not approved fails with the package's name and the command to approve it.
- The transform runs in a browser with no network, in a page that holds only the slide it draws, at the same point in the render as the shipped charts, and inside panes too. Its output is sanitized like any slide and keeps no address the slide did not already hold, so it can't send the slide anywhere or name a file on your disk. A slide whose package fails keeps its own content and shows a note saying why; a slide that also names a shipped component with a transform is that component's, and the render says so.
- As root on Linux, Lattice starts that browser as the unprivileged `nobody` user so Chromium's own OS sandbox can run, and checks that it does. Where that is not possible, the approval prompt and the render both say that this layer is missing, why, and how to fix it, even with `--quiet`. Code packages need Chromium 131 or later.
- `lattice packages export` exports an installed code package as it is, so its code and its approval digest survive the round trip. Shipped components are still not exported as code packages.
