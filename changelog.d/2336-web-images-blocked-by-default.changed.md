- **Breaking:** a deck's images from the web (`http:`, `https:`, `//host`) no longer load by default in the Studio's PDF, PowerPoint and image exports, as already in its preview, and in the CLI's exports. Each one shows as a drawn placeholder: a hatched box with a picture mark, in the deck's own colors, that keeps the image's address. A web `url()` background shows the same hatch. Loading a web image tells its server who opened the deck and when.
- The Studio shows "This deck loads N images from these sites" above the preview, with a **Load them** button. The choice is remembered for that deck and those sites only: a new site asks again, **Block again** takes it back, and a restored workspace backup never carries it. Your own decks are not trusted automatically, because a paste or an AI edit can add a web image too. The preview, Present (its overview grid included), the Stage window, Read · Article and the Studio's PDF, PowerPoint and image exports all follow the choice; the Webpage (player) export never loads a web image and always shows the placeholder.
- The CLI prints one line saying how many web images it left out, and from which sites (`--quiet` silences it); `--allow-remote` still loads them.
- The Studio's raster exports no longer fetch a web image from the page that drives the export: right before each slide is captured, every web image and `url()` outside the deck's choice is swapped for the placeholder, whatever its spelling, and put back afterwards. Read · Article, which shows the deck inside the Studio's own page, gets the same treatment.
