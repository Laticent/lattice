- **The approval prompt for a code package names the right fix when AppArmor turns the OS sandbox off.** On Ubuntu 23.10 and later, AppArmor stops an ordinary user's Chrome from starting its sandbox, and the prompt told them to set `CHROME_PATH`, which cannot help. It now says AppArmor is the cause and names the two fixes: an AppArmor profile for the browser, or the `kernel.apparmor_restrict_unprivileged_userns` sysctl. Inside a container (a seccomp filter on Lattice and on the container's first process), it names the container's seccomp profile instead: Docker's default profile is what blocks the sandbox there. Each render's warning gives the same remedy, and the other OFF cases each get their own. On macOS and Windows, where the sandbox is the platform's default, a render no longer prints that line as a warning.
