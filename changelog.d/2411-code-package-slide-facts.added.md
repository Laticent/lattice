- **Code packages get the slide's plain facts beside its HTML.** A package's `slide` now carries `facts`: the slide's classes and directives, its title, its content as blocks (headings, paragraphs, nested list items, tables with their captions, code, quotes, images), all of its text, and the palette token names every theme defines. Text is plain (`**Kickoff**` arrives as `Kickoff`, math as its TeX), and beside it each heading, paragraph and list item carries `runs`, which mark what the text loses: a code span as a value, a `{DONE}` pill as a state, bold, a link's address. A loose list item keeps each of its paragraphs. The running header and footer are not content; they are in the directives. `facts` is the stable input: a package that draws something new from the author's content (a Gantt chart from dates, a map from place names) reads it and never parses Lattice's markup. `slide.html` stays for packages that tweak the finished slide, and its markup may still change. The CLI and the Studio read the facts the same way, before the package runs, and the package gets them frozen.
- A code package's output no longer has to repeat every class the engine put on the slide (`content`, `form`). The door puts back any it leaves off, so a package that builds its section from the facts draws instead of failing with a note.
