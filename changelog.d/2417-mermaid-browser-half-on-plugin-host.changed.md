- **Mermaid's browser half runs on the plugin host.** The Studio, the Playground, the landing previews and the Stage load the diagram library as the Mermaid plugin's declared payload, which the runtime's plugin host fetches from beside `lattice-runtime.js` (`mermaid.min.js`, preloaded by the frame that needs it), instead of a URL each page threaded into every frame. The runtime can now also draw a fence patched into a live document without a rebuild (the docs site's frames still rebuild when a deck gains its first diagram). A library that fails to load hands every fence back to its source before the page's `load`, as before, and Mermaid's own on-load pass no longer paints its error graphic into an empty diagram slot.
- **Breaking:** a diagram fence's `<pre>` carries the plugin host's settle markup — `data-lattice-hydrate="mermaid"` and `data-lattice-settle` (`pending` · `hydrating` · `rendered` · `error` · `unavailable`, plus `data-lattice-final`) — instead of `data-mermaid-state` and `data-mermaid-final`. CSS or scripts that read the old attributes (a custom theme, an integration waiting on diagrams) should read the new ones; the old `rendering` state is now `hydrating`. A page that serves `lattice-runtime.js` and wants diagrams must now either serve `mermaid.min.js` beside it or write its own Mermaid `<script src>` before the runtime (the old shape, still honored); `buildSrcdoc` and the single-slide renderer no longer take a `mermaidUrl`. Exports are unchanged: the CLI's PDFs are byte-identical, and the Studio's PDF export of the diagram gallery is pixel-identical.
