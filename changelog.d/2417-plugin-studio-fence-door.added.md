- **A zip plugin can draw its fence in the Studio.** Import a plugin's `.zip` in the Library (it stays in this browser: never in a deck, a `.lattice` project or a backup), list it in the deck's `plugins:` front matter, and approve its code from the notice above the preview. The fence then draws in the preview and in Share → PDF, in a sandbox with no network, through the same door and the same rules as the CLI's (the 400-fence allowance, the output cap, the `lp-<name>` id and class namespace, no drawing on a slide a shipped pass rebuilds from its text). A plugin the deck does not list runs nothing. The Plugins tab lists installed plugins with Remove.
- **A plugin that returns a media element with no source no longer breaks Share → PDF.** An empty `<video>`, `<audio>`, or `<img>` / SVG `<image>` with no address is dropped from a plugin's output in both doors (a `data:` image stays); before, the Studio's PDF writer failed on it.
- **A plugin zip may not declare `render.exec`, `payload` or `vendor`.** The gate refuses them by rule (`refusePluginCode`), not by prose.
