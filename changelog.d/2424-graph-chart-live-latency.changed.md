- Typing in the Studio shows a graph chart's new text after one layout instead of three. On an 11-state machine the drawing now moves about 270 ms after a key instead of 1.3 s, and catches up 0.8–1.1 s after a burst instead of 1.6–2.3 s. The drawing that remains is the same as before.
- The layout kernel is about a third faster on both graph charts with byte-identical layouts: it skips boxes and lines a candidate's bounding box cannot reach, walks the boxes as an array, and reads a line's end loads once per line.
- A graph chart that wraps (the state chart) routes only the layouts that can still win: dagre's layout only when its ceiling could beat the grid, and often just the one grid it picks. The state chart's stress deck lays out in 533 ms instead of 1,152 ms (routing passes 77 → 30), with byte-identical layouts.
- While an author types, a graph chart that wraps keeps the rows it had: each keystroke lays out that one grid instead of searching every wrap again, so a key shows sooner (an 11-state state chart: 158–202 ms instead of 280–325 ms; the flowchart of the same machine: 193–214 ms instead of 230–241 ms) and the rows hold while typing (unless an edit leaves the grid unable to hold the shapes, or the direction changes). 300 ms after the last pinned draw lands, the chart searches once and takes its choice, so the drawing at rest still matches the export; a chart whose new content wants other rows reflows then, once.
