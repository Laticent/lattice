- **A code package's worker can no longer load a font, so a font load can't carry data out.** `new FontFace(name, 'url(…)').load()` and `self.fonts.load(…)` reached a loopback server from the worker in Playwright's Gecko build (Firefox 142), where the frame's content-security policy (`font-src data:`) did not hold, just as it had not for `EventSource`. Stock Firefox 156 applied the policy to both. `FontFace`, `FontFaceSet` and `self.fonts` are now removed with the worker's other network tools, so the wall no longer depends on the policy for them: both reach nothing in stock Chrome 154, Firefox 156 and Safari 26.6, and in Playwright's Chromium, Gecko and WebKit builds. A package that loaded a font in its worker now gets "FontFace is not a constructor"; the guide never offered that, and `kit.measure` still measures with the installed fonts.
- The worker's network tools are now removed from every prototype above its global, not only from the global. Chromium defines `fetch`, `importScripts` and `indexedDB` on `WorkerGlobalScope.prototype`, not on the global, so the old wall only shadowed them and `WorkerGlobalScope.prototype.fetch.call(self, …)` reached them (the policy still stopped the request). `navigator.storage` and `navigator.storageBuckets` go too, and the wall checks itself: a package does not load if any name survives.
