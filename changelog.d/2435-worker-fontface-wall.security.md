- **Closed a network path out of a code package's worker on Firefox: a font load.** `new FontFace(name, 'url(…)').load()` and `self.fonts.load(…)` reached a loopback server from the worker on Gecko, where the frame's content-security policy (`font-src data:`) did not hold, just as it had not for `EventSource`. `FontFace`, `FontFaceSet` and `self.fonts` are now removed with the worker's other network tools, so both reach nothing on Chromium, Gecko and WebKit. A package that loaded a font in its worker now gets "FontFace is not a constructor"; the guide never offered that, and `kit.measure` still measures with the installed fonts.
- The worker's network tools are now removed from every prototype above its global, not only from the global. Chromium defines `fetch`, `importScripts` and `indexedDB` on `WorkerGlobalScope.prototype`, not on the global, so the old wall only shadowed them and `WorkerGlobalScope.prototype.fetch.call(self, …)` reached them (the policy still stopped the request). `navigator.storage` and `navigator.storageBuckets` go too, and the wall checks itself: a package does not load if any name survives.
