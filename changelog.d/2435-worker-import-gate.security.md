- **A code package can no longer hold a dynamic `import()`.** `import()` is syntax, so the worker's wall, which removes names, could not take it away; it rested on the frame's content-security policy alone, and with no policy it reached a local server on Chromium, Gecko and WebKit. Lattice now parses a package's `transform.js` (with acorn, as the script the worker runs) and refuses one that holds an `import(…)` call when you add it, list it, render with it, and when the Studio imports it or runs it. The word in a string or a comment is fine. A transform that does not parse is refused too.
- **Nothing in a code package's worker turns a string into code.** `eval`, `Function` and the `constructor` of every kind of function now throw an `EvalError` when called (they still exist, so `Function.prototype` and `instanceof Function` keep working), `ShadowRealm` is gone, and `setTimeout` and `setInterval` throw when handed a string. Code built at run time therefore cannot bring an `import()` back. None of the shipped code packages used any of them. Measured with no content-security policy at all, the worker now reaches nothing in Playwright's Chromium, Firefox and WebKit builds or in stock Chrome 154, Firefox 156 and Safari 26.6.
- `acorn` is now a runtime dependency of the CLI (it was a development one).
