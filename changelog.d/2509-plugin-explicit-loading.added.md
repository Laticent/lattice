- Plugins load explicitly. A deck can name the plugins it needs in a front-matter import list, `plugins: [math, mermaid]`, and a slide class that requires a plugin (`math`, `diagram`, `scene`) loads it. Every shipped plugin stays on by default, so a deck with no `plugins:` key renders exactly as before, and listing a plugin that is already on changes nothing. The list only adds: no deck can switch a plugin off. In the engine and the CLI bake, using a plugin's syntax no longer decides whether the plugin loads; it decides only when its library loads and its bake runs, and `render()` reports `plugin/used-not-loaded` for a plugin a deck uses that nothing loaded.
- The Studio's deck settings have a **Plugins** tab. It shows each plugin, whether it is on for this deck and why (on by default, listed in this deck, or needed by a slide class), and its checkbox adds or removes the plugin in the deck's `plugins:` line, so the choice travels with the deck into every export.
- `lint:deck` warns `unknown-plugin` on a `plugins:` name no plugin has, and `render()` reports it as the diagnostic `plugin/unknown-plugin`. `createEngine({ plugins: { defaults } })` lets a host narrow the default set.
