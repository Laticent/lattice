- The Export-to-Marp bundle's two checks of a deck's HTML (the script strip and the forged-marker refusal) no longer miss everything after a front-matter value that opens a code fence. That line made the rest of the deck read as code to both, while Marp rendered it as live HTML.
- The Export-to-Marp bundle's `marp.config.cjs` no longer sets `html: true`. It lists the HTML a deck may carry (text, tables, images, video, `https:` frames, inline SVG with its gradients), and an engine plugin lets through only the bundle's own runtime tags. A tag not on the list shows as text, and no `<script>` of the deck's runs even if the export's strip missed it. The export prints any tag or attribute the list will refuse. Render a bundle with its own `npm run pdf`: `--html` replaces the list with "everything". 421 of the 422 shipped decks render the same; `design/forms.gallery.md` lost two stray lines its last slide carried.
- A `\href{javascript:…}` in a bundle's math no longer becomes a live link when marp-cli renders it. VS Code's preview still shows it as one (`followups.d/2578-p3-marp-bundle-math-links-in-vscode.md`).
