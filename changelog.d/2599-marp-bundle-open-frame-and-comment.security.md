- **Export-to-Marp keeps its runtime and its notes clean when a deck ends in markup left open.** A deck that ended in an unclosed `<iframe>` made the browser read the bundle's runtime `<script>` lines as the frame's text, so the runtime never loaded; the bundle engine now closes an open frame first. A deck that ended in an unclosed `<!--` ran on into the bundle's guard comment, so the guard text appeared in the speaker notes; the note is now cut at the guard. An open `<math>` (`</svg>` does not close MathML) and a nested `<svg>` each lost the runtime or the Mermaid tag too, and are closed the same way. A sweep of 47 hostile tails (open `<textarea>`, `<style>`, `<xmp>`, `<noscript>`, `<noembed>`, `<plaintext>`, `<title>`, nested `<svg>`/`<math>`/`<foreignObject>`, tables, `<template>`, `<select>`, `<form>`, `<object>`, `<embed>`, `<frameset>` and more, at the end of the deck and mid-deck) through real marp-cli and Chromium found no script run, no event-handler attribute, no `<base>` and no unlisted resource.
