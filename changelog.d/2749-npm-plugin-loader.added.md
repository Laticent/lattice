- `lattice packages fetch [dir]` downloads the npm plugins listed in a project's `lattice-plugins.json`. Each entry names an exact version and pins the bundle's SHA-256. The command reads the one bundle file out of the registry tarball and keeps it only at its pin. It never runs `npm install` and never runs the bundle. It then asks for your approval, naming the list, the package, the version and the hash. A deck that lists the plugin under `plugins:` draws it from that cache, in the locked sandbox page, with no network. An npm plugin is not approved, and does not run, where the OS sandbox reads OFF or cannot be determined. `lattice packages trust plugin/<name> [dir]` approves one later.
- An npm plugin bundle that holds an HTML-like comment (`<!--`, or `-->` at the start of a line) is refused. A browser reads one as a comment where the admission check did not.
- An npm plugin bundle whose bytes are not UTF-8 text is refused. Its approval and its render would otherwise hash different bytes, so it could never run.
