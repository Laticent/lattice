- **Added: slide metadata as one record in a comment.** A slide's settings can now be written as a record: `<!-- {layout=cards, footer="Q3 review"} -->`, or the long form `<!-- @meta{…} -->`. Field names are kebab-case (`focus-steps`, `background-color`); `layout`, `variant`, `universal` and `modifiers` build the slide's class, and a plugin register is a field too (`icon=bare`). A record sets its own slide; add `carry` for "from here on". A record writes exactly the `<section>` the directive comments it replaces write: all 354 example and gallery decks render byte for byte the same when every directive is rewritten as a record. Directive comments (`<!-- _class: cards -->`) still work; a later change in this line of work retires them, with a codemod.
- **Added: notes in a record, and a reader note.** Long text goes on `key: |` lines inside the same comment. `note` is the speaker note; the new `reader` field is a note for whoever opens the exported file: PDF note annotations, PowerPoint notes and the notes sidecar carry it as a paragraph labeled `Reader:` after the speaker note, and the HTML player keeps it as its own hidden channel. `--strip-notes` removes a record's `note` and keeps its `reader`; `--strip-say` removes its `say`. A comment cannot hold `-->`, so a note writes `--\>` (and `--!\>` for `--!>`).
- **Breaking:** a comment whose first line opens with `{` or `@meta{` is now a slide record, not a speaker note: `<!-- {TODO} check the numbers -->` used to be the slide's note and now reports `meta/record` and sets nothing. Write such a note without the leading brace, or put the brace on the line after `<!--`, which stays a note. None of the shipped decks has one.
- A record that does not read, sets a deck-only key (`theme`, `lang`, `size`), names an unknown field, or a comment written in the engine's internal form (`lat-meta`, `lat-note`, `lat-pane`) is reported in the render's diagnostics (`meta/record`, `meta/forged`) and applies nothing; it never falls through to the speaker note. `lint:deck` reports a record inside a list item or blockquote (`meta-not-own-line`), including one indented under a list item with no marker on its line.
- **Added for plugin authors: the `source` contribution** (spec/LPM.md §3.3, 0.13-draft): an embedded, in-tree plugin's pure transform of the deck at engine entry, before plugin admission. Additive under `api: 1`; a zip plugin may not declare it, so existing plugin approvals are unchanged.
- **Export to Marp keeps records working.** The Marp bundle (CLI and Studio) writes each record back as the directive comments Marp reads, quoting values Marp would read as YAML, with the speaker note as a plain comment and the reader note labeled `Reader:`. Checked with `@marp-team/marp-core` on the exported demo deck.
- **Fixed:** a speaker note reading `$100` in a Studio-shared HTML player no longer corrupts the slide markup (the note was injected with a replacement string, where `$1` is a backreference; the CLI had the same fix).
- **Fixed:** the Studio's code-package notice now offers a package used only inside a `_pane:` pane (its marker reader matched only the `pane:` alias).
