- **Changed: a record slide edits in the Studio as a directive slide does.** The "This slide" drawer edits a record in place (`<!-- {layout=cards, finish=ledger} -->`): a modifier joins it, a register word is written as its field (`head-left` becomes `headline=left`), and swapping the layout keeps `layout=` typed. The speaker note, say line and description editors read and write a record's `note`, `say` and `describe` fields. A key the slide does not set is now written as a record (`<!-- {footer=Q3} -->`), and Compose writes a pane as `<!-- {pane=bar} -->`, keeping a record marker's other fields.
- **Added: the host's registers as record fields.** `finish`, `headline`, `rule`, `eyebrow`, `spectrum`, `spectrum-edge`, `spectrum-card`, `spectrum-card-edge`, `spectrum-trim`, `lift`, `stamp`, `tone` and `corners` take the values their front-matter register takes, on one slide: `{finish=ledger}` is `_class: finish finish-ledger`, and a register's default asks for its documented restore word (`{lift=off}` is `flat`). The two render the same `<section>`.
- **Added: completion inside a record.** After `<!-- {` the editor offers the record's fields, and after `field=` its values: components for `layout`, that layout's variants for `variant`, the class grammar for `class`, a register's own words for the rest.
- **Added: the `meta-record` lint rule.** `lint:deck` reports what the engine drops from a record it reads: an unknown field, a value outside its register, braces or a quote that never close, a deck-only key, a repeated field. Each finding names the engine's code (`meta-unknown-key`, `meta-field-value`, `unterminated-record`, …).
- **Fixed:** the Studio's speaker-note editor no longer shows a record as the slide's note, and saving a note no longer deletes the slide's record.
- A plugin register named like a record field (`layout`, `note`, `pane`, `footer`) now fails plugin resolution even when the `meta` plugin is not among the plugins resolved.
