- The Studio's and the Playground's live previews no longer run function-plot or Mermaid in the page that holds your deck. Each figure is drawn in a sandboxed frame (`sandbox="allow-scripts"`, an opaque origin, no network) and the drawing comes back as sanitized markup. The two libraries are fetched and checked against their SHA-256 pins before a frame runs them. Only function-plot's frame may `eval`, because the library compiles expressions. The exports and the plain `.html` have no host page and load the libraries as before, and the Studio's Webpage bake frame draws in-page so its bytes stay the CLI's.
- A diagram's first draw in a fresh Studio page now takes about 1.0 s longer: a Mermaid frame costs about 0.8 s to start and a first draw used to share that cost with the preview's own start. Measured in headless Chromium on one deck with one diagram, two runs each: first draw 2341 / 2362 ms before, 3366 / 3351 ms after; a later edit 733 / 684 ms before, 827 / 728 ms after. A plot's first draw is at parity (1247 / 1355 ms before, 1292 / 1496 ms after).
- A flowchart's hover tooltip now takes the diagram's own palette (the rule in the diagram's sheet) in the Studio's previews, where the library's own tooltip showed a pale yellow. The click behavior is unchanged: a link opens, and a click callback stays off at `strict`, as before.
- A Mermaid error in a preview now keeps up to six lines of the library's message (the parse position and what was expected) where a frame would otherwise have cut it to its first line.
