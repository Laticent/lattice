- The Studio's and the Playground's live previews no longer run function-plot in the page that holds your deck. A plot is drawn in a sandboxed frame (`sandbox="allow-scripts"`, an opaque origin, no network) and the drawing comes back as sanitized markup. The library is fetched and checked against its SHA-256 pin before the frame runs it, and only that frame may `eval`, because the library compiles expressions. The exports and the plain `.html` have no host page and load the library as before, and the Studio's Webpage bake frame draws in-page so its bytes stay the CLI's. A plot's first draw is at parity with the in-page path (1247 / 1355 ms before, 1292 / 1496 ms after, headless Chromium).
- Mermaid in the Studio's and the Playground's live previews is drawn in a sandboxed frame too, and it is **faster** than drawing it in the page was. The frame loads Mermaid's own ES-module build by URL (a 28 KB core, then only the chunks a diagram type needs) instead of inlining its 3.1 MB single file, so the page no longer parses 3 MB of HTML or runs a 350 to 500 ms script task. Measured in a CPU trace of the real Studio, headless Chromium, three runs each, time from the editor change to the first diagram: 1779 ms in the page before, 1366 ms in the frame now (a plain prose deck is 885 ms); main-thread time 1652 ms before, 1257 ms now. The frame's policy names the one directory the modules load from and the engine's font folders, carries no `'unsafe-eval'`, and an import map's `integrity` pins the SHA-256 of every module, which a browser that supports it enforces (a changed module is refused). The ES modules are vendored beside the single file (`lib/plugins/mermaid/vendor/esm/`, pinned by tree hash, refreshed by `npm run vendor:plugins`) and staged under `frames/mermaid/`, which needs CORS: GitHub Pages sends it, the Cloudflare previews read `docs/public/_headers`, and the local servers are configured in `astro.config.mjs`.
- A flowchart's hover tooltip now takes the diagram's own palette (the rule in the diagram's sheet) in the Studio's previews, where the library's own tooltip showed a pale yellow. A link still opens and a click callback stays off at `strict`, as before.
- A Mermaid error in a preview now keeps up to six lines of the library's message (the parse position and what was expected), where a frame would otherwise have cut it to its first line.
