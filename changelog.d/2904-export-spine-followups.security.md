- **A deck's own script can no longer stand in for the CLI's slide camera.** The camera ran in the deck's JavaScript world and skipped loading its code when `LatticePdfCompose.captureSlide` already existed, so a deck that defined that global first was handed the export's picture reader and could replace every slide picture in a PNG set, PowerPoint or LibreOffice export. The camera now runs in an isolated world (a second JavaScript context over the same page, the one browser extensions use), and its file reader is bound to that world alone. A deck can still see a picture the camera has already read for one of its slides, as the PDF export already lets it. Every export's pictures are byte-identical to before.
- Two Studio exports started at once (a double click on PowerPoint and LibreOffice) no longer swap picture settings. The `images:` choice was held in one shared variable, so the export that started last decided every picture of both; each export now carries its own.
- A slide with no size (hidden, or not laid out) now stops its export with a named error instead of coming out as a blank 1 × 1 picture. The command line stops a PNG, image-set, PowerPoint or LibreOffice export and names the slide (a CSS rule that hides it, say); a PDF leaves the hidden slide out.
- An emoji drawn only by a pseudo-element (`h1::before { content: "🎉" }`, or the escape `"\1F389"`) now keeps its emoji font slice in the Studio's exports and in every picture the camera takes, instead of drawing in a fallback face. On the command line this covers CSS in the front matter's `style:` and a `--css` stylesheet, whose emoji used to bring no emoji font into the export at all.
- The slide camera no longer rewrites the word `body` or `html` inside a CSS string or comment: `content: " body "` drew as ` .__lc-body ` in PNG, PowerPoint, LibreOffice and the PDF's photo layer.
