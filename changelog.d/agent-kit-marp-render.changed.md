- The agent kit's render page now teaches a second route that does **not** move the deck: hand `marp-cli` the stylesheets with `--theme-set` and render the deck where it already sits. The page also names, for the first time, what Marp contributes and what Lattice contributes, the six things that make a deck Marp-renderable, and the three runtime `<script>` tags with the order they have to run in.
- It states where the assets come from — one `curl` of the published `dist-kits` tarball for everything including `fonts/`, a jsDelivr URL for the runtime scripts, and a warning that `raw.githubusercontent.com` serves JavaScript as `text/plain` with `nosniff`, so a `<script src>` pointing there is downloaded and never executed.
- Three asset rules, each measured by rendering the same deck both ways: `--theme-set` takes local paths only (a URL renders the deck in default Marp styling, silently), `fonts/` must sit beside the **output** file rather than the stylesheet, and the runtime scripts may be local or a CDN URL.
- The kit README said "the two runtime `<script>` tags" while every deck it ships emitted three. Both counts now derive from `RUNTIME_SCRIPT_SRCS`, the one list that names the runtime engines — the tag block is generated from it too, so the pair cannot desynchronise again.
