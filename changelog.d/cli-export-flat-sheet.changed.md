- The CLI export (PDF, PNG, HTML and `--player`) now ships the engine's flat stylesheet, the same one the Studio's Webpage player ships, instead of inlining `lattice.css` and the palette unpacked. A token that derives from another now follows each slide's own overrides, so a print slide's page number takes the print ink. Over every committed deck, that page number (`print-mode`, `finish-canvas-print-face`) is the only thing that renders differently.
- **Breaking:** in a CLI export, a deck's bare `section { --token: … }` override (front-matter `style:` or an in-body `<style>`) no longer beats a token the palette declares at `:root`, which is how Marp and every other Lattice host already behave. Write the override at `:root` (`:root { --accent: … }`), which keeps working, or on a class (`section.brand`).
- A `<section>` an author nests inside a slide is no longer styled as a slide in the CLI export. It used to pick up slide padding and chrome.
- An installed theme package that omits `@import 'lattice'` still renders on the layout sheet.
- The exported player's CSS prune now reads one-colon `:before`/`:after` (KaTeX's, and every rule in the Studio's minified sheet) as pseudo-elements, so it keeps those rules instead of dropping them or giving up on the prune.
- `tools/palette-sweep.js` re-themes a rendered export by swapping the whole deck sheet between `/* lattice:sheet-start size=… theme=… */` and `/* lattice:sheet-end */`, composed by the builder the CLI itself uses (`lib/export/cli-deck-sheet.js`), and refuses a render whose sheet that builder does not reproduce. The `/* lattice:palette-end */` sentinel is gone.
- The engine's comment stripper no longer reads a `/*` inside a CSS string as a comment. A custom layout sheet carrying `content: "/*"` lost every rule after it.
