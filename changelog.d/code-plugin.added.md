- A `code` plugin now renders every fenced block that no other plugin claims, on any slide. It loads highlight.js core plus only the grammars a deck's fences name (and the ones those embed, such as the JavaScript and CSS inside HTML), instead of the full 192-language build the engine used to load in every process. Every highlight.js language colors as the full build did, with one deliberate exception: an `http` block now looks for a JSON or XML body instead of guessing among all 192 languages, which fetched about 190 grammars in the Studio and colored a plain-text error body as EBNF. The `code` and `compare-code` slide classes now declare that they require it. A host that narrows the default plugins without it gets plain, uncolored code blocks.
- Fixed: `_focus: line N` and `_build` line stepping counted a multi-line comment or string as one line, so every later line was off by one, and they added an empty extra line at the end of each block. Line N is now source line N, matching what `lint:deck` counts.
- The Studio and Playground no longer bundle 36 highlight.js grammars up front. A deck fetches the grammars its fences name, plus the ones those embed, so an HTML fence still colors its `<script>` and `<style>`. A deck with no code fetches none. The Studio's ESM engine drops from 271 KB to 228 KB gzipped, and the classic Playground bundle from 498 KB to 454 KB.
- **Breaking:** the twelve `--hljs-*` theme tokens are renamed to role tokens: `--syntax-comment`, `--syntax-keyword`, `--syntax-builtin` (was `built_in`), `--syntax-number`, `--syntax-constant` (was `literal`), `--syntax-string`, `--syntax-entity` (was `title`), `--syntax-type`, `--syntax-variable`, `--syntax-parameter` (was `params`), `--syntax-markup` (was `tag`) and `--syntax-punctuation`. A theme that still sets `--hljs-*` falls back to the engine's default syntax colors, which can be unreadable on a light code panel, until it renames them; `lib/tokens/crosswalk.js` `flip()` does it mechanically, and the build rejects an old name in a theme file. The draft theme spec (`spec/THEME-1.0.md`) is amended to match.
- Every fenced code block now sits on the code panel, on any slide. Before, a fence on an ordinary content slide painted the panel's syntax colors straight onto the slide background, where the pale ones (functions, types, strings) were unreadable on a light theme. The panel also gains a faint inner edge (`--code-edge`), so it stays visible on dark themes whose slide background matches the panel. Escape sequences inside a string (`\n`, `\t`) now take the string's color instead of none.
- `diff` fences color added and removed lines with two new roles, `--syntax-inserted` and `--syntax-deleted`, on full-width tinted bands. Every theme declares its own pair, and the four accessibility themes use pairs that stay distinct under the condition each is built for.
- Configure a code block with a record on the line above it: `` `@code{title=src/load.ts, numbers, focus=4-5}` ``. The fields are `title=` (a file-name bar), `numbers` and `start=`, `focus=` and `mark=` (the `_focus: line` grammar, `3-5 9`), `diff` (each line's `+`/`-` marks it, and the rest is highlighted in the fence's own language), `wrap`, and `format`/`width=`/`dialect=` for the formatter. `code: numbers, wrap` in the front matter sets a deck-wide default. The record renders nothing; a plain caption span above a fence on a `code` or `compare-code` slide is still a caption. A slide's `_focus: line` and `_build: lines` work on a configured block too.
- `lint:deck` adds `code-record` (a record that does not read), `code-record-orphan` (a record with no fence after it) and `code-line-range` (a `focus=`, `mark=` or `_focus: line` past the end of its block, which silently marked nothing).
- `lattice fmt deck.md` pretty-prints a deck's code blocks in place, and **Format code blocks** in the Studio's command palette does the same as one undoable edit. Prettier formats JavaScript, TypeScript, JSON, CSS, SCSS, Less, HTML, Vue, Markdown, YAML and GraphQL, and with its plugins PHP, XML and Java; ruff formats Python; sql-formatter formats SQL (PostgreSQL unless a record says `dialect=`). A record's `format=off` keeps a block as written, `width=48` sets its line width, and `format` (or `code: format` for the deck) keeps a block formatted: the Studio formats it when you leave the editor. Formatting rewrites the source and the render never formats, so a formatter upgrade never changes a deck nobody re-formatted. Code a formatter cannot parse keeps its text and is reported. The formatters are optional dependencies, loaded per language; `lattice fmt --check` exits 1 when a block would change. `lint:deck` adds `code-format-unsupported` for a block that asks in a language no formatter reads.
- Export to Marp colors a shell command list the way Lattice does. marp-core's own bash grammar left `npm`, `docker`, `kubectl` and every flag uncolored. The bundle's `marp.config.cjs` now rebuilds bash on marp-core's highlight.js from Lattice's shell grammar. VS Code's Marp preview does not read that config, so it still shows stock bash.
- In Export to Marp, a fence on a plain slide now sits on the code panel too. Marp renders a fence as a bare `<pre>`, which the panel rule did not match.
- Export to Marp removes `@code{…}` record lines, which Marp would otherwise print as text above each block. Marp does not draw what a record asks for (line numbers, focus, marks, diff bands, a title, wrapping); the bundle's README lists it.
- Fixed: a receded code line (a block's `focus=`, or a slide's `_focus: line`) faded to about 1.5:1 against the code panel, and a receded comment to about 1.2:1, so the context lines read as blank. A receded line now drops to one quiet color held at 3:1 or better on every theme, and the build checks it.
- Copy buttons on a code block, off by default: `` `@code{copy}` `` on a block, or `code: copy` in the front matter for every block (`copy=off` opts one out). Two small buttons at the panel's top right copy the code as plain text, or as HTML with the theme's colors written inline, so it pastes colored into a document or an email. They appear only where someone reads the deck in a browser (the Studio preview, the Playground, Present, the exported webpage) and never in a PDF, PowerPoint, image or video export.
- The `code` and `compare-code` layouts follow the `cards:` register. A short block's panel now shrinks to its code and sits at the stage's middle instead of filling the slide with an empty panel; `cards: stretch` (or `_class: cards-stretch` on one slide) brings back the full-height panel, and `top` and `spread` work as on card layouts. The two panels of `compare-code` stay equal height.
