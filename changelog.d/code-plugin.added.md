- A `code` plugin now renders every fenced block that no other plugin claims, on any slide. It loads highlight.js core plus only the grammars a deck's fences name (and the ones those embed, such as the JavaScript and CSS inside HTML), instead of the full 192-language build the engine used to load in every process. Output is byte-identical: all 299 committed decks and fixtures render the same HTML, and every highlight.js language colors exactly as the full build did. The `code` and `compare-code` slide classes now declare that they require it. A host that narrows the default plugins without it gets plain, uncolored code blocks.
- Fixed: `_focus: line N` and `_build` line stepping counted a multi-line comment or string as one line, so every later line was off by one, and they added an empty extra line at the end of each block. Line N is now source line N, matching what `lint:deck` counts.
- The Studio and Playground no longer bundle 36 highlight.js grammars up front. A deck fetches the grammars its fences name, plus the ones those embed, so an HTML fence still colors its `<script>` and `<style>`. A deck with no code fetches none. The Studio's ESM engine drops from 271 KB to 228 KB gzipped, and the classic Playground bundle from 498 KB to 454 KB.
- **Breaking:** the twelve `--hljs-*` theme tokens are renamed to role tokens: `--syntax-comment`, `--syntax-keyword`, `--syntax-builtin` (was `built_in`), `--syntax-number`, `--syntax-constant` (was `literal`), `--syntax-string`, `--syntax-entity` (was `title`), `--syntax-type`, `--syntax-variable`, `--syntax-parameter` (was `params`), `--syntax-markup` (was `tag`) and `--syntax-punctuation`. A theme that sets `--hljs-*` stops coloring code until it renames them; `lib/tokens/crosswalk.js` `flip()` does it mechanically, and the build rejects an old name in a theme file. The draft theme spec (`spec/THEME-1.0.md`) is amended to match.
- Every fenced code block now sits on the code panel, on any slide. Before, a fence on an ordinary content slide painted the panel's syntax colors straight onto the slide background, where the pale ones (functions, types, strings) were unreadable on a light theme. The panel also gains a faint inner edge (`--code-edge`), so it stays visible on dark themes whose slide background matches the panel.
- `diff` fences color added and removed lines with two new roles, `--syntax-inserted` and `--syntax-deleted`, on full-width tinted bands. Every theme declares its own pair, and the four accessibility themes use pairs that stay distinct under the condition each is built for.
- Configure a code block with a record on the line above it: `` `@code{title=src/load.ts, numbers, focus=4-5}` ``. The fields are `title=` (a file-name bar), `numbers` and `start=`, `focus=` and `mark=` (the `_focus: line` grammar, `3-5 9`), `diff` (each line's `+`/`-` marks it, and the rest is highlighted in the fence's own language), `wrap`, and `format`/`width=`/`dialect=` for the formatter. `code: numbers, wrap` in the front matter sets a deck-wide default. The record renders nothing; a plain caption span above a fence on a `code` or `compare-code` slide is still a caption. A slide's `_focus: line` and `_build: lines` work on a configured block too.
- `lint:deck` adds `code-record` (a record that does not read), `code-record-orphan` (a record with no fence after it) and `code-line-range` (a `focus=`, `mark=` or `_focus: line` past the end of its block, which silently marked nothing).
- A `code-format` plugin pretty-prints a code block before it is colored, when its record asks (`` `@code{format, width=48}` ``) or the deck sets `code: format`. Prettier formats JavaScript, TypeScript, JSON, CSS, SCSS, Less, HTML, Vue, Markdown, YAML and GraphQL, and with its plugins PHP, XML and Java; ruff formats Python; sql-formatter formats SQL (`dialect=postgresql` and the rest). Every formatter is pinned to an exact version and loads only when a block in its language asks, so a deck that formats nothing pays nothing. Code a formatter cannot parse keeps its text, and the export says why. The CLI formats in its bake and the Studio above its render, through the same planner, so the preview shows what the export prints. `lint:deck` adds `code-format-unsupported` for a block that asks in a language no formatter reads.
- Export to Marp colors a shell command list the way Lattice does. marp-core's own bash grammar left `npm`, `docker`, `kubectl` and every flag uncolored. The bundle's `marp.config.cjs` now rebuilds bash on marp-core's highlight.js from Lattice's shell grammar. VS Code's Marp preview does not read that config, so it still shows stock bash.
- In Export to Marp, a fence on a plain slide now sits on the code panel too. Marp renders a fence as a bare `<pre>`, which the panel rule did not match.
- Export to Marp ships formatted blocks formatted, and removes `@code{…}` record lines, which Marp would otherwise print as text above each block. Marp does not draw what a record asks for (line numbers, focus, marks, diff bands, a title, wrapping); the bundle's README lists it.
- Fixed: a receded code line (a block's `focus=`, or a slide's `_focus: line`) faded to about 1.5:1 against the code panel, and a receded comment to about 1.2:1, so the context lines read as blank. A receded line now drops to one quiet color held at 3:1 or better on every theme, and the build checks it.
