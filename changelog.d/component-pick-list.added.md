- **Added `dist/docs/components.pick.md` — the component PICK surface: one line per component,
  the whole 61-component catalog in ~3k tokens.** `AGENTS.md` draws the line itself —
  "`components.json` is for *picking*; each component's `.docs.md` is for *authoring inside* the
  one you picked" — but the file it pointed at carried the authoring detail too, so choosing a
  component meant a **95k-token** read of slots, skeletons, effective variants and anti-pattern
  prose for all 61. HARD RULE #6 makes that read mandatory before every `_class:` slide, which
  made it the most-repeated read in the repo. Each row carries what a pick actually needs: bucket,
  the three axes, search tags, the **effective `capacity`** as `axis:sweet/soft/hard` with its
  escalation target, and a one-line purpose. One line per component also means `grep -i comparison`
  returns rows instead of a walk through a JSON document.
- **`components.json` is unchanged** — it stays the full machine record that the Studio's slide
  picker, deck export, the playground bundle and the LFM spec read, and it is still where
  `whenToUse` / `antiPatterns` / `slots` / `density` live. `AGENTS.md` and `CLAUDE.md` now route
  *picking* to the pick list and say plainly not to load the full catalog to choose; the detail
  you need after choosing is in the component's own `.docs.md`, where HARD RULE #6 already sends
  you. The pick list is generated by the same `tools/build-docs-portal.js` pass, so it rides the
  existing `docs:portal:check` staleness gate rather than adding a new one.
