- Compose draws a spark (`~{12 14 17, bar, c3}`) as the slide draws it and opens an editor on a tap: a grid of number boxes for a trend (or a value and a total for a ratio), the chart type, color, size, and the marks a line can carry (end dot, low and high, zero line, full width). The type chips offer only what the data takes (a trend takes line, area, bars, steps and win/loss; a ratio takes ring and bullet), and changing to a chart that draws no line clears the marks it cannot carry in the same write. Each change rewrites only the word it changed, so `~{12 14 17, bar, c3}` keeps its order and spelling, and an edit the engine would refuse writes nothing and says why. The "Insert spark" button on the slide bar adds a small rising line after the caret's word and opens its editor.
- `editSpark` in `lib/plugins/sparks/sparks.inline.js` is the matching writer, and `read` returns the spark's fields and the numbers as the author wrote them. A property test runs the writer over every readable spark in the shipped decks and galleries, and an edit lands only when the engine's own reader still reads the result as a spark.
- The pill editor takes an icon (`{DONE, icon=api}`): pick one from the icon grid, change it, or take it off. It also warns when a circle or diamond has a label too long for it, using the same check as the linter's `pill-shape-crowded`.
- On a phone, the active slide's bar (Undo, Redo, the insert buttons and Format) stays pinned fully on screen while a long slide scrolls under it, instead of riding half above the top edge with its buttons clipped. "Add a point" in the spark editor focuses the new number box with its value selected, so the next keystroke replaces it.
