- **Fixed: the `numbered` section stamp renders again — on every render path, and alongside `silent`.** It wrote the numeral onto `section::after`, the pseudo the engine reserves for the page number. Two owners took it back: the pagination mask (ours, and Marpit's own on the marp-vscode / marp-kit / export-to-Marp path) comments out any non-pagination `content` on that pseudo, so the counter was stripped from every browser surface while the emulator PDF kept it; and `silent` / `no-paginate` null the same pseudo at an equal specificity from a later file, so `divider silent numbered` — the sample shipped in the docs, the manifest and the gallery deck — rendered nothing anywhere. The numeral now rides the slide heading's `::after`, which neither can reach, and no longer suppresses the page number.
- **Changed: the stamp is one running count on dividers only, at the top-left edge, inked to be read.** Four changes to what it is, not just where it comes from:
  - **One counter.** `divider` and `divider light` share a single series, so a mid-deck light break reads 05 after 04 instead of restarting at 01. The `lat-divider-light` and `lat-closing` counters are gone.
  - **Breaking: `closing numbered` is removed.** A bookend is not a section, and a closing that announced itself as "01" was the clearest symptom of the three-counter design. `title` never took the modifier. Authors using `closing numbered` should drop the token; the class is inert, not an error.
  - **A masthead in the top band, set as display type** — a `--fs-hero` numeral in `--font-display` at weight 700 with no tracking, on the divider's own left margin, over a hairline that stops just past mid-canvas so the top-right corner stays free for a deck logo. It had been `--fs-h1` at `+0.04em` tracking, a heading size and a label idiom on a display mark. The two rungs follow the on-dark ramp's division of labour — `--on-dark-secondary` for the numeral, `--on-dark-ghost` for the rule, resetting to `--text-secondary` / `--border` on `divider light`. It is pinned to the SECTION rather than the heading, so it holds the same position on every divider however long the heading runs.
  - **A numbered divider suppresses its running header and footer.** The masthead owns the top band. The page number is untouched — it sits bottom-right. 
  - **The mark's band is reserved, so a long heading cannot climb into it.** Pinning the numeral was not enough: the headline block is flex-centered, so it grew in both directions and at four lines its top edge crossed the hairline while the numeral struck through the eyebrow. The slide now reserves the band with symmetric padding and centers the block with `safe center`, which falls back to `start` exactly when the block would overflow — the top edge stops at the band and the growth goes downward instead. Headings of one or two lines render byte-identically to before (the reservation is symmetric, so the midpoint does not move); a three-line heading shifts 6.14px down, and from there the block pins with a constant `2.5cqi` of clearance under the mark's painted edge. `divider light` and `divider qr` needed it too — measured without the band, a light divider carrying a lede sits at −15.2 and `divider numbered qr` at −85.3. And because the growth now runs toward the bottom, a heading long enough to fill the band eventually leaves the FRAME, which the engine already reports — `⚠ OVERFLOW` on export, a "Content clipped" tag on the slide, the runtime ring. The collision was silent before because an absolutely-positioned pseudo lying on the copy is an overlap, and the overflow probe measures spill past the frame.
  - **The value is an attribute now, not a CSS counter — because the counter was wrong on every Marp surface.** Marpit scopes a theme by prefixing its selectors, so `body { counter-reset }` became `section body { … }`, a `<body>` inside a section that matches nothing; and Marpit puts each slide in its own `<svg><foreignObject>`, so the sections are not siblings and each one implicitly started its own counter. The result, measured on real marp-cli 4.5.0: `01` on **every** divider in the deck. `lib/core/section-index.js` stamps `data-lat-section` from one kernel through two adapters — the engine's HTML and a live DOM — and the stylesheet reads `attr()`, which is the same mechanism Marpit's own pagination uses for the same reason. Where nothing stamps it the numeral does not draw at all: a blank mark is a gap an author can see, a wrong one is misinformation the room cannot check. Verified on real marp-cli 4.5.0 against a 13-slide deck with four dividers: `01/02/03/04` in **both** its HTML and its PDF output, the PDF's confirmed in the text layer, alongside the same series on our own export and packed browser path. The runtime stamps at boot as well as in the transform tail, which is what lets a consumer that captures the page early still get the number.
  - **Inked as content.** It was bound to `--on-dark-watermark`, the 12% decoration rung, under an `opacity` — 1.4:1, present but not readable. It now takes `--on-dark-secondary` (`--text-secondary` on `divider light`), the same rungs the eyebrow beside it uses, with no CSS opacity: measured 5.05:1 to 11.79:1 across the shipped palettes. It also moves from `--z-atmosphere` to `--z-content`.
