- A `fonts:` front-matter line and `--fonts` flag choose how much of each typeface an export carries: `exact` (only the characters shown), `used` (the whole face we ship, so edited text keeps every glyph; the default for text), `full`, or `system` (embed nothing). A word ending in `-emoji` sets the Noto Color Emoji font (default `exact`): `fonts: used exact-emoji`. The player, PDF and editable PowerPoint and LibreOffice files read it from one shared kernel (`lib/core/font-policy.js`). `unknown-fonts` warns on a word it does not know.
- The exported player now keeps the text faces whole by default (`used`) instead of cutting them to the shown characters, about 130 KB more on a small deck; `fonts: exact` restores the old size.
- `fonts: exact-emoji` (the default) cuts the player's emoji font to the emoji the deck uses, about 2 KB each instead of a 60 to 700 KB slice. It runs through a color build of HarfBuzz's subsetter (`lib/fonts/hb/hb-subset-color.wasm`), because the stock one drops the color tables and leaves emoji blank. A deck with five emoji went from a 3.1 MB player to 1.06 MB.
- `fonts: system` now keeps the engine's faces out of a Studio PDF too. The PDF writer both hosts run skips them, so words set in those faces stay in the page picture. Before, only the CLI honored it.
- The published `lattice` command now cuts the emoji font too (the color wasm is found through the package's `lib/`), and so do `--read` and `--fluid` pages; a character written as an entity (`&#x1F389;`) keeps its glyph, and an emoji in the `title:` gets its slice. The Studio's slide camera no longer inlines every emoji slice into every slide.
- The Studio's Pictures, Resolution and Fonts choices in the Share panel share one dropdown: each row has a title and a one-line explanation, the closed control stays one row tall, and the follow-the-deck row reads `Auto — <what it lands on>` like the other pickers.
- The plain `.html`, `--read` and `--fluid` exports now cut the KaTeX math faces to the glyphs the page uses, as the player already did. Text drawn only at view time falls back to another font.
- `fonts: system-emoji` now applies to PDFs, PowerPoint, LibreOffice and image exports as well as web pages: the picture draws its emoji with the computer that makes it (a machine with no emoji font draws boxes), in the command line and the Studio alike. `exact-emoji`, `used-emoji` and `full-emoji` still draw Noto Color Emoji in a picture, because no emoji font file rides in a PDF.
- Editable PowerPoint and LibreOffice exports take the `fonts:` text tiers and the `images:` choice: `exact` embeds just the characters the deck draws in each face (capitals from `text-transform` included), `used` and `full` the whole face, `system` none; `images: original` keeps every picture in the file lossless, and the quality now applies to cropped pictures too (default 90, was a fixed 92 for crops). The rules live in one place, `lib/core/font-policy.js` and `lib/core/image-policy.js`, and Calco (the Office writer) is handed finished fonts and plain instructions instead of holding any policy. Emoji are not embedded in these files: Noto Color Emoji is COLR v1, which LibreOffice draws blank, so the reader's own emoji font draws them.
