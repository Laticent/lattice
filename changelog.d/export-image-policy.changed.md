- **PDF, the offline player, PowerPoint and LibreOffice now shrink big pictures by default.** In the PDF and the player, a photo or screenshot over 150 KB is capped to 2560 px on its long edge and re-encoded as JPEG (quality 90), but only when that saves at least 30% (a format change) or 10% (a resize). A file that does not win, a transparent PNG, a GIF and an SVG are embedded exactly as before. On a 52-slide deck of 21 PNG screenshots (23.9 MB), the PDF went from 33.5 MB to 6.0 MB and the player from 66.6 MB to 12.6 MB; a deck of photos that were already tight JPEGs came out the same size.
- **A 4K deck now exports its PDF, PowerPoint and LibreOffice file at HD by default.** The design is the same at either size; the pixels are what make the file big (typically 1.6x for a PDF and 2x for PowerPoint, measured on a 52-slide photo deck). `--size 4k` on the command line, or **4K** in the export panel's new Resolution control (shown only for a 4K deck, with the cost), keeps 4K. The command line says when it lowered the size, and both hosts show the finished file's size. The deck's own `size:` is never rewritten.
- **One JPEG quality, 90, for every picture an export writes**: source photos, PowerPoint and LibreOffice slide pictures, and the PDF's slide-photo layer (it was 92 for the last two). The Studio and the command line read it from the same place.
- **You decide, per deck or per export.** `images: original` in the front matter, `--images original` on the command line, or **Original quality** in the Studio's Pictures control embeds every picture as added and keeps PowerPoint and LibreOffice slides as lossless PNG (13.7 MB becomes 26.3 MB on that deck). A number on the same line sets the JPEG quality, 1 to 100: `images: optimized 90` or `--images "optimized 90"`. The Studio and the command line read the same keys and run the same plan (`lib/core/image-policy.js`) with Chromium's JPEG encoder.
- `--size deck` renders on exactly the size the deck declares, never lowered. The repo's own gallery, golden, contrast and fit renders pass it, so a `size: 4k` deck is still measured at 4K while an author's export defaults to HD.
