- **The plain `.html` export now refuses scripts, frames and stylesheets from anywhere but itself.** A script running inside an exported deck could load another `<script src>`, an `<iframe>`, a CSS `@import` or `<link rel=stylesheet>`, or a prefetch from any host; the export's policy now carries `default-src`, `script-src`, `style-src` and `frame-src` limited to the file itself, inline content, `data:` and `blob:`. Measured on real exports in Chromium, WebKit and Firefox: those five loads stop reaching a server, and five decks (KaTeX, Mermaid, function-plot, charts) render with no policy violation and identical screenshots. Navigation, `window.open`, WebRTC, a meta refresh and `target=_blank` links stay possible for a running script in every export, because no content-security directive covers them; that is accepted in the npm-plugin threat model note (§5.4). (`lib/core/subresource-csp.mjs`, `lattice.js`)
