- **Photos no longer carry their metadata out of an export.** A PDF, a self-contained player (`--player`) and an `export:marp` bundle used to embed a photo's own file as it was whenever the image policy did not re-encode it, so a camera JPEG's location, camera name and comments, or a PNG's text chunks, went out with the deck. Every photo now passes through the same cleaner the Studio's Library and the `.lattice` writer use: the metadata is removed and the pixels stay exactly as they were. A photo that was already clean, which includes every photo from the Studio's Library, comes out byte for byte, so only decks whose photos carried metadata export different bytes. A file the cleaner cannot read is never shipped as it is: the PDF keeps it in the slide's picture, the player shows the drawn stand-in, and the Marp bundle leaves it out, each with a note. One exception remains, pending the owner's decision: a photo pasted into the Markdown itself as `data:` text rides verbatim wherever the deck's source travels (the player's embedded source, a `.lattice` file's `deck.md`, `--embed-source`, the Marp bundle's `deck.md`), metadata included.
- **The player cleans every picture a browser draws, and the pictures inside an SVG.** A `data:` picture written as `image/jpg`, in upper case, with a `;name=` parameter, wrapped across lines or percent-encoded used to ship with its metadata, and so did a JPEG inside an SVG, in the player and in an `export:marp` bundle. Each now meets the same cleaner, decided by the file's own bytes; the SVG around it is otherwise unchanged. An address spelled with a CSS escape (`data\3a image/…`) or, inside an SVG, an XML character reference (`data&#58;image/…`) is read the way the browser reads it and cleaned too, and the drawn stand-in for a picture the cleaner cannot read no longer breaks a single-quoted SVG attribute or CSS rule.
