- **The Studio and the command line now photograph a slide with the same code, so the same format comes out the same from either.** Before, the command line took a native Chrome screenshot and the Studio redrew the slide through the html-to-image library (which shrinks every font by up to 1px and mis-drew some backgrounds). On a 52-slide deck, all 52 slides differed between the two tools, the Studio's PNG set was 52% larger, and a topic slide's bottom shelf was missing from the Studio. The shared camera (`lib/core/slide-camera.mjs`) lays the slide out again with the page's own stylesheet instead of copying styles. Measured on that deck against native Chrome, at most 0.0065% of pixels differ by more than 8 levels (html-to-image: 4.3% on average); across tools, the PNG set, PowerPoint, LibreOffice and PDF pictures differ by at most 0.14% of pixels on the worst slide, and file sizes agree to 2 decimals (PNG set 25.91 MB from both).
- **PowerPoint, LibreOffice and PNG pictures now show the slide as the live preview does**, in both tools: the finish glow and a topic slide's lighter shelf are kept. The Studio used to flatten them. The PDF's photo layer keeps the flat face, because PDF viewers such as poppler draw soft finishes badly.
- **One PNG encoder.** PNGs from both tools are written by the same encoder, with per-row filtering. The browser's own encoder wrote files about 40% larger (the 52-slide deck's PNG set zip: 39.8 MB with the browser's, 28.2 MB with this one; the Studio used to write 39 MB).
