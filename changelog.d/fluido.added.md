- **Added: `@laticent/fluido`, the library that decides how a slide fits its box.** Every surface that splits a slide (the command-line export, the Playground and the Studio) now asks one pure, dependency-free core which slides divide, on which seam, and how many pages each becomes, including the budget cut that breaks one long code block into runs. No deck's output changes: 402 decks at three sizes split byte for byte as before. A slide whose split would produce more than 64 pages, by any route (a plain cut, a component's own recipe, or a long code block cut into runs), now stays one page and is marked instead; the longest run in any shipped deck is 41 pages. Fluido has a page on the Libraries site with a live demo.
