- **A deck that merely MENTIONS a `<section>` tag no longer loses Form.** The shared section walker scanned for the literal string `<section`, so one HTML comment quoting `<section class="title">` opened a phantom section that never balanced — and every slide after it went unstamped: no `data-form`, no `data-frame`, no `form` class, no progress rail, no watermark (measured: 0 of 3 slides on a real render). The walker now runs on the same tokenizer the rest of the engine uses, so a comment, a closed `<style>`/`<script>` block and a quoted attribute are text, exactly as a browser reads them. This also removes a real split between the render paths — the DOM twin walks a parse and never had the bug, so the same deck used to get two different answers depending on which path built it.
- **An apostrophe in an unquoted HTML attribute no longer eats the rest of the deck.** The tag scanner treated every `'` and `"` inside a tag as a value delimiter, so `<div data-tip=it's>` — or any unbalanced quote, such as `<p title=5">` — opened a value that never closed, and everything after it became invisible to the scanner. A quote now opens a value only where one can start, directly after `=`, which is what a browser does. This is the same kernel `findTopLevelH2` uses to locate a slide's title, so the masthead band was also going missing on those decks.
- **A sentence mentioning a `<style>` tag no longer blanks the deck.** An unclosed rawtext element was read as text all the way to end of file — a browser's rule, and catastrophic here: a deck stamped 0 of 3 slides because one line of prose named the tag. Rawtext is now skipped only when it actually closes.
- **`<sectionfoo>` is no longer treated as a `<section>`**, and a `>` inside a quoted attribute no longer ends the open tag early (`<section title="a>b" class="x">` now reports its class).
- **The `class` attribute is found by walking attributes, not by matching a substring.** A slide whose other attribute's value happened to contain ` class='…'` had that text read as its class and rewritten in place — tearing the neighboring value open into bogus attributes while the real class never got `form`, so the slide silently lost its chrome. A single-quoted `class='…'` is now rewritten rather than joined by a second `class` attribute, and a `$&` in a class value is no longer treated as a replacement pattern.
- **An uppercase `<SECTION>` is stamped or left alone as a whole, never half of each.** The walker reads tag names case-insensitively, as HTML defines them, but the Form stamp did not — so such a slide came out carrying the `form` chrome class with no `data-frame` at all, the exact half-stamped state the frame-identity invariant forbids.


- **The render path now says so when a deck still carries a retired Form opt-out.** `form: off`, a deck-wide `class: no-form` and a slide's `no-form` all SUPPRESSED chrome, so a deck carrying one renders differently the moment it is built against a current engine — the masthead band, the meta bay and the progress rail come back. That used to happen with a successful exit code and no other sign; `lattice` now names each shape on stderr, with the slide number and where to get the fix. The render still succeeds — we warn and coach, we never refuse an author's deck. Inert shapes (`form: standard`, a bare `form` token) stay silent, because a warning on a deck that renders identically is what teaches people to ignore warnings.
