- `npm run gotchas:index` and `build:check` now refuse a gotcha whose index row exceeds 280 characters, naming the entry. The heading is billed twice — once as the link label, once slugged as the anchor — and paid on every read of `engineering/gotchas.md`, so the cap bounds what one new gotcha can add to a block that is already 9,409 tokens. It is a ratchet pinned just above today's widest row, not a target: the live corpus passes unchanged.
- The topic filename is deliberately not billed. It is shared by every entry under the topic, so counting it would let a topic rename and a near-cap new entry each pass alone while the second to merge failed for the other's change.
