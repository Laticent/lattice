- **Inline sparks.** A `~{…}` in inline code now renders as a word-sized chart that sits wherever inline code can go: a `kpi` line, a table cell, a `big-number` caption, a sentence. `` `~{12 14 13 17 21}` `` draws a line; `:area`, `:bar`, `:step` and `:winloss` draw the same series other ways; `` `~{72%}` `` draws a ring and `` `~{72/80}:bullet` `` a bar against a target. `:sm` / `:lg` / `:fill` size it, `:c1`–`:c12` color it, `:end` / `:minmax` mark values, `:zero` starts a line at zero. Every spark sits in a squared 3:2 frame by default; `:bare`, `:outline` and `:rounded` change it for one spark, a `spark-*` class for one slide, and the new `spark:` front-matter register (`spark: bare`, `spark: outline rounded`) for the whole deck. A span that doesn't parse stays code, and `lint:deck` warns with the reason (`spark-literal`). In the Studio, typing `` `~ `` offers starter sparks and `:` after the brace offers the modifiers; a spark measured too big for where it landed (past its space, or more than 1.5 lines tall) gets a `spark-too-big` warning with a one-click fix to the size that fits. See the docs site's new **Sparks** guide (`/guides/sparks/`), `lib/base/base.docs.md` § Inline sparks, and `examples/inline-sparks.md`.
