- **Inline sparks.** A `~{…}` in inline code now renders as a word-sized chart that sits wherever inline code can go: a `kpi` line, a table cell, a `big-number` caption, a sentence. `` `~{12 14 13 17 21}` `` draws a line; `:area`, `:bar`, `:step` and `:winloss` draw the same series other ways; `` `~{72%}` `` draws a ring and `` `~{72/80}:bullet` `` a bar against a target. `:sm` / `:lg` / `:fill` size it, `:c1`–`:c12` color it, `:end` / `:minmax` mark values, `:zero` starts a line at zero. Every spark sits in a squared 3:2 frame by default. A **look** decides how its one color is spent across the tile, the edge and the marks: `:pigment` (the default, the color fills the tile), `:etching` (a clear tile, the color is the line) and `:tone` (one hue stepped by value), the same three finishes Lattice's charts use, drawing from the chart color cycle so a spark and a chart show a slot in the same hue. A spark that names no color is `:c1`. `:bare` and `:rounded` change the frame and corners. Each is set for one spark, for one slide with a `spark-*` class, or for the whole deck with the new `spark:` front-matter register (`spark: bare`, `spark: etching rounded`). A span that doesn't parse stays code, and `lint:deck` warns with the reason (`spark-literal`). In the Studio, typing `` `~ `` offers starter sparks and `:` after the brace offers the next step only (a type, then a size, then a color …), limited to what the spark can take — and pills now complete the same way, a shape, then a color, then a size; a spark measured too big for where it landed (past its space, or more than 1.5 lines tall) gets a `spark-too-big` warning with a one-click fix to the size that fits. See the docs site's new **Sparks** guide, under a new **Inline elements** sidebar group (`/guides/inline/sparks/`), `lib/base/base.docs.md` § Inline sparks, and `examples/inline-sparks.md`.
