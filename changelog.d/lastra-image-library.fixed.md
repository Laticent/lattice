- **One image library, `@laticent/lastra`, now reads, cleans, resizes and encodes every picture an export or the Studio handles.** Lattice had four header readers, three EXIF orientation parsers and a metadata scrubber only the Studio could use; each is one function in `docs/src/lib/lastra/` now, with no dependencies, the same in Node, a browser and a worker. Exports keep their bytes on the galleries and on a photo deck of PNG, JPEG, turned JPEG and transparent PNG pictures (a PowerPoint's own run-time stamp aside, which never followed `SOURCE_DATE_EPOCH`).
- **A photo's turn is read the way the browsers paint it, on the files the old readers disagreed on.** A JPEG whose EXIF block sits after its frame header (every engine turns it) is now kept upright in the PDF and sized upright in the image layout; a second EXIF block, an orientation outside 1 to 8, and a TIFF block with the wrong magic number no longer turn a picture no browser turns; junk or fill bytes between JPEG segments no longer hide a picture's size from the export's recode. A PNG whose `eXIf` chunk turns it (Chromium and Firefox apply it) is no longer re-encoded squeezed into its stored box.
- **A file whose first bytes only resemble a PNG, JPEG or GIF, and that no browser decodes, is no longer taken for one** by the PDF writer or the image layout's sizing; both now read the full signature, as the browsers do. The image layout also sizes an AVIF photo now, where it used to fall back to its plain composition.
