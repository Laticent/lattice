- The Library's Images tab now opens a detail view for each photo: the picture large, with its description, credit, date taken and name editable. The description shows on the card, and the chat reads it too.
- Renaming a photo keeps its old name as an alias, so `asset:<old-name>` in a deck keeps showing the same photo with no deck edited. Names and aliases share one namespace, so a new upload cannot take a name that is an alias of another photo. Removing an alias frees the name.
- The delete warning on a photo now counts decks that still write one of its old names.
- A workspace backup now carries each photo's description, credit, date taken and old names, and a restore puts them back. An older backup without them still restores. An old name that another photo already holds is dropped on restore instead of refusing the photo.
- A description keeps the quotes you type. The chat still gets a cleaned copy of it, so a quote mark cannot break out of its prompt. Date taken is a date picker.
- A photo whose name is only an old name on this device no longer makes a restore or an upload fail with "delete it first": it is renamed on clash (or reused when the bytes match), and the decks a restore wrote are pointed at the right photo.
- A photo keeps at most 20 old names. A rename past that is refused.
- A Library photo's description now fills an empty alt on its image in a deck: `![](asset:roof)` is announced as "The team on the roof" in the preview, the exported page and a collage's lightbox caption and narration, and it updates when you edit the description. An alt you write yourself is never replaced, and a deck with no described photos exports the same bytes as before.
- A photo's own file is read when you add it: the artist or copyright becomes the credit, the date taken fills in, and a description from the file's XMP, IPTC or EXIF is offered in the photo's detail view under "From the file" with a **Use as description** button. A camera's default text ("SONY DSC", "IMG_2041") is not offered. A photo that carried a location says so there; the location itself is removed from the stored photo and kept nowhere.
- Saving a photo's name and details together is one step: a refused name leaves the details unsaved too, and Enter in a field saves.
- A photo's detail view lists its old names with how many decks still write each, and **Use new name** rewrites those decks to the current name. Each deck gets a Version history entry first, and a code sample that mentions the old name is left as written.
- **Suggest** in a photo's detail view asks the model you connected in Setup for a one-sentence description of that photo, and puts it in the Description field for you to edit. It sends a small thumbnail only when you press it, to your own OpenRouter account, and saves nothing until you press Save. With no model connected, or a model that cannot read images, it says so instead of doing nothing.
- The photo detail view is fully keyboard-driven: Enter on a card opens it, Tab stays inside, Enter in a field saves, and Escape closes it and returns focus to the card.
- A photo's description is never read as a slide directive: a description such as "bg contain" stays alt text.
- Reading a photo's own details is safe against crafted files, including a packet built to freeze the page, and a file's text is cleaned the same way text you type is.
- **Use new name** reports honestly when the browser has no room to save: it rewrites nothing it cannot undo, and says how many decks were updated.
- **Use new name** reads markdown the way the renderer does: a list item, heading or quote ends an inline code span, an HTML `<pre>` block runs to its closing tag, and a code fence inside a list item ends with the item, so the count of decks and the rewrite agree with what a slide really shows. A very long block no longer crashes the detail view.
- A description keeps a family emoji, a flag and a Persian word's joiner when it is saved, while hidden-text characters are still removed. A **Suggest** answer from a cancelled visit can no longer overwrite what you typed after reopening the same photo.
- **Use new name** now asks the same markdown parser the slides render with where code, tables, lists and quotes are, instead of guessing, so the count of decks that still use an old name is exactly what a slide shows. Every place the engine resolves a photo name follows the rename (a video poster, a background directive, an inline image tag); only code is left alone. A flag emoji and a family emoji survive a description; hidden text made of invisible characters does not.
