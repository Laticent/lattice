- The Studio Library has an **Images** tab. Add photos from your camera roll, camera or files (on Android and iOS the picker opens natively), or drop them on the panel. Each image can belong to **all decks** or to **this deck** only, and moves between the two without renaming. JPEG and HEIC photos are resized to a 2560 px long edge and re-encoded, which also removes their embedded location. Photos are included in workspace backups and come back on restore: a restore never deletes or overwrites a photo already on the device, a photo it already holds is reused, and a different one under a taken name comes back under a new name with the restored decks updated to match. A file's bytes, not its extension, decide how it is treated, so a JPEG renamed `.png` still loses its location. PNG, WebP and GIF keep their pixels but lose embedded EXIF, XMP and comment blocks, and AVIF is converted to JPEG, so no photo's location rides into an export. In a browser that refuses to store files (Safari in a private window), the Library keeps the photo as raw bytes instead of failing, and says so if it cannot store it at all. Adding a photo whose name is taken keeps the old one and says which name the new one took. Deleting a photo that decks use, or a deck that owns photos, asks first. Deleting a deck deletes the photos kept to that deck only, and the Workspace storage line now counts photos by their size.
- A deck can show a Library photo by name: `![](asset:team-photo)`, `![bg](asset:hero)`, or in a `collage` photo list. The name is the one the Images tab shows on the card. The reference works in the live preview and the Present overlay; the Library card counts the decks that use it. A photo that was deleted, or that belongs to another deck, shows the drawn missing-image stand-in instead of a broken picture. PDF, PowerPoint, image-set and webpage exports carry the photo as pixels, never as a link that dies with the tab. Markdown, Marp and `.lattice` exports keep the reference as written. The CLI keeps it too, because a Library lives in the browser.
- The Studio editor completes Library photos. Typing inside the parentheses of any image (`![alt](`, `![bg](`) offers `asset:<name>` for the photos the open deck can see, with their size and whether they are kept to this deck. On a `collage` slide, a bare list item (`- `, then a letter or Ctrl-Space) offers whole `![Alt](asset:name)` lines with the alt text selected so you can replace it. The shelf is read on first use, so a deck that never names a photo pays nothing.
