- Importing a plugin clears the editor's `unknown-plugin` warning on a deck that already listed it, and removing a plugin brings it back, without a keystroke. The editor's lint and the Coach read the plugin names through a shared array and re-ran only on an edit, so a phone user who never typed kept a stale warning beside a plugin that Deck settings showed as installed.
- In the docked Library the five section pills fit one row (the last used to wrap alone).
- The notice that asks to run a plugin's code now says the same thing every time. When the code is not approved the button reads **Approve**, whether or not the deck lists the plugin (it used to read "Run it" in one case and "Approve" in the other), and approving is what lets it run. A plugin you approved earlier and then unlisted is offered **Add to deck**, with no second consent wording, since the approval stays with the code. The Library card reads "Not approved yet" and says it will ask when a deck uses the plugin.
- In the Studio preview, a plugin the deck lists but this browser has not approved yet now shows the same drawn placeholder card an unlisted plugin gets, saying "Plugin block · not approved in this browser" (and the same small chip for an inline `@kind{…}` span). It used to show the plain code block with a note under it, so the two states looked unrelated. The block's own text is no longer shown while nothing runs.
- The strip that asks you to approve a plugin's code (and the one that offers to add a plugin to the deck) now flashes its background twice and pulses the button's ring when it appears, then settles. It is a short highlight flash, not a loop, and it is off when the device asks for reduced motion.
