- A palette's parent is now DISCOVERED from one place. `themes/<name>.manifest.json` declares `extends`; the CLI, the docs Playground and the Export-to-Marp bundler walk that graph through the shared `themeChain()` instead of each re-deriving it with its own `@import` regex. The `@import 'parent'` line stays in the CSS — Marp has no manifest, and it is also still what splices the parent into the composed stylesheet at render time — and `check:ownership` fails if it disagrees with the manifest.
- Fixed: the engine's composed stylesheet was wrong on the CLI path for every `-dark` theme. The emulator registered only the leaf palette, so its `@import 'indaco'` had nothing to resolve against and `render().css` came back as ~2 KB of scaffold instead of the full ~768 KB sheet. Exported PDFs were unaffected (the CLI inlines its own flattened stylesheet), but any consumer calling the engine's composed output from a CLI-shaped setup got an unstyled deck. The whole chain is registered now.
- Fixed: three theme-import scanners had drifted apart, and the emulator's required whitespace after `@import` — so a minified `@import"indaco"` would have lost its parent there while resolving correctly elsewhere. Latent rather than live (the CLI only reads source-form themes), but the fix had reached one copy and not the others. The `check:ownership` theme gate carried the same `\s+` form and now reads the minified shape correctly too.
- Removed: `themeImportNames()` from the docs theme fetcher and the emulator's private palette flattener, both replaced by the declared chain — verified byte-for-byte identical to the flattener's output across all 32 palettes.
