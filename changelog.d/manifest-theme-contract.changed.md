- A palette's parent is now resolved from one place. `themes/<name>.manifest.json` declares `extends`; every Lattice path — the engine, the CLI, the docs Playground, the Export-to-Marp bundler — walks that graph through the shared `themeChain()` instead of re-deriving it by scanning `@import` out of the stylesheet. The `@import 'parent'` line stays in the CSS because Marp has no manifest and must learn the graph from the sheet, and a new `check:ownership` gate fails if the two ever disagree.
- Fixed: four separate `@import` scanners had drifted apart. The emulator's required whitespace after `@import`, so a minified `@import"indaco"` silently lost its parent there while resolving correctly in the engine and the browser — the engine's copy carried a fix for exactly that case which the others never received.
- Fixed: the engine's composed stylesheet was wrong on the CLI path for every `-dark` theme. The emulator registered only the leaf palette, so `@import 'indaco'` had nothing to resolve against and `render().css` came back as ~2 KB of scaffold instead of the full ~768 KB sheet. Exported PDFs were unaffected (the CLI inlines its own flattened stylesheet), but any consumer calling the engine's composed output from a CLI-shaped setup got an unstyled deck. The whole chain is registered now.
- Removed: `themeImportNames()` from the docs theme fetcher, and the emulator's private palette flattener. Both are replaced by the declared chain, which was verified byte-for-byte identical to the flattener's output across all 32 palettes.
