- **Breaking:** every on/off a deck or a slide can set is spelled one way: `no-X` turns it off and `with-X` turns it back on for one slide. The old spellings no longer do anything, and `lint:deck` (and the Studio) rewrite each in place: `callout-off`/`-on` → `no-callout`/`with-callout`, `motion-off`/`-on` → `no-motion`/`with-motion`, `spectrum-off`/`-on` → `no-spectrum`/`with-spectrum`, `spectrum-edge-off` → `no-spectrum-edge`, `spectrum-card-off`/`spectrum-card` → `no-spectrum-card`/`with-spectrum-card`, `spectrum-trim-off`/`spectrum-trim` → `no-spectrum-trim`/`with-spectrum-trim`, `row-label` → `with-row-label`, `no-rule` (the pane spine) → `no-spine`, `rule-none` (the heading rule) → `no-heading-rule`, `finish-none` → `no-finish`, `backdrop-none` → `no-backdrop`, `treatment-none` → `no-treatment`, and `tag-none` / `tag: none` → `tag-bare` / `tag: bare`. Front-matter settings keep their plain words (`motion: off`, `spectrum: off`, `rule: none`).
- **Breaking:** a slide's `with-X` now wins over a `no-X` everywhere, including a deck-wide `class: no-X`. A slide that carried both used to lose the switch for `motion`, `callout` and the table row label.
- New `with-progress`, `with-header`, `with-footer`, `with-logo` and `with-note` bring the section rail, header, footer, logo or below-note back on one slide over a deck-wide `no-X` or over `silent`. `silent` keeps hiding the header, footer, page number and section rail; any one comes back with its own `with-X`. The Studio's Chrome tab shows what each slide actually shows and writes the right `no-X` or `with-X`.
- A deck-wide `class: no-row-label` now reaches every table, a deck-wide `class: no-period` now strips heading periods, and a deck-wide `class: no-spine` now removes the pane spine; all three used to be silently ignored on the engine path. `with-spine` now brings the spine back on one slide.
- `no-period` no longer trims an ellipsis: a heading that ends `...` keeps its dots.
- In an Export-to-Marp bundle, `no-pagination`, `silent` and `with-pagination` now set the page number, and `no-period` / `with-period` now set the heading period. Marp's own stylesheet processing removed the rule that hid the page number, so it always showed, and the heading period was never applied. A deck-wide `class:` now also reaches the page numbers of slides that set their own `_class`.
- New reference page, Switches, lists every switch.
- **Breaking:** an Export-to-Marp bundle keeps Lattice's deck-wide settings (`class:`, `color-mode:`, `finish:`, `logo:`, …) in ONE settings block directly under the front matter, instead of a hidden copy at the end of the file. Editing the deck's settings after export used to do nothing for every key Marp does not read, and only half of `class: no-progress` landed: Marp drops a deck class on any slide with its own `_class`, so the section rail vanished from some slides and stayed on the rest. The block is read as you edit it in marp-cli, the VS Code preview (unsaved edits included) and VS Code's Export command, and a deck `class:` reaches every slide. A `class:` written in the front matter instead still works, in marp-cli at once and in the VS Code preview once saved. Re-exporting a bundle, or rendering its deck with Lattice, folds the block back into the front matter.
- An exported bundle always says `marp: true`. A deck with front matter but no `marp: true` exported a bundle that VS Code opened as plain Markdown rather than as slides.
