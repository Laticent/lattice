- **Breaking:** an Export-to-Marp bundle keeps Lattice's deck-wide settings (`class:`, `color-mode:`, `finish:`, `logo:`, …) in ONE settings block directly under the front matter, instead of a hidden copy at the end of the file. Editing the deck's settings after export used to do nothing for every key Marp does not read, and only half of `class: no-progress` landed: Marp drops a deck class on any slide with its own `_class`, so the section rail vanished from some slides and stayed on the rest. The block is read as you edit it in marp-cli, the VS Code preview (unsaved edits included) and VS Code's Export command, and a deck `class:` reaches every slide. A `class:` written in the front matter instead still works, in marp-cli at once and in the VS Code preview once saved. Re-exporting a bundle, or rendering its deck with Lattice, folds the block back into the front matter.
- An exported bundle always says `marp: true`. A deck with front matter but no `marp: true` exported a bundle that VS Code opened as plain Markdown rather than as slides.
