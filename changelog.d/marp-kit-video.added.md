- A `@video{…}` record now draws in a deck written in Marp, the copy-and-go kit's or a record typed into an Export-to-Marp bundle: the same poster figure and `video` card Lattice draws, in `marp --pdf`, in a `marp --html` file, and in the VS Code preview at the *Disable* security level. It used to print as a line of code. The address comes only from your Markdown (marp-cli reads it as it parses; VS Code reads the saved file), so a record you have just typed in VS Code draws when you save.
- The kit and the Export-to-Marp bundle now tell you to run one exact marp-cli version, 4.5.1, the one Lattice's CI renders with, instead of a `^4.3.1` range that resolved to versions nothing had rendered. The bundle README's `npx` line names the same version.
- The kit README says what its settings allow (raw HTML, local files, and the VS Code preview at *Disable*), and that they apply to every deck in the folder.
- The kit's readable `lattice-runtime.js` no longer carries its 8.5 MB DevTools source map (the file drops from 11 MB to 2.7 MB), and NOTICE.md names the repository the kit's engine files are built from.
- The kit's sample deck states the current layout count (79) and what a render loads (9 MB), and a test now holds both to the catalog and the build. Its "what renders where" slide marks charts and diagrams in the VS Code preview as working once the preview runs scripts, which is what a real VS Code shows.
- Typing in the VS Code preview no longer blanks a diagram or leaves a chart unbuilt on every keystroke: the runtime now lays the slides out in the same task as the preview's re-render, so Mermaid finds its cached drawing (0 frames with a missing diagram or chart, from 25 and 34, typing on those slides in a real VS Code).
