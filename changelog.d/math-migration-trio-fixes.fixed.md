- **Fixed: the `#1554` WebKit raster spec could not run.** `docs/e2e/math-compare-webkit.spec.ts` still asserted `section.math.compare > h3`, which is now zero — the column labels moved into `.cell-stage` with the rest of the body. The spec is tagged `@webkit-tablet` and runs only from the nightly, so no per-PR gate saw it, and the same change added 37 lines to its docblock explaining that the DOM had moved without moving the four assertions eleven lines below. Repointed, along with a reference to a test file that had been renamed.
- **Fixed: the variant-collision gate was blind to the selector shape the leak took.** It filtered on `startsWith('section.stats')`, which misses `section.form.stats …` — and the one selector it never checked was `section.form.stats … .cell-masthead .masthead-lede`, one of the four rules measured leaking onto a math slide. It also split the selector list on bare commas, fragmenting `:where(a, b)`. Both fixed, the matched count is pinned so a filter that starts matching *fewer* rules fails loudly, and the fix is mutation-proved against the rule that was invisible.
- **`form: off` is now named in the record.** The migration documented that per-slide `no-form` renders math unstyled but not the deck-level `form: off`, which is the first-class documented opt-out and *was* a working configuration for math. Recorded flatly, with the measured context that `stats` and `diagram` degrade the same way under `form: off` — math has joined an already-degraded mode rather than being singled out.
- **Corrected: `compare-code` does not make the same claim math did.** Four places said it was "the last frame making the same weak claim". It carries the same wording in its manifest and not the same substance — it builds a real four-row explicit grid and places its `> h2` at `grid-column: 1 / -1; grid-row: 1`, where math's title was `position: absolute` arithmetic reproducing the masthead's geometry. Math's migration is not a precedent for migrating it, and the canonical doc now says so.
- Four stale docblocks still described math as chrome-exempt (`plugins.js`, `form-default.js`, `masthead.transform.js` ×2, `base.elements.css`).
- The frame-conformance protocol's "flip `strict` only after proving the probe verdict unchanged" precondition was read as "verdicts *proven*" rather than "unchanged", because math's verdicts changed on purpose and the probe itself changed in the same branch. The departure is now recorded at the precondition instead of left for the next migration to inherit as silent precedent.
- **Fixed: un-truncating the variant summaries broke the gallery.** They are injected verbatim into each slide's generated `_footer:`, and at 130–138 characters the footer band clipped six of them — over the overflow ratchet, and a visibly ellipsed footer in both committed gallery PDFs. The 70-character cap was load-bearing and was not established as such before being removed. The summaries are rewritten to fit it as whole sentences, which is what the defect actually was.
- **Fixed: `math compact` at portrait.** The bare/`feature` tall reflow reserved for the KaTeX display's line box with `--sp-sm`, and `compact` shrinks the spacing tokens while the equation's own `em` does not — so the reserve went and the ascent cleared the stage. The reserve is `max(var(--sp-sm), 0.3em)` now, tied to the thing it reserves for. On the sovereign frame that slide clipped 3px of real ink; it now has 29px of clearance on each side.
- **Corrected a claim, and this one was load-bearing:** the record said no reflow could fit `feature`'s over-wide equation under the Fit Spine's no-scale axiom. That is false — a red team measured it fitting at 0.9em (42.28px), which is *larger* than the 37.41px the same equation is set at on a 16:9 slide. What is true is narrower: bare `math` and `feature` share one rule and bare's hero fits at the current 2.4em with 29px of clearance, so a single scale cannot serve both. The lever that serves both is breaking the expression across lines (~35%, measured) plus re-testing the scale-up — owner-ruled and tracked in #2136.
- **The family-reflow gate would have certified a reflow keyed to the wrong family.** It accepted any `[data-family]` selector, including `[data-family="wide"]` — the 16:9 default, where nothing needs to give. It now requires `tall`, `strip` or `square`, mutation-proved by re-keying a live rule to `wide`.
