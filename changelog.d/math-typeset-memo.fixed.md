- Typing on a slide that contains math no longer re-typesets equations that did not change. The engine now memoizes KaTeX by expression. Measured in the real Studio, on one math slide: a keystroke in prose costs **0** `renderToString` calls where it cost **10**, a 13-character burst costs **0** where it cost 80-110 (a range, not a point: how many keystrokes the debounce coalesces moves run to run), and the slide's cold paint costs **5** where it cost **10** — the memo also collapses an expression repeated within a slide. Typing a genuinely new expression still costs exactly **1**, so the memo keys rather than suppresses.
- `npm run bench` gains a `math` render row and a new **edit tier** that reports what an author pays per keystroke, for a single character and for a 12-character burst. The burst case was measured nowhere before — every existing typing harness inserts a 700 ms settle between keys, which is precisely the case the frame scheduler already handles. The tier gates on typeset **counts** rather than wall clock, so it is exact on every machine. Note the bench measures the WHOLE-DECK route (90 typesets per keystroke, now 0); the Studio renders one slide, so the author-facing figure is the per-slide one above.
- **New:** `docs/e2e/math-typeset-edit-cost.spec.ts` counts typesets from inside the real Studio page rather than from a Node harness, by wrapping the KaTeX module the provider registers. It runs in the nightly. Every run identifies which bundle it measured from a repeated expression in the deck — a stale preview server served the memoized build to three consecutive "before" runs and reported the memo's `0` for unmemoized code, and that fingerprint is what caught it.
