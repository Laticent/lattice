- **`npm run merge:order` finds digest PRs that conflict with each other and lands the smaller of each pair first.** It checks every pair of ready PRs for conflicts the way GitHub merges (in memory, merge drivers ignored), holds back any PR that already conflicts with `main`, and orders the rest: a PR built on another's branch after it, the smaller of two conflicting PRs first (the other rebases after it lands), otherwise oldest first, with the reason on each row. Every PR lands in exactly one list: ordered, held (it or the PR it is built on conflicts with `main`), or unordered (a dependency cycle). It checks pairs only, so a conflict that needs three PRs together, or a later change to `main`, is still the queue's to catch. `/desk-merge` step 3 now uses it. On its first run against nine real ready PRs it found two that conflict with each other (#3351 and #3361) and one that conflicts with `main` (#3345).
