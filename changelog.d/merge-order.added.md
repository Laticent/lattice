- **`npm run merge:order` orders a merge digest so the queue never ejects one digest PR for another.** It checks every pair of ready PRs for conflicts the way GitHub merges (in memory, merge drivers ignored), holds back any PR that already conflicts with `main`, and orders the rest: a PR built on another's branch after it, the smaller of two conflicting PRs first (the other rebases after it lands), otherwise oldest first, with the reason on each row. `/desk-merge` step 3 now uses it. On its first run against nine real ready PRs it found two that conflict with each other (#3351 and #3361) and one that conflicts with `main` (#3345).
