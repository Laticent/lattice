- The exported file now draws every Mermaid fence the engine parses, the same rule the live preview follows. A ` ```mermaid ` block inside an HTML block (such as a `<div>`) or inside a `$$` math block is no longer drawn in the PDF, PNG, PPTX or HTML export, because the engine reads it as HTML or math and the preview never drew it; the export used to draw it anyway, often clipped. The CLI now warns, naming the line, when a deck holds a Mermaid block inside an HTML block; after a `<div>`-style tag a blank line draws it, and inside a `<pre>`, `<script>`, `<style>` or `<textarea>` block it has to move out. A closed Mermaid block whose body contains a line of three asterisks is now drawn instead of exported as source. Two shapes still draw in the preview but not in the export: an info string that only starts with `mermaid` (` ```mermaid-x `) and a raw `<pre><code class="language-mermaid">` written as HTML.
