- **No tagged release carried the old names.** The image card's classes and the `guards:` key both arrived after 1.0.0, so the three changes below break decks written on `main` or in the live Studio since then, not decks written against 1.0.0. Earlier entries in these notes that name `at-tl`, `card-soft`, `card-o65`, `ink-light`, `band`, `compact` on the card, `guards: strict` or `guards-loose` describe those features before this rename; use the new names listed here.
- **Breaking: the image card has its own classes, and the old ones paint nothing on it.** Every card class is now `image-card-<word>`, the word the deck's `image-card:` line takes: `image-card-top-right` (was `at-tr`), `image-card-soft` (was `card-soft`), `image-card-65` (was `card-o65`), `image-card-light` (was `ink-light`), `image-card-sm` (was `card-sm`), `image-card-compact`, `image-card-regular`, `image-card-band` and `image-card-float`. The deck line itself does not change. `at-*` is the tint placement again and no longer moves the card, so a slide can carry `tint-corner at-tr` and `image-card-top-right` side by side. `lint:deck` reports each old class as `image-card-renamed`, an error that names the new one, and `lint:deck --fix` rewrites it. Beside a corner or edge tint (the slide's own or the deck's `class:`), an `at-*` word still places the tint, so lint warns instead and `--fix` adds the card's own word next to it (`tint-corner at-tr image-card-top-right`), keeping both where they were. The repo's decks are migrated.
- **Breaking: `image-card: compact` no longer tightens the slide's spacing.** It used to stamp the universal `compact` class, which also tightened the `--sp-*` scale on every image slide. It now stamps `image-card-compact`, which tightens the card only. A per-slide `compact` still tightens the slide and no longer tightens the card: on a `spotlight` or `statement` slide `lint:deck` warns, and `--fix` adds `image-card-compact` beside it so the slide renders as before.
- **Breaking: the old `guards:` spelling of `fit:` no longer does anything.** `guards: strict` used to trim like `fit: trim`; the engine now reads only `fit:`, so a deck that kept `guards: strict` gets the default fit level. `lint:deck` reports the line as an error (`guards-renamed`), and `--fix` writes `fit: trim` for `strict` and deletes the line for `loose`, which was the default. The per-slide `guards-strict` / `guards-loose` classes do nothing either; `--fix` rewrites them to `fit-trim` / `fit-heal`. `examples/overflow-guards.md` is migrated.
