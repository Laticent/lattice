- **A hostile-plugin test now guards the code sandbox.** `npm-plugin-canary.test.js` runs a deliberately hostile plugin renderer through the real plugin door and checks that a local HTTP, WebSocket and UDP listener sees nothing and that no storage read returns data; a control arm proves the listener can see each exit. A second test, `npm-plugin-export-check.test.js`, opens the real `--player` and plain HTML exports in Chromium, WebKit and Firefox and lists the exits they leave open. It is marked `todo` until the export policy gaps are closed. (`test/integration/export/`)
- **The code-package door's sanitizer no longer keeps an address hidden in a CSS variable.** A plugin could return `style="--q:'https://x/y';background-image:image-set(var(--q) 1x)"` and the door kept it, so an online page fetched the address. `cssRefTargets` now lists an address-shaped string held in a custom property whenever the CSS reads a variable. (`lib/core/door-attr.mjs`)
