- **A small file can no longer make the Studio or the CLI build millions of values.** The size caps bound how much a backup, a `.lattice` file or a package zip inflates to, but not what `JSON.parse` builds from it, and a value can be two bytes: a 3 MB file could ask for a million objects, and a 256 MB one for 134 million numbers. Every JSON file those doors read (a workspace restore, a `.lattice` manifest, and every package manifest, theme `essentials.json`, finish recipe and scene spec, in the Studio and in `lattice packages add`) now has its values counted first, and is refused past one million, far above anything real.
- **A backup with oversized or broken reference docs still restores your decks.** The reference docs and any unreadable scenes in a backup are now skipped when they are too large, unreadable, or hold more than 2,000 rows, and everything else comes back. What was skipped is listed in a notice that is shown again after the Studio reloads and stays until you dismiss it, where it used to vanish with the reload. Only the backup's core (its decks, settings and library) refuses the whole restore, and the message says which part.
- **A backup too large to restore in full now says so when you make it.** If your reference docs are over the 256 MB a restore reads, or your library or settings over their limits, the backup still downloads, and a message that stays up long enough to read says what will not come back. No message means no size limit will refuse the file.
- **Restoring a backup, and saving any new Library item, no longer reads every stored PDF.** The Library store looked up records by reading the whole shelf, reference docs included; it now reads only the kind it needs. A restore with many scenes and a few large reference docs went from about 2 seconds to under 20 ms in the measured case.
