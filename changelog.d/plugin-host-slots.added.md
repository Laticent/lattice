- A plugin that declares `contributes.returns` can put `${field}` in the drawing it returns, and the host fills it with the checked value: a word, number, flag or text value as escaped plain text, a markdown value as the host's own sanitized HTML (bare tags, no attributes). A slot fills in visible text only, never inside a tag, a comment, `<style>` or `<script>`, so a returned value cannot become a link or a style; a `${name}` that is not a declared field stays as written. A markdown value fills only in a block fence, outside `<svg>` and `<math>`; in an inline span it fills as its escaped source text. The fills of one render are budgeted at 2 million characters. Works in the CLI and in the Studio. Demo: `lib/packages/_demo-host-slots/host-slots.md`.
- An installed plugin's `styles.css` now reaches the CLI export and the Studio's previews and exports. The host parses the sheet and writes every selector back behind the plugin's own root (`[data-lattice-plugin="<name>"]`), so it can style that plugin's drawing and nothing else, then passes it through `sanitizeStyleText`. A sheet may hold style rules and `@media` / `@supports` blocks; an unbalanced brace, a nested rule, `&`, a leading combinator, `@keyframes`, `@font-face`, `@import` or any other at-rule is refused when the plugin is added.
