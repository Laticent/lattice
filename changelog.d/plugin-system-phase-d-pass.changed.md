- Mermaid's browser half belongs to the Mermaid plugin now. The diagram pass that draws every ` ```mermaid ` fence in the Studio, the Playground and `--fluid` moved out of `lib/runtime/index.js` into `lib/plugins/mermaid/mermaid.hydrate.js`. The runtime drives it through the plugin registry and no longer names Mermaid in its code. Diagrams draw exactly as before.
- The plugin model replaces `render.exec.hydrate: "runtime"` with `"pass"` and adds a `highlight` contribution (LPM 0.4-draft). A pass is a `hydrate.js` that exports `createPass(ctx)`, a document pass the runtime bundles and drives. A `highlight.js` exports a highlight.js grammar, which the host registers under the plugin's code fences. Mermaid's stylesheet (`mermaid.styles.css`) and grammar (`mermaid.highlight.js`) moved into the plugin. The stylesheet now sits in the plugin slot of `dist/lattice.css`, after the math and function-plot sheets; no selector of theirs matches Mermaid's output.
- A CLI bake's context carries only the generic services in `BAKE_SERVICES` (`lib/plugins/host-bake.js`), and `bakeDeck` refuses any other. `diagramTheme` is gone. `paletteReader` replaces it, and Mermaid's bake builds its own theme variables with it. The image-set export's cross-scheme look reads the bake's generic re-bake hook (`state.rebake`) instead of Mermaid's record.
