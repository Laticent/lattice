- The editor's `_class:` autocomplete now completes by position, the way a shell completes a command line. The first word offers only components. Every later word offers only what THAT component accepts: its own variants first, then its family modifiers and the modifier groups as labeled sections, with the finishes last. A modifier already on the line drops out, and so does every other member of an exclusive axis once you pick one (`tone-pass` hides `tone-warn`; `us` hides `world` on a map). A dependent such as `at-tl` appears only after `tint-corner`. A bare space after the component opens no menu, so pressing Enter for the default look never picks a variant by accident. The menu opens on the first letter, or on Ctrl-Space. `_class: dark` still works: once the first word names no component, it completes as the default `content` slide.
- A modifier is offered only where the slide part it acts on exists. `big-number` has no heading, so it stops offering `rule-none` and `with-period`. `lifted` appears on the components whose cards actually lift, and after `kpi ops` but not plain `kpi`. The table modifiers appear on a table component, or on any slide whose body contains a table. No manifest lists modifiers: each component's surfaces are derived from its anatomy and corrected by a render proof, `npm run check:modifier-effects`, which renders every component with and without each modifier and records what actually changes.
- Inside each section, the modifiers authors use most in the example decks come first. A group acting on something the slide already contains, such as a table, moves up.
- A component manifest's `excludes` now takes a whole modifier group (`"table"`, `"cards"`, …) or any single universal token, not only `compact` / `accent` / `claim-bleed`.
