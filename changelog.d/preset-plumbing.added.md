- A `preset:` can now recommend a palette (`theme:`), a color mode (`color-mode:`), a rendering hand (`mode:`), a mark finish (`marks:`) and a finish restraint (`backdrop:`), and every render path, the CLI, Export to Marp, the Playground sheet and the Studio read the recommendation. A key the deck writes still wins, a deck-wide `class: dark`, `light` or `print` (or a `-dark` theme) keeps its color mode, and the Studio's preset picker and Reset never remove the author's `theme:` or `color-mode:`. In the Studio drawer and the Playground sheet, Auto follows a recommended palette or color mode and names it (`Auto — preset: Cuoio`). No shipped preset sets these keys yet, so every existing deck renders as before.
- A preset can carry internal design tokens: a deck on such a preset gets a `preset-<name>` class on every slide, and the build generates the matching rule. None of the four shipped presets carries tokens.
- Export to Marp now reads a `theme:` with a trailing comment (`theme: cuoio  # brand`) as `cuoio`, as the renderer does, instead of shipping the default palette.
- The Studio and website preview read `theme:` and `color-mode:` with a trailing comment the way the renderer does.
