- **Breaking:** the page-number key is now `pagination:`, so the key and its `no-pagination` / `with-pagination` classes share one word. `paginate:` is a lint error (`key-renamed`) and the engine ignores it; `lint:deck --fix` renames it and keeps the value, or deletes it when the deck also sets `pagination:`. Unlike the image-card and `guards:` renames, `paginate:` was in the August v0.9.0 preview (GitHub only, never on npm), so this breaks decks written for that preview too; `lint:deck --fix` migrates them.
- **Breaking:** two lint rules follow the key: `paginate-unsupported-value` is now `pagination-unsupported-value`, and `paginate-comment-retired` is now `pagination-comment-retired`. The comment rule also reports a `<!-- pagination: … -->` slide comment, which does nothing, as Marp's `paginate` comment does nothing.
- Export to Marp still writes Marp's own `paginate:`, and drops a leftover `paginate:` line, so an exported deck numbers the same slides. The Studio's Page numbers switch writes `pagination:` and removes an old `paginate:` line.
- `key-renamed` reads one table, `KEY_RENAMES` in `lib/authoring/lint-core.js`; each later key rename adds a row there instead of a rule.
