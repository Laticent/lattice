- **Fixed: the inline-run transformer no longer turns an attribute's text into markup.** Its string path read a tag with a regex that stopped at the first `>`, so `<li title="a><img src=x onerror=…>">` ended the tag inside the quoted value and the transformer wrote its `<span class="lat-run">` there, which made the `<img onerror>` a live element. `lib/core/inline-run.js` now reads tags with a small state machine that follows the HTML tokenizer: a quoted value is one piece, an unquoted value ends at whitespace or `>`, a `<script>` body follows the script escape rules, `<title>` and `<style>` are ordinary elements inside SVG and MathML, and a slot's class comes from the `class` attribute itself rather than from any text that looks like one. It also tokenizes a section once instead of once per list item, so a long list or a comment-heavy item no longer costs quadratic time. No shipped deck's output changes: all 322 example and gallery decks render byte-identical HTML. A seeded differential fuzz checks that the string path and the DOM path build the same tree on 800 items full of `>`, `<`, quotes, SVG and script edge cases.
- **Fixed: the Studio preview no longer parses sanitized slide markup twice.** When it patched a new slide into the live frame, `patchSlideBody` parsed DOMPurify's output into a holder, serialized it, and parsed the text again into the same-origin frame. That round trip is where mutation XSS lives: a tree that does not survive it can come back holding an element the sanitizer never saw. The function now moves the holder's parsed nodes with `replaceChildren`, so the frame shows exactly the tree DOMPurify's verdict covers.
- **Fixed: an unterminated `<!-- class:` directive no longer freezes the Studio.** The prose counter stripped class directives with a regex whose three side-by-side whitespace quantifiers backtracked in cubic time when no `-->` followed: 4000 spaces after `<!-- class:` took 24 s, on the main thread, and a shared or imported deck could carry it. `stripClassComments` in `lib/authoring/prose-budgets.js` now does the strip with a linear scan, and `review-core.js` uses that one copy instead of its own. The same input takes under 0.1 ms, and 20,000 unterminated directives take under 1 ms. A differential test pins the scan to the old regex on a seeded corpus and on every Markdown file the repo ships.
