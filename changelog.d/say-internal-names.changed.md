- **Breaking:** the `lib/` modules that handle a slide's `say:` line no longer call it a caption. For code that deep-imports `@laticent/lattice/lib/*`: `lib/core/resolve-captions.mjs` is now `lib/core/resolve-narration.mjs`, its `frontMatterCaptions` is `frontMatterSayMap`, and `parseNarrationFrontMatter()` returns the map as `.say` instead of `.captions`. In `lib/authoring/notes-core.js`, `captionFromHtml` is `sayLineFromHtml`, `extractSlideCaptions` is `extractSlideSayLines`, `isCaptionComment` is `isSayComment`, `stripCaptionsFromSource` is `stripSayFromSource`, `stripCaptionsFrontMatter` is `stripSayFrontMatter`, `stripChannelsFromSource`'s `captions` option is `say` (the old key throws, so a privacy strip never silently skips the say text), and `slideNoteRecord` returns `say` instead of `caption`. `mergeNarration` (`lib/core/read-along-build.js`) takes `{ sayLines, fmSayMap }` and throws a `TypeError` that names the new keys when it is passed `captions` or `fmCaptions`, so an old call fails at once instead of quietly dropping every override. The rendered output does not change.
- Three CLI messages now say "say" for the spoken line: the `--captions` log line when a split remaps the front-matter `say:` map, the "nothing to narrate" message, and the warning when the Markdown attached to a PDF could not have a note or say comment removed.
