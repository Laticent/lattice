- **Segno's generated `parse()` allocates nothing per successful call.** It reuses one result object (its tree was already valid only until the next parse, because the buffer is shared) and skips the rule-table lookup for the grammar's default rule. A pill's grammar stage went from about 270 ns to about 225 ns, and the shipped decision for a pill from about 500 ns to about 480 ns (same machine, interleaved runs of `npm run parser:bakeoff:segno`). A successful `parse()` now returns the SAME result object every time, so a caller that kept results from two parses, or wrote to one, sees the later parse's values; read `tree.buf` and `tree.top` before parsing again (the buffer was always shared). Trees and errors are unchanged; the 305 Segno tests and `inline-code-table.test.js` pass. The generated parsers in `lib/core` (`flowchart-row`, `list-text`) pick the change up too.
- **`npm run parser:bakeoff:segno` times a row's columns alternately.** It used to time the retired kernel, the arm's copy and the shipped dispatcher one after another, with one timer function whose call site the first column warmed. Each column now gets a timer of its own and the columns alternate round by round. On one quiet machine both versions read the every-span ratio at 1.2x to 1.4x (the 1.5x bar is met); the earlier 1.3x to 1.7x readings came from a busy sandbox, so the ratio was noise-bound rather than pill-bound.
