- The Studio's Reading view no longer lets an escaped `u\72l(https://…)` in a theme's CSS through its last guard. The view drops every web address from the deck sheet it puts in the Studio's own page, and that check matched a literal `url(` only. It now reads CSS with `cssRefSpans`, the reader the exports and the scanner share, and judges each address the way the refusals do, so a tab inside the scheme, a `\\host`, or a non-web scheme such as `chrome-extension://` is caught too. It also drops a nested rule written without `&` (`.a{+ p{…}}`), which it could neither fence nor read, and it reads an escaped at-rule name (`@\70roperty`) as the at-rule, so neither can reach the Studio around the article. The theme gate and the web-image block in front of it already refused a web address unless you had allowed its origin.
