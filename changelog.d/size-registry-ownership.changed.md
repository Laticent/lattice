- The engine now owns the slide-size registry. Named canvases (`hd`, `story`, `mobile`, …) live in `lib/engine/sizes.js` and a deck still selects one with `size:` in front matter. Source stylesheets no longer declare `@size` — the same 14-line table had been duplicated byte-for-byte across 32 palettes plus the base sheet, and the engine parsed it back out of its own CSS comment on every render.
- **Breaking (theme authors only):** a theme can no longer register or redefine an `@size`. The registered names are the whole vocabulary; a stylesheet that declares `@size` is rejected by `check:ownership`. In-repo themes all declared the identical table, so no deck changes shape — but an out-of-tree theme carrying a custom canvas will now render at that theme's `size:` name only if the name is registered, and otherwise at the `hd` default. A canvas we do not ship is a one-line addition to the registry.
- Export-to-Marp is unaffected: `@theme` stays in every stylesheet, and the build stamps the `@size` directives Marp reads into `dist/lattice.css`, `dist/lattice.min.css`, `dist/themes/*.min.css`, and the marp-kit. A new `check:ownership` gate fails in both directions — on source CSS that declares `@size`, and on a Marp-facing artifact whose stamp is missing or has drifted.
- `lint:deck` derives a deck's adaptive family from the same registry the renderer resolves against, in Node and in the browser alike. It previously fell back to a hand-copied name table in the browser, which a newly registered size slipped past.
- Fixed: a `size:` value naming an inherited `Object` property (`size: constructor`) resolved to a function instead of a canvas, yielding `NaN` page geometry. Unregistered names now resolve to the `hd` default, and the emulator still rejects a typo'd `size:` before launching Chrome.
