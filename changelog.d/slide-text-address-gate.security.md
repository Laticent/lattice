- **Plugins draw on every layout, and no built-in pass reads their output as an address.** A zip plugin's fences and `@kind{…}` spans used to stay code on the 42 layouts a shipped pass rebuilds from its bullets (the charts, `kanban`, `roadmap`, `team-profile`, `logo-wall`, a `qr` closing slide…), because a pass such as `qr` would have turned a plugin's bullet into a QR code. Every pass that turns slide text into something the viewer loads or scans (the `contact`, `wifi` and `qr` codes, the `video` poster, logo masks, roster and collage photos, the runtime's data probe) now reads through a mask that skips `[data-lattice-plugin]`, on the engine's pass and the runtime's DOM pass alike, so the door draws everywhere. `contact` and `wifi` still keep only their card, as they always have for any code block.
- New `checkSlideTextAddressReaders` gate (`build:check`): a source file that reads slide text (`textContent`, a walk over `<li>`s, a regex hunting `href=`/`src=` in markup) and writes an address (a `src`, `href`, `url()`, poster or QR code) fails the build unless `SANCTIONED_SLIDE_TEXT_ADDRESS_READERS` lists it with its reason. Each entry pins its address writes and its guard calls by COUNT, so a new write or a deleted guard in a large file fails too, and a stale entry fails. Today's 19 readers are listed: 8 that skip plugin output, 11 that build no address from slide text (export readers of a finished document, the consent gate, resolvers that never invent an address).
- **Fixed: a plugin's list item can no longer leave its box.** A plugin fence written inside a bullet, whose output held a bare `<li>`, had that item moved by the browser out of the plugin's box and into the author's list, where the live preview's `qr` pass encoded it (found by this change's red team, before release). The door now refuses an `<li>`, `<dd>` or `<dt>` outside its own list, in the Studio and the CLI; the block stays code with a note saying why.
- A plugin `@kind{…}` span that a chart layout turns into label text (`piechart`, `funnel`) now gets a warning instead of silently showing as written.
- The Reading view and the webpage export's reading document now copy a plugin's drawing whole, with its `[data-lattice-plugin]` root, instead of lifting its lists and paragraphs as if the author had written them.
- The Reading view and the webpage export's article contain a plugin's paint as a slide does: a `position:fixed` box or the plugin's own stylesheet stays inside the plugin's box, and a wide drawing scales to the reading column.
