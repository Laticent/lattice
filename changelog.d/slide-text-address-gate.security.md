- **Plugins draw on every layout, and no built-in pass reads their output as an address.** A zip plugin's fences and `@kind{…}` spans used to stay code on the 42 layouts a shipped pass rebuilds from its bullets (the charts, `kanban`, `roadmap`, `team-profile`, `logo-wall`, a `qr` closing slide…), because a pass such as `qr` would have turned a plugin's bullet into a QR code. Every pass that turns slide text into something the viewer loads or scans (the `contact`, `wifi` and `qr` codes, the `video` poster, logo masks, roster and collage photos, the runtime's data probe) now reads through a mask that skips `[data-lattice-plugin]`, on the engine's pass and the runtime's DOM pass alike, so the door draws everywhere. `contact` and `wifi` still keep only their card, as they always have for any code block.
- New `checkSlideTextAddressReaders` gate (`build:check`): a source file that reads slide text (`textContent`, a walk over `<li>`s, a regex over a section's HTML) and writes an address (a `src`, `href`, `url()`, poster or QR code) fails the build unless `SANCTIONED_SLIDE_TEXT_ADDRESS_READERS` lists it with its reason and its guard. A `masks` entry must still call `maskPluginSubtrees` or skip `[data-lattice-plugin]`, and an entry fails when its file gains a new kind of read or write, or no longer matches at all. Today's 13 readers are listed: 8 guarded, 5 that build no address from text (export readers, the consent gate, resolvers that never invent one).
