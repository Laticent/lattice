- The running header now renders on `split-panel` and `split-compare` slides. Frame chrome (`header`, `footer`) was `position: absolute` with no stacking order, so among positioned siblings paint order fell to DOM order — and chrome is emitted around the component's subtree, not above it. The header comes first and lost to any opaque part docked at the same corner; its strip rasterized to one flat color on every non-`mirror` variant of both families. `section header` / `section footer` now sit at `z-index: 3`, above component content and below the diagnostic tabs.
- Frame chrome over a `split-panel` or `split-compare` panel takes the ink of the field beneath it instead of the canvas ink, so revealing the header does not make it unreadable: `--on-dark-secondary` on the inverse panel, `--on-accent` on `watermark`, `--cat-on-fill` on a `cat-N` tint. `metric`, `steps` and every `mirror` form put canvas under the chrome and keep the ordinary muted ink. Verified across all 61 component galleries: 511 running headers and 504 running footers, with every panel-field case now clearing AA (5.47–13.90:1) and only the three intentional canvas cases below it, at the deck's existing muted-chrome level.
- **The running footer on those layouts was already illegible, and is fixed too.** `<footer>` is emitted after the component's subtree, so unlike the header it always won paint order and has always rendered over the panel carrying canvas ink — 2.44:1 on a `cat-3` tint, 2.76:1 on the inverse panel. Pre-existing, not a consequence of the stacking fix.
- A deck-level `header:` longer than roughly 25 characters runs past the panel's edge on these layouts and loses contrast there; keep it short or clear it per-slide with `<!-- _header: "" -->`.
- `build:galleries:check` and `build:bucket-galleries:check` now flag a PDF whose *render inputs* changed, not only its own markdown. They compared one mtime — the gallery `.md` against the PDF — so a CSS or engine change with no deck edit reported every gallery current; the on-dark ink release was entirely CSS and moved 424 slides across 122 galleries while this reported all of them up to date. They ask git what changed rather than reading the filesystem clock, which is wrong in both directions (a fresh clone stamps everything at checkout time; `git checkout <ref> -- themes` made 15 palettes look newer than every PDF with identical content).
