- The running header now renders on `split-panel` slides. Frame chrome (`header`, `footer`) was `position: absolute` with no stacking order, so any opaque component part docked at the same corner painted straight over it in DOM order — the header strip rasterized to one flat color on every non-`mirror` variant of the family. `section header` / `section footer` now sit at `z-index: 3`, above component content and below the diagnostic tabs.
- A header over a `split-panel` takes the ink of the field beneath it instead of the canvas ink, so revealing it does not make it unreadable: `--on-dark-secondary` on the inverse panel (7.17:1), `--on-accent` on `watermark` (5.47:1), `--cat-on-fill` on a `cat-N` tint (10.80–13.90:1). Measured across the component's 22 headers in both moods: all 22 were sub-threshold before, 18 now clear AA and the other 4 sit on ordinary canvas at the deck's existing muted-chrome level, unchanged. A deck-level `header:` longer than roughly 25 characters runs past the panel edge and loses contrast there.
- `build:galleries:check` and `build:bucket-galleries:check` now flag a PDF whose *render inputs* changed, not only its own markdown. They compared one mtime — the gallery `.md` against the PDF — so a CSS or engine change with no deck edit reported every gallery current; the on-dark ink release was entirely CSS and moved 424 slides across 122 galleries while this reported all of them up to date. They ask git what changed rather than reading the filesystem clock, which is wrong in both directions (a fresh clone stamps everything at checkout time; `git checkout <ref> -- themes` made 15 palettes look newer than every PDF with identical content).
