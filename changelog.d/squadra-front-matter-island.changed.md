- The front-matter island: one reader for where a deck's front matter ends and which of its lines are keys (`lib/core/front-matter-island.mjs`). The engine's `parseFrontMatter`, the shared markdown-it kernel, the pane render, the register resolvers, the slide splitter, the deck model, the plugin admission and the `lattice-deck` lint language read it, where each used to carry its own pattern. `lattice-deck` gains an `fm-key` node per front-matter key (name, value and block-scalar body spans, and the key it nests under) and the `deck.settings` and `deck.registers` facts. No tracked deck renders or lints differently.
- **Fixed:** a deck whose front matter closes with `---` followed by spaces no longer reads the start of its first slide as deck-wide classes; the engine already ended the front matter there for every other setting.
- **Fixed:** a Windows (CRLF) deck that opens with two `---` lines is no longer read as having an empty front matter, which made adding a plugin in the Studio drop the author's first slide.
