- `state-chart` transitions and states accept `:::token` to name a **theme token** to paint with — `1. Draft `start`:::state-info-hue`, `- `reject => 3`:::state-fail-hue`. A transition takes an optional second slot for its edge-label background (`:::state-fail-hue/surface-raised`). The token is used as `var(--<token>)`, so a tinted deck still re-themes with the palette; there is no syntax for a hex literal. Malformed names are dropped whole and the element keeps its inherited paint.
- **Fixed:** the tint channel no longer erases what it cannot paint. A `:::token` naming a token that does not exist used to make the custom property invalid rather than fall back, which sent a transition's `stroke` to `none` (the edge vanished), dropped a state's border, and painted the state solid black. Each inline value now carries its own fallback, so an unknown token renders the untinted default — which is what every doc surface already promised.
- **Fixed:** the start marker's arrowhead is painted from the palette again. It reads `--edge-tint`, which was declared only on the edge group — and a start marker sits outside every group, so the arrowhead fell to the SVG initial and painted pure black on every machine, chains included, and invisibly against a dark canvas.
- **Security:** tints read back out of the DOM by the browser pass are re-validated against the token grammar and escaped at the sink. The build-time parser refuses anything but a bare token, but the pass reads `data-tint` and the transitions JSON from the document — where a deck author's raw inline HTML also lands — and interpolated them into a `style` attribute unescaped, which let a crafted value inject live markup into the preview frame (HARD RULE #22).
