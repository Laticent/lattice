- **Breaking:** a `_focusSteps` slide is now ONE slide everywhere: one page number, one section, one rail dot. It used to be copied once per step, so a three-step table printed three pages and pushed every later page number up by two. Present walks the steps instead (the Studio, the presenter's Stage window and the exported HTML player): next lights the next target, and entering the slide backward lands on its last step. PDF, PowerPoint, images, the narrated video and the editor preview show the slide at rest, every unit even and nothing lit. For a printed walkthrough, export with `--steps` (or turn on "One page per step" in the Studio's export sheet): each stepping slide prints once per step, and every page keeps the slide's page number. Presenting live to a room carries the step, so everyone following sees the same reveal. `focusSteps` sets one slide only: front matter does not set it, and the bare `<!-- focusSteps: … -->` sets the slide it is on, like `_focusSteps`.
- `_build` now walks in Present, as `examples/build.md` always promised: entered by next, or jumped to (the rail, the overview, opening Present on it), the slide starts with nothing revealed and each click reveals the next step. Still formats show the whole slide, as before.
- `lattice <deck> --steps` and the Studio's "One page per step" switch (PDF, PowerPoint, LibreOffice, and "One image per step" for an image set) give each step of a `_build` or `_focusSteps` slide its own page, painted at that step. Every page keeps its slide's page number, and speaker notes and alt text ride on each page. Off by default.
- `lint:deck` flags a slide that carries both `_build` and `_focusSteps` (`one-stepping-directive`): a slide takes one stepping directive.
- `lint:deck` warns when a slide carries a static `_focus` beside `_focusSteps` (`focus-with-steps`): the walk owns the slide's focus, so the static one is ignored.
- A focused line of code (`_focus: line N`, a `_focusSteps` line walk, or the code block's own `focus=`) is now outlined (one box around a run of adjacent focused lines), and the dimmed lines around it stay readable at 4.5:1, so the whole slide passes WCAG AA. Before, the focused line differed from the dimmed ones by color alone, which did not read as focused on a dark code panel, and the dimmed lines were held only at 3:1.
