- **Breaking:** `compare-table` is renamed to `table`. Replace `<!-- _class: compare-table -->` with `<!-- _class: table -->`. There is no alias — an unmigrated slide falls back to `content`, so the table still renders with the house treatment but loses its row capacity, autosplit, portrait card reshape and focus axes. `lint:deck` now names the replacement outright — `'compare-table' was renamed to 'table'` — because the fuzzy suggester cannot: it scores edit distance, and the two names are 8 apart, which is exactly the case a deliberate rename is worst for.
- **Breaking:** a `table` slide now HUGS its content vertically and centers in the stage, instead of stretching to fill it. The old geometry stretched the table but left each cell's text pinned to the top of its band, so a short table read as a line, a gap, a line, a gap. Add `table-fill` to a slide to get the filling geometry back — now with cells centered in their bands, which is what the stretch always should have paired with.
- **Breaking:** a `table` slide picks up the universal table treatment it was previously excluded from, so it now draws the low-alpha accent zebra and uses the shared `--sp-*` cell padding rather than its own `cqi` values. `table-plain` turns the zebra off.
- `table-plain`, `table-fill`, `--table-zebra`, `--table-grow` and `--table-valign` work on the table component for the first time. They were inert on `compare-table` by construction: the component owned a near-duplicate of the universal table CSS and had to be denied that treatment to stop the two fighting. The component now styles no `<table>` element at all — it declares the contract (capacity, density, focus axes, the portrait reshape) and rides the shared treatment.
- The first column reads as a row label — 600 weight, heading ink — only when it actually is one. `lib/core/table-row-label.js` decides per table and turns the emphasis off on a single-column table, an index header (`#`, `No.`, `Ref`), an all-numeric first column, and a column of bare state markers. Measured across every markdown table under `examples/`, `exemplars/`, `test/integration/baseline-decks/` and `lib/components/` — 228 of them: every one keeps its label except the two demonstration tables added below, which exist to show the rule declining.
- New `row-label` / `no-row-label` modifiers overrule that measurement in either direction. `no-row-label` wins a slide carrying both.
- A plain markdown table under `mode: sketch` now gets the drawn frame and wavy row rules. It previously took the hand type with no frame, because sketch's table rules named three components instead of describing the tables they decorate.
- `row-label` and `no-row-label` work on a plain table too, so a table outside the component can opt in. Both are **per-slide** tokens: a deck-level `class:` does not reach them. `examples/universal-table.md` demonstrates all three states on rendered slides: measured on, measured off over a year column, and `row-label` forcing it on over that same column.
- A table written as raw `<table>` HTML keeps its bold first column. It gets no verdict — markdown-it hands raw HTML through as an opaque block, so its rows never reach the rule — so the slide falls back to emphasizing the first column unconditionally, which is exactly what `compare-table` did. Without that fallback the rename would have quietly taken the emphasis away. The fallback is scoped to slides whose markdown actually holds a raw `<table>`, and every pipe table on such a slide carries its own verdict, so a deliberately-declined column (a year) is not swept up.
- Under `mode: sketch`, the drawn frame and wavy row rules follow the same stage-child scope as the universal treatment. A table inside `split-panel`, `split-compare`, `compare-code` or `image` is left alone, as `base.docs.md` promises, and `glossary` keeps its frame without gaining wave strips — its rows are separated by a zebra wash and it draws no cell border, so a strip there would be a line the deck never drew.
