- A theme's name now has one owner: `themes/<name>.manifest.json`. The filename and the `@theme` directive are projections of it, and a new `check:ownership` gate fails if any of the three disagree. They agreed by discipline before, but nothing checked — `themes/foo.css` declaring `@theme bar` would pass every gate and register under a name no picker, manifest, or `@import` referred to.
- `addThemes()` accepts `{ name, css }` alongside a bare CSS string, on both the engine (`./engine`) and `window.LatticePlayground`. Passing the name is now the contract: every in-repo caller already had it and was discarding it, leaving the store to recover it by regex. The bare-string form is unchanged for external consumers, and a second gate keeps new in-repo callers on the object form.
- Fixed: registering a stylesheet with no `@theme` directive scanned the entire buffer before giving up — hundreds of microseconds on a large sheet — and then registered nothing while returning a `false` no caller checked, so the theme vanished and the deck rendered unstyled with no signal. The legacy scan is now bounded to the file header, and a named registration with a missing or non-string name throws.
- `@theme` deliberately stays in source theme CSS, unlike `@size`: `@workwel/lattice/themes/<name>.css` is a published export documented as a Marp theme file, and Marp throws without the directive.
