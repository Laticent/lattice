- **Fixed: a theme whose parent import is written without quotes composed to an unstyled deck.** The engine store read `@import 'indaco';` and `@import"indaco";` but not the bare `@import indaco;`, so a theme using that form lost its parent and came back as ~2 KB of scaffold instead of the full ~769 KB stylesheet — the same silent failure the `-dark` wrappers had, from a different cause. No shipped palette uses the bare form, so nothing in the box was affected; a stylesheet handed to `addThemes()` by the Studio, a shared deck or an external `./engine` consumer was.
- The two remaining places that read a theme's parent out of CSS now share one grammar. The engine store and the `--css` flattener each carried their own regex and had drifted apart — one accepted the bare form and mismatched quotes and mis-read `@import url(…)` as a theme named `url`; the other accepted neither. Both now go through `themeNameImports` / `replaceThemeNameImports` in `lib/theme/chain.mjs`, matching what the theme gate already enforces, and a test drives both consumers over the same fifteen `@import` forms so a future fix cannot reach one and miss the other. Composed output is byte-identical for all 32 palettes across four sizes.
