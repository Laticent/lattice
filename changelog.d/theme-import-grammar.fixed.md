- **Fixed: a theme that merely MENTIONED another palette in a comment inherited the whole thing.** A header comment reading `/* … like @import 'onyx'; but warmer … */` made the engine splice all 768 KB of `onyx` into a theme that declared no parent — and since comments are stripped afterwards, the rest of that sentence was left behind as live CSS, read as a selector, and swallowed the rule following it (a theme's own `@font-face`, in the case that surfaced). The Theme Studio puts a user's free-text description straight into that comment, so any description mentioning a palette by name was enough. Comments are no longer scanned for imports.
- The two places that read a theme's parent out of CSS — the engine store and the `--css` flattener — now share one grammar and one comment policy, in `lib/theme/chain.mjs`. They had drifted apart: one mis-read `@import url(…)` as a theme named `url`, and they disagreed about a comment sitting inside the directive. A test drives both over the same 28 `@import` forms so a future fix cannot reach one and miss the other. Composed output is byte-identical for all 32 shipped palettes across every registered size.
- The grammar is quoted-only, which is what CSS itself, real Marp, the theme gate, and the engine's own base-import resolver already required. A bare `@import name;` is no longer followed by either reader — nothing in Lattice emits it, and accepting it in one reader while the base resolver rejected it silently composed a theme down to a 2 KB unstyled scaffold. `@import "name.css";` — a sibling file in a `--css` layout sheet — is supported explicitly, where it previously worked only by accident.
