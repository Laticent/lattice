- **The web-reference scanner now removes a web `ping`, `action` and `formaction`.** They send a request when the reader clicks a link or submits a form, not when the page renders, so the scanner had left them in place; the Reading view and the preview frame stopped them with the slide sanitizer and the content-security policy, but a host with neither (the `fonts: true` mode) did not. A web address in one now goes, with its attribute, and appears in `blocked` with its origin so a host can offer to approve it; a relative address, a fragment or an approved origin stays. Exported files change only for a deck that carries a web `ping`, `action` or `formaction`: all 384 decks under `examples/`, the baseline decks and `exemplars/` export byte for byte the same.
- **An allowed origin no longer vouches for an address that only begins with it.** `blockWebImages` decoded an attribute value a second time before reading its origin, so `https://own.example&amp;sol;@evil.example/x` read as the allowed `own.example` where Firefox and Safari read `own.example&sol;` as userinfo and fetch from `evil.example`. It now decodes once. This is a live leak in the Reading view (which allows its own origin) for a `srcset`, a `src` or a style `url()` on Firefox and Safari, found by the checker on the click-time change; Chromium refuses a credentialed subresource, so it did not show there. `attributionsrc` is removed with the other click-time attributes.
- **A `<noscript>` no longer hides an address from the scanner in the Playground's preview.** The scanner read `<noscript>` content as text; the sanitizer that runs after it reads it as markup and keeps the elements, so `<noscript><img srcset=…></noscript>` came out as a live image that Firefox fetched despite the preview's content-security policy. A `<noscript>` now sends the markup to the page's own parser, as a `<select>` does.
- **`&Tab;` and `&NewLine;` split a `ping` or `attributionsrc` list as the browser does.** The scanner decoded both named references to nothing, so `ping="/x&Tab;https://evil.test/p"` joined into one relative address and passed, while a browser reads two addresses and pings the second. They now decode to a real tab and newline, as `&#9;` already did.
