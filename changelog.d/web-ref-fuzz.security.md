- **The web-reference scanners now refuse five more ways a deck could make the browser fetch from the web.** A seeded fuzz of `blockWebImages` and `blockWebCss` found them: a `<base href="https://…">` (it re-points every relative address on the page), a refresh `<meta>` (it navigates the page; a refresh to a `data:` or `blob:` page is removed whatever its target), an address written without its slashes (`http:host`, `http:/host`, absolute to the URL parser on a `file://` or https page), and, where no content-security policy sits behind the page (the Reading view), an `<iframe srcdoc>` or `data:` page in an iframe, object or embed, and an SMIL animation that sets a link's address. A `<select>` now makes `blockWebImages` ask the page's own parser, because newer browsers parse its content differently. The gallery gate now lists a `<base>` element.
- New `npm run fuzz:web-refs`: generates CSS and HTML from the tokenizer rules, rewrites each input, loads it in Chromium, WebKit and Firefox against a loopback server, and fails on any request. A seeded 600-input slice runs in the integration tier on every PR.
