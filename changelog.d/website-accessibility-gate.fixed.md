- **Accessibility, website:** the component reference's active nav item rendered its label in `--accent` on an `--accent` pill — a 1:1 contrast ratio, an invisible label — on the default palette. An unlayered `a { color: var(--accent) }` in the docs stylesheet was beating the layered Tailwind utility meant to color it, so every link in that nav ignored its own ink token. Fixed at all five call sites that had drifted off the token bridge's declared pairing.
- **Accessibility, website:** the Playground shipped with no `<main>` landmark, no `<h1>`, and two toolbar rows in no landmark at all; the Studio shipped with no `<h1>` on any of its four shells. Both now have them.
- **Accessibility, website:** scrollable code blocks and Markdown tables were reachable only by pointer at phone width, leaving anything past the right edge unavailable to a keyboard (WCAG 2.1.1). They are focusable now.
- **Accessibility, website:** the site menu's current-page row measured 4.47:1 (label) and 3.80:1 (description), and its close button was a 16×16 target under a mouse — below WCAG 2.2's 24×24 minimum. All three fixed; the same close-button floor is raised on the shared Dialog.
- **Accessibility, website:** inactive tabs used a 60%-alpha ink that measured 2.46:1 in light mode. They now use the muted text token, which is gated.
- **Accessibility, decks:** `--text-muted` — the ink for the running header, running footer and pagination counter on every slide — was the one text role the theme contrast audit never scored, its AA standing asserted only in a comment. It is now gated against both the canvas and the card in all 32 themes.
- **New gate:** `docs/e2e/axe-site.spec.ts` runs the WCAG 2.2 A/AA rule set over 12 site routes at desktop, tablet and phone widths in both color modes, plus the site menu open. An exact 1:1 contrast ratio — which axe reports as `incomplete` rather than a violation — now fails.
