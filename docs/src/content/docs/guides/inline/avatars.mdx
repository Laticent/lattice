An **avatar** is a drawn stand-in portrait. You write the person's name in `!{…}` inside
**single-backtick** inline code, and Lattice draws a head and shoulders on a tinted tile:

```markdown
Our sponsor `!{Ada Okafor}` Ada clears blockers above the program.
```

It is for the face you do not have a photo of yet, a fictional persona, or a template
where faces are the point. When you have the real photo, use the photo.

## The name picks the face

The name is the only thing an avatar needs. **Every trait you do not write is chosen by the
name**, so `` `!{Ada Okafor}` `` is the same face on every render, on every surface, and in
every copy of the deck. Case and spacing do not change it.

## Write only the traits you care about

A trait is written by name, `key=value`, because the values overlap: `round` is a face, an
eye shape and a pair of glasses. Pin the two or three things that make someone
recognizable, and the name fills in the rest. Pinning one trait never reshuffles the others.

Skin, hair, eyes and clothes keep their colors in every theme, as a photograph does. A
person's skin does not change when the deck switches palette.

### Earrings, head coverings and clothing

These are opt-in. A name that does not write them gets no earrings, no head covering and a
crew-neck top, so a face you already drew does not change.

```markdown
`!{Amina Yusuf, headwear=hijab, headwear-color=plum}`
`!{Rohan Mehta, headwear=turban, headwear-color=olive}`
`!{Omar Haddad, headwear=skullcap, headwear-color=cream}`
`!{Sam Lee, headwear=cap, clothing=hoodie}`
`!{Ada Okafor, earrings=hoop, clothing=blazer}`
```

A hijab and a turban hide all hair; a skull cap or a cap hides the fringe and anything that would
rise above it (a bun, an afro, curls). The hair you wrote stays on the face under the covering, so removing the
covering brings it back. A hijab covers the ears, so it hides earrings; a bob covers the lobe, so only the edge of an earring shows.

### `gender=` is a preset, not a lock

`gender=woman`, `gender=man` or `gender=neutral` (the default) changes which hair, beard and
brows the name picks from. It never limits what you can write: `` `!{Sam Lee, gender=man, hair=long}` ``
has long hair, and any trait you write wins over the preset.

## The tile

The tile behind the face belongs to the deck. Its words are bare, with no `key=`:

<CraftLab
	label="Sizes, shapes, colors and rings"
	kind="none"
	editMarkdown
	markdown={LAB_TILE}
	size="short"
	hint="Try c9 to c12, or border=c2 on the plain avatar."
/>

| Word | What it does | Default |
|---|---|---|
| `c1` to `c12` | the tile's color, from the same cycle sparks and charts use | picked by the name from `c1`–`c8` |
| `sm` `md` `lg` `xl` | the size: `sm` and `md` sit inside a line of text, `lg` and `xl` stand beside it | `md` |
| `circle` `rounded` `square` | the tile's shape | `circle` |
| `framed` `bare` | a pale tile behind the person, or the bust alone | `framed` |
| `border=c1` … `border=c12` | a ring in that color | no ring |
| `label="…"` | what a screen reader says, when the name is not right | the name |

The tile is a pale tint of its color over white in light and dark mode alike, so dark
clothes never sink into a dark slide. To style every avatar in a deck at once, set the
`avatar:` front matter (`avatar: rounded bare`), or a slide's class (`avatar-square`). An
avatar's own word wins over both.

## In a team-profile roster

Write the avatar on the line where the photo goes, and it becomes the portrait. Avatars mix
freely with real photos and with monograms for people you describe in neither:

```markdown
<!-- _class: team-profile -->

- Ada Okafor
  - `!{Ada Okafor, hair=coily, skin=6}`
  - `Executive Sponsor`
- Marcus Vale
  - ![](marcus.jpg)
  - `Chief Financial Officer`
- Hana Suzuki
  - `Field Engineer`
```

The portrait is an avatar alone on its line, or beside the role. An avatar anywhere else, in
a note that mentions someone, stays where you wrote it. The name is right beside the
portrait, so a screen reader hears it once, not twice.

## What stays as code

A span that opens with `!{` and does not read stays as the code you typed: a value a trait
does not have (`skin=9`, `hair=mohawk`), a word that is not a tile word, or no name.
`lint:deck` warns and lists the values the trait does take. A backslash keeps a valid one as
code on purpose: `` `\!{Ada Okafor}` ``.

In a roster, an avatar that did not draw never becomes the person's role: a broken one stays
as written, and one whose drawings have not arrived yet shows a monogram.

## Where it renders

Everywhere a deck does: the PDF, HTML and PowerPoint exports from the CLI, the Studio, the
Playground and an Export-to-Marp bundle. The drawings load only for a deck that writes an
avatar, so a deck without one pays nothing. The Studio editor does not yet complete trait
names as you type.
