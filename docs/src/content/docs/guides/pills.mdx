A **pill** is a small chip carrying a status, a label, or a piece of
metadata — `` `{STABLE}` ``, `` `on track` ``, `` `2025 Q1` ``. Every pill is drawn
from the same tokens, so a deck reads as one system: structure is shared, and
color is what carries the meaning.

Three ways to get one:

| You write | You get | Reach for it when |
|---|---|---|
| `` `{STABLE}:c2` `` | An **inline pill** — you choose shape and color | The value carries the meaning, anywhere on the slide |
| `` - Row text `on track` `` | A **metadata pill** — the component styles it | The component already has a slot for it |
| `` - Adoption `68%` `at-risk` `` | A **status pill** — the engine picks the color from the word | You are on a chart component with a status slot |

Learn the first one — it works everywhere. Only certain components recognize
the other two, so for those, where you write them matters.

## The brace grammar — a pill you place by hand

Put a label in braces inside **single-backtick** inline code and it renders as
a pill. Shape and color belong to the value, not to the slide — so one list can
carry four different statuses without any variant on the slide itself.

Modifiers follow the closing brace, each introduced by a colon. **Order is
free** — `` `{X}:tag:c4:lg` `` and `` `{X}:lg:c4:tag` `` are the same pill.

### Shape

Lattice draws all eight shapes itself, as a border radius or a clip path on its
own box. None of them is a font character, so a shape looks the same in the PDF,
in the browser, and in an export.

| Modifier | Shape | Use it for |
|---|---|---|
| *(none)* | Capsule | The default status chip |
| `:chip` | Softly rounded | A quieter label |
| `:tag` | Square corners | A filed or categorical label |
| `:tag-bordered` | Square, double stroke | Emphasis without spending a color |
| `:circle` | Circle | **A digit or a single mark** — `` `{3}:circle` `` |
| `:chevron-right` | Right-pointing | Sequence, forward — `` `{STEP 2}:chevron-right` `` |
| `:chevron-left` | Left-pointing | Sequence, back |
| `:diamond` | Diamond | **One or two characters** — `` `{!}:diamond` `` |

`circle` and `diamond` are square boxes, so they hold a character or two and no
more. Put a word in one and `lint:deck` will suggest `:tag` or `:chip` instead.
It only suggests — deck linting never blocks a build.

### Color — `:c1` … `:c12`

Ordinal slots, **not color names**. The same slot is sky blue on `indaco` and
deep red on `burgundy`, so a slot picks a distinct color, never a meaning:

> Never write `:c2` because "green means good." It is not green everywhere.

You never do contrast math. Each slot picks up the palette's categorical fill
and edge, plus the ink Lattice already derived to clear WCAG AA on that fill.

### Size — `:sm` and `:lg`

A pill scales from the surrounding type, so it stays proportional to the row it
sits in. The default size needs no modifier.

```markdown
- Small `{MINOR}:sm:c9` · default `{NORMAL}:c9` · large `{MAJOR}:lg:c9`
```

## What stays literal — plain code is untouched

Plain inline code is untouched. `` `getUserId()` ``, `` `:root` ``,
`` `--accent` ``, `` `[data-mark]` `` and `` `{ ok, scene }` `` all render as
code, exactly as typed. A pill needs a brace pair with no comma inside, which is
what keeps `` `{ ok, scene }` `` looking like the code it is.

**An unknown or repeated modifier falls back to literal rather than being
ignored.** `` `{X}:c13` `` renders as visible code, not as a pill. You catch it
in the first review pass, which you would not do if it quietly drew something.

### Forcing the literal

Put a backslash in front:

```markdown
`\{LIVE}`   renders as   {LIVE}
`\[x]`      renders as   [x]
```

The backslash only escapes what *would* have dispatched, so a regex is safe:
`` `\d+` `` and `` `\[a-z]` `` are untouched and keep their backslash.

**Nothing inside a fenced or indented code block is ever read as a directive.**
Those are not inline code, so the grammar never reaches them.

### Turning the grammar off

One line in front matter turns the whole grammar off. Reach for it on a deck you
did not write, where `` `[x]` `` in prose was never meant to draw anything:

```yaml
---
inline-code: literal
---
```

One slide at a time is `<!-- _class: inline-code-literal -->`. In the Studio it
is **Deck settings · General · Inline pills and marks**. Use the backslash for a
span or two; use this switch for a whole deck.

## State marks — the four checklist discs

The same four markers you already write bare at the start of a bullet draw the
same disc inside inline code, anywhere inline code can go.

| Marker | Means |
|---|---|
| `[x]` | Done |
| `[-]` | Partial |
| `[ ]` | Not started — the neutral open ring |
| `[/]` | Out of scope |

The same four markers work in two positions: bare at a bullet's start for a
checklist row, and inside inline code for a mark in a sentence, a heading, or a
table cell.

Each mark carries `role="img"` and an `aria-label`, so a screen reader says
"done" without any visible text on the slide.

**Only the four exact forms dispatch.** `` `[?]` ``, `` `[!]` ``, `` `[0]` ``,
`` `[X]` `` and `` `[data-mark]` `` all stay literal — the grammar is
deliberately narrow, because `[` also opens a CSS attribute selector, an array
index, and a citation.

### Use brackets for a mark, braces for a pill

Because braces make a pill, `` `{x}` `` would otherwise draw a capsule holding
the letter `x`. The four markers are **reserved** inside braces: they render
literal, and `lint:deck` points you at the bracket form.

## The metadata pill (trailing inline code)

A trailing inline `code` span on a list row becomes a pill automatically — no
modifiers, no grammar:

```markdown
- Throughput target met `on track`
- API latency `at risk`
```

Keep the text to **one word (hyphenated is fine) or two at most**. Pills do not
wrap; a long phrase just makes a wide pill.

## Status pills — the chart vocabulary

Some chart components read a **closed vocabulary of ten status words** from a
trailing inline-code span. Here **the word is the meaning**: you write `at-risk`
and Lattice picks the color from it, so there is no modifier to remember.

```markdown
<!-- _class: progress -->

## Rollout readiness.

- Adoption `68%` `on-track`
- Data migration `41%` `at-risk`
- Security review `12%` `blocked`
```

Ten words, grouped into five meanings:

| Write one of these | Reads as | Draws |
|---|---|---|
| `on-track` · `done` · `live` | Good | The palette's positive color |
| `at-risk` · `warn` | Careful | The caution color |
| `blocked` · `fail` | Bad | The alarm color |
| `pilot` · `decision` | Noted, in flight | The informational color — also the fallback |
| `deferred` | Parked | A gray, deliberately quiet |

Color is not the only channel. In the print and accessibility palettes each
group also carries its own glyph, so the reading survives grayscale and
color-vision deficiency.

### Where the status word goes

The position differs per component — it is **not** a universal slot:

| Component | Where you write it | What it colors |
|---|---|---|
| `progress` | Second trailing span on the row — percent first, status second | A pill |
| `timeline-list` | Trailing span on the event's lead line, after the title | A pill |
| `kanban` | Trailing span on the card's nested lane bullet | A pill, and the card |
| `gantt` | A token on a task bullet | The bar |
| `state-chart` | Trailing span on the state line | The badge |
| `slope` | Trailing span on the entity's lead line | The chart mark |

`progress`, `timeline-list` and `kanban` draw an actual status pill. `gantt`,
`state-chart` and `slope` read the same ten words but color a bar, a badge, or a
chart mark instead.

One word changes meaning on `gantt`: it paints `live` in the informational
color, not the positive one. On a schedule, `live` is work still running and
`done` is work finished, and the two bars need to look different.

### Two ways a status word trips you up

**Spell it lowercase and hyphenated.** Lattice does not fix up your spelling:
`at risk` (with a space) and `At Risk` (capitalized) are not in the vocabulary,
and neither is caught for you. Only `gantt` and `kanban` forgive capitals —
`AT-RISK` colors a kanban card exactly as `at-risk` does, and the pill keeps
your spelling. Everywhere else, write it lowercase.

**A word Lattice does not know still draws a pill.** In `progress` and
`timeline-list` it falls back to the informational color — the same one `pilot`
and `decision` use — so a typo looks like a deliberate verdict, and a reviewer
reads it as one. Only `gantt` warns about an unknown token. On the others, check
each status word against the ten above before you ship the deck.

### What the status vocabulary cannot do

The ten words reach only those six components. A `{LABEL}` pill goes anywhere,
takes eight shapes and twelve color slots — and still cannot say "this is
failing," because the status colors are not among the twelve.

So there is no supported way to put a red status pill on a `cards-grid` slide.
Do not reach for whichever `:cN` slot looks red in your theme: it is a different
color in the next one, which is the whole reason the slots are numbered rather
than named.

## Date pills — positional, and never parsed

A date pill is **positional and per-component**. Nothing is ever date-parsed:
the engine does not recognize `2025 Q1` as a date, it just styles whatever sits
in that slot. Write `banana` in the leading slot of a `timeline-list` row and
you get a pill reading "banana".

| Component | Where the date goes |
|---|---|
| `timeline-list` | **Leading** span, before the title — `` 1. `2025 Q1` Framework approved `` |
| `regulatory-update` | Last nested bullet, on its own |
| `roadmap` | Trailing span on a phase column header |

`timeline-list` is the one to watch, because its date **leads** the line where
most components put metadata at the end. Write the date after the title and
`timeline-list` styles it as a status pill instead.

## Pills you get without writing one

A `glossary` slide grows a range pill in its heading by itself — the first
letter of the first and last term, so a list running Consent to Processor reads
`C – P`. You write nothing, and it follows the terms as you edit them.

## Where a pill can go

Anywhere inline code can: a heading, a paragraph, a blockquote, a table cell, a
footer, or a list row — including mid-sentence.

A `list-tabular` row has two limits:

- The **`spec`** variant addresses its two codes by position, which cannot see
  a pill. A `spec` row whose trailing chip is a pill works; one whose *key* is
  a pill does not.
- **Two trailing items in one row overlap** — `` 1. Name `META` `{PILL}` ``.
  That is grid behavior, not a pill limitation: two plain `` `code` `` values
  do the same. Put one value in the trailing slot.
