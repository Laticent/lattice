# The Specimen Book — specimen galleries + the Playground as their reader (2026-07-05)

> Provenance: winner of a five-design competition run 2026-07-05 (candidates:
> Curator/Specimen Book, Instrument, Atlas, Minimal Spine, Showcase). Each
> candidate went through five critique-and-revise iterations, then a red team,
> an inversion pass, and an independent checker that verified every
> load-bearing claim against this repo (16/16 CONFIRMED for this design).
> Three judges (user lens, maintainer lens, design-critic lens) each ranked it
> first at 9/10. A separate UX-heuristics scoring (Nielsen's ten +
> responsiveness + wayfinding) also ranked it first (8.65/10), with its one
> sub-8 criterion — recognition over recall — noted as the candidate for an
> Atlas-style visual-grid graft later; that graft is NOT in scope here.

## §0 Amendments from user review (these supersede the matching clauses below)

The user reviewed all five designs as interactive prototypes and picked this
one, with a direction: the Playground should feel like a **precursor to
entering the Studio** — same chrome, same primitives, a taste of the Studio's
depth — while staying the stateless quick-try surface (no deck CRUD, no AI,
no persistence beyond the existing scratch draft).

1. **Deck setup stays, in both modes.** `DeckSetupSheet` (front matter:
   finish, palette-managed theme handling) and the debug-overlay toggle
   survive the redesign and are reachable from Read mode as an Inspector-lite
   — finish and debug apply to whatever deck the reader is walking. The
   debug overlay is a first-class learning tool next to stress-test slides.
2. **The gallery drawer stays, unified as two shelves.** `GalleriesSheet`
   becomes the reader's deck source: shelf one "Components" (the 56 specimen
   decks), shelf two "Full decks" (the jargon showcase + the 12 generated
   family surveys). One Walk bar, one stepping model, for both shelves —
   walking a full deck uses slide-index positions where no `galleryPlan`
   exists (captions come from the plan only on specimen decks).
3. **Reset stays, scoped to the editor.** Read mode is stateless, so Reset
   lives only in the Edit escape hatch as "Reset to this slide's example,"
   with the §4 arm-to-confirm + backup + undo-toast guards unchanged.
4. **"Insert skeleton" is REMOVED, replaced by "Open in Studio."** Skeleton
   insertion is an authoring affordance the Studio already does properly
   (InsertComponent). The Playground instead offers a one-click handoff that
   carries the current draft into a new Studio deck via a one-shot
   `lattice-studio-handoff` key `{ md, from: 'playground', ts }`, consumed by
   the Studio on apply (mirror of the §4 Playground handoff contract,
   including park-on-decline). Every §4/§6 clause that names "Insert
   skeleton" (its guard, its `readerComponent` fallback, its arm-to-confirm
   copy) now applies to Reset only; the skeleton button and its code path are
   deleted in PR 5. The Studio-side consumer is a small addition to PR 6 (or
   its own follow-up slice if the Studio diff wants isolation); until it
   lands, the button ships hidden behind the handoff key's absence check.
5. **Tour gains one step** for the Studio handoff ("outgrow the Playground →
   continue in the Studio"), replacing nothing — the §4 tour rewrite already
   deletes the stale Drawing Board/Workbench outro.
6. **The mode is named "Explore," not "Read," and walk steps are labeled
   chips, never single letters.** The user's framing, adopted verbatim: the
   surface's job is not that people *read* the deck — it is to whet appetites,
   show what is possible, deliver visual eye candy. Every "Read mode" below is
   the same mechanism shipped under the **Explore** label (UI copy, tour copy,
   command-menu entry all say Explore; internal keys may keep `read`). The
   Walk bar's per-slide affordances are **full-word labeled chips** — "Title,"
   "Default," the variant's own name, "Stress test," "Anti-patterns," "See
   also" — at accessible target sizes with AA contrast; single-letter dots are
   a named anti-pattern for this surface (cryptic recall-over-recognition,
   sub-AA targets). Verified against the on-brand interactive simulation the
   user reviewed before accepting this doc.

Everything else below stands as written.

## 1. Name + thesis

**The Specimen Book.** The generated per-component gallery deck is the product; everything else serves it. The manifest becomes a *specimen contract* — every gallery slide's own copy states what it demonstrates, the way a type-specimen book shows a typeface by talking about itself — and the Playground becomes a beautiful reader over those decks: walking through components means literally stepping through their gallery slides (title → default → each variant → stress → compositions → anti-patterns → see-also), with the editor demoted to an escape hatch you drop into when you want to touch the markdown. (One naming note up front: the docs site already ships a surface called Specimen — `docs/src/components/Specimen.astro` + `docs/src/playground/specimen.js`, the component-page flip-to-edit preview. It keeps its name and its job; every NEW artifact in this design says **voice** or **plan** — `specimenVoice` flag, `plans/` asset dir — so grep never conflates the two.)

## 2. Gallery content contract

**The specimen voice (replaces the fictional universe in per-component galleries — hybrid at repo level).** Per-component galleries switch from the "Signal→Strategy" fiction to didactic specimen copy: the slide demonstrates the component *by describing it*. `big-number`'s sample headline is about what a single dominant number does to an argument; the `dense` variant's copy says what `dense` changes and when to reach for it. Rationale: these decks are documentation — the fiction documents the fiction, not the layout, and a reader stepping slide-by-slide (§4) must answer "what am I looking at?" without leaving the slide. **Where the teaching goes (the budget-survival rule):** element copy *demonstrates* within its word budget; the *caption* channel (footer + Reader chrome, §2.5) carries the didactic sentence. Didactic prose is wordier than fiction, so the voice contract explicitly forbids inflating element copy to teach — the caption teaches, the elements show. The six HARD RULE #8 hand-curated decks (master `test/integration/baseline-decks/gallery.md`, `examples/gallery-jargon.md`, `examples/chart-family-coverage.md`, `examples/content-capacity.md`, `design/design-system.gallery.md`, `design/forms.gallery.md`) **keep the fiction** — they demonstrate real-deck usage, a different job. That is the hybrid: specimen voice for per-component + generated bucket galleries, fiction for the curated six.

**Manifest changes** (`lib/components/manifest.schema.json` + `validate()` in `lib/components/index.js`):

1. **`variantDocs` coverage becomes total — a `validate()` error.** Today `validate()` only checks keys ⊆ `variants[]` (index.js:831), and `renderGallery` silently *drops* any variant without docs (`variants.filter(v => m.variantDocs[v])`, `tools/build-component-docs.js:320–322`) — which is exactly how `map`'s `world` became invisible. New rule: every member of `variants[]` MUST have a `variantDocs` entry. Safe to hard-gate on day one: measured across all 56 manifests, exactly **one** violates — `chart/map` (`world` in `variants`, no `variantDocs.world`) — and PR 1 fixes it as its proof case. **Axis-default rule:** where a variant is the `default` of a `variantAxes` entry (as `world` is for map's Basemap axis), its specimen slide documents the *axis and the toggle* — never a re-render of the Default slide; anchored in `design/editorial.md` §Specimen voice. **The gate lands with its authoring path** (`loadAll()` throws on `validate()` errors, index.js:1074–1077, and eight docs pages import it — a hard gate that strands a contributor mid-migration breeds junk entries): the error message links a conforming `variantDocs` template; §Specimen voice defines the interim rule for entries added to not-yet-migrated components (short, honest, budget-clean — the migration PR revoices them, and `VOICE_DEBT` already names the component); and the contract test rejects placeholder-shaped content (`TBD`/`TODO`/lorem patterns, empty captions) so an unblock hack can never reach a committed PDF.
2. **`stressDoc` replaces `stressSample`** — `{ caption, sample }` (`caption` = one sentence naming the limit shown). `validate()` accepts both spellings during migration; the string alias is removed when migration completes. **Required wherever the manifest declares `capacity`** — but NOT a `validate()` error on day one: 15 manifests declare `capacity` and 11 lack a stress sample; hard-gating would be a flag day. Enforced by the named debt list below, reaching zero by PR 4 — then graduated into `validate()` as a cheap final commit (0 violators by construction).
3. **Mechanical stress honesty — with a band that is never empty.** Where `capacity` is present, `countPrimaryCollection` (`lib/authoring/lint-core.js:232`, re-exported :1464 — the counter the capacity contract already uses) applied to `stressDoc.sample` must land in the **integer band `[min(soft+1, hard), hard]`** on `capacity.axis` — equal to `(soft, hard]` when `soft < hard`, and exactly `{hard}` when `soft == hard` (cards-stack declares soft=4, hard=4; a half-open band would be the empty set and force a bogus exemption — the closed form makes its at-the-ceiling n=4 stress slide legal, as it should be). The default `sample` must land **≤ `capacity.soft`** — measured today, all 15 capacity-holders pass, so this is a hard gate from day one with 0 violators; `sweet` is *advisory guidance* in §Specimen voice, never gated (three defaults sit between sweet and soft today, legitimately). Current stress slides measured against the band: kanban (n=4 ∉ [6,6]), agenda (n=6 ∉ [7,7]), q-and-a (n=5 ∉ [6,6]) fail; cards-stack passes — the three failures are **`band` debt entries** (rule below), fixed by their migration PRs. Enforced in the new unit test, not check-ownership.
4. **Word budgets become blocking — via the debt list, because the tree is red today.** `density` stays advisory for deck authors (deliberate, 2026-06-30 decision), but the new test runs **`elementWordCounts`** (`lib/authoring/prose-budgets.js:84`, exported :195) over every `sample` / `variantDocs.*.sample` / `stressDoc.sample`: default + variant samples ≤ `density.soft` per element; stress sample ≤ `density.hard`. **Measured honestly — compliance, not just field presence: 53 violations across 19 of the 26 density-bearing components exist right now** (q-and-a solo at 40 words vs soft 12; compare-prose vertical at 54 vs 20; kpi spotlight at 33 vs 8). So the rule binds *immediately* for every component not carrying a `budget` debt entry, and the 19 offenders enter `VOICE_DEBT` by name; their migration PR shortens the copy (per the budget-survival rule above) and deletes the entry. **Density-integrity invariant:** `density` values are tool-derived, never prose-fitted — a migration PR may add or change `density` only at `tools/calibrate-density.js` output, with the calibration artifact committed alongside; when specimen copy can't fit `soft`, the copy shortens or the component goes to `VOICE_EXEMPT` with a reason. Raising `density` in the same PR that adds the prose it excuses is a named blocked pattern (§Specimen voice + PR checklist) — these budgets feed review-core's advisory for *real deck authors*, and loosening them to pass our own gate would corrupt that contract. Coverage plan: `density` exists on 26/56; each migration PR declares it for its group's `item`/`row`-axis components (calibrated); unmeasurable components go on the exemption list with a reason.
5. **Self-narration rules** (prose contract, anchored in `design/editorial.md` §Specimen voice): (a) the default sample's H2 states the component's job as a complete declarative sentence; (b) a variant sample's copy names what the variant changes; (c) captions are surfaced *on the artifact*. **Caption sources are total — every `galleryPlan` kind names one:** title + default → the manifest's existing `description` field (verified present; map's reads "A world-countries (or US-states) basemap that fills regions by value…"); variant → `variantDocs.caption`; stress → `stressDoc.caption`; composition → the existing `Composition: <modifier> · <name> <modifier>` text (:315); anti-patterns / see-also → fixed strings. On the PDF, variant/stress footers become `"${label} · ${name} ${v} — ${caption}"` at the `renderGallery` call sites (:340/:347); the default slide's footer stays short (its H2 already self-describes). **Caption footers are gated on `specimenVoice`** — an unmigrated manifest renders today's short footers byte-for-byte, so the mechanism lands inert in PR 1 and each migration PR's regeneration turns it on for exactly the decks whose rendered output that PR's visual fan-out reviews (this also halves the committed-PDF churn: one regeneration per deck, not two). **Footer truth, measured:** `injectFooter` (:379) no-ops on a hand-set `_footer:` (:380) — zero manifest samples carry one today, and the contract test bans it outright (0 violators, hard gate day one), so the guard can never silently swallow a caption. **Silent-slide caveat, stated not hidden:** the anchor trio's samples and every title slide carry `silent`, which suppresses footer chrome; their caption footer exists in the `.md` (committed `closing.gallery.md:19` today) but does not render — by those components' own contract. For those slides the narration lives in the sample COPY (§Specimen voice requires self-identifying copy) plus the Reader's chrome caption (§4).
6. **`specimenVoice: true` — the machine-attestable voice flag** (new boolean schema field, default absent). Prose *quality* cannot be machine-judged, so it isn't pretended to be: the flag asserts "this manifest's samples passed the migration PR's visual-review fan-out," is set **only** in that PR, and gives the debt list a real predicate. Setting it on an unmigrated component makes its debt entry stale and fails — flag flip and debt deletion are **forced into the same reviewed diff**, where the fan-out evidence sits.

**Enforcement summary.** Rule 1 → `validate()` error from PR 1 (0 violators after the map fix). Rules 2–5 (footer ban and default-≤-soft included, both 0-violator hard gates) + rule 6's flag consistency → new **`test/unit/components/gallery-contract.test.js`** (beside `component-manifest.test.js`, `accent-contract.test.js`) in the `npm test` inner loop. Slide-count integrity → existing `expectedGallerySlideCount()` (`build-component-docs.js:418`) + the integration suite; `stressDoc` counts exactly as `stressSample` does today.

**Migration path for 56 components — a NAMED debt list, not a count** (the #20/#22 allowlist pattern, not the #21 count-ratchet: a count permits offsetting regressions; names don't):

- `VOICE_DEBT` — entries `{ name, missing: ['stressDoc'|'density'|'voice'|'budget'|'band'], since }`, every item a machine predicate: `stressDoc`/`density` = field absent, `voice` = flag absent, **`budget` = a named sample element exceeds its `density` budget** (19 components today, 53 violating samples), **`band` = stress count outside the closed band** (3 today: kanban, agenda, q-and-a). Measured at PR 1: 41 stressDoc / 30 density / 56 voice / 19 budget / 3 band. The test fails if a listed component *newly* violates something not in its entry, if an unlisted component violates anything, **or if an entry is stale** (predicate now passes) — the list can't rot in either direction. Each migration PR deletes its bucket group's entries. Empty by PR 4.
- `VOICE_EXEMPT` — components that genuinely cannot carry a rule (no countable axis for `density`; a single-element anchor with no meaningful stress state), each with a one-line reason. Stale-entry-fails applies here too.

No flag day, no half-migrated ambiguity: a component is conforming, in debt by name, or exempt with a reason — and the test knows which.

## 4. Playground UX — the Reader

**Two modes, one toggle: `Read` | `Edit`** (shadcn `pill-tabs`, toolbar-left, persisted). In Read mode the current component's *generated gallery deck* fills the width, one slide at a time, with a **Walk bar** beneath. Edit mode is today's editor+preview split. **Source-of-truth rule: Read mode NEVER writes `lattice-docs-pg-source`.** The one crossover is "Edit this slide": it copies the gallery slide's markdown into the editor and flips to Edit — arm-to-confirm (Studio pattern) when the draft isn't pristine; same guard on "Reset to example" / "Insert skeleton". **Any action that overwrites the draft first parks it under `lattice-docs-pg-source-backup` and raises an undo toast** — a confirm alone is not sufficient protection for the only copy of user content.

**Two component states, one rule each — the sync collision dissolved.** The design names two variables that today are conflated in `currentName`: **`draftComponent`** (derived — `detectComponent(source)`, may be null) and **`readerComponent`** (persisted `lattice-docs-pg-component`, always resolves to a catalog name). `syncPickers` (`PlaygroundApp.tsx:326`) mutates ONLY `draftComponent`: the missing clear case (today `if (!det) return`, :328) makes detect→null show the picker in a neutral "no component in draft" state with the Variant select disabled — it **never writes the persisted pointer**, so a pasted multi-slide deck or plain-markdown draft cannot starve Read mode or wipe the remembered component on mount. `readerComponent` changes only on explicit pick, handoff, or URL. Read mode renders `readerComponent`; Edit-mode picker prefers `draftComponent` when non-null.

**The handoff — one key, ALL three writers, consumed on APPLY.** Three surfaces write `lattice-docs-pg-source` unguarded today: (a) `specimen.js` `openInPlayground` (:194), also serving (b) the docs-reference `[data-open-playground]` buttons (`ComponentDocsView.tsx:185–187` via `specimen.js:215–219`), and (c) `seedPlaygroundSource` in `landing-handoff.ts`. PR 5 flips all three to a one-shot `lattice-docs-pg-handoff` entry `{ md, from, ts }`. The Playground applies it automatically when the draft is pristine, else shows arm-to-confirm — and **the key is consumed on apply, not on load**: decline or dismiss parks it with a persistent "unapplied edit from `<name>`" affordance, so user-authored Specimen edits are never destroyed by a "no". An already-open tab consumes on `visibilitychange`/focus; the `ts` lets a days-old handoff name its origin instead of firing context-free. **Pristine is an insert-time fingerprint, never catalog equality:** every seed/reset/skeleton/apply path records a hash of what it wrote under `lattice-docs-pg-inserted-hash`; pristine ⟺ current source hashes to it. (Equality against the *current* catalog would break fleet-wide on every voice-migration deploy — an untouched old-bytes sample would suddenly read as a dirty draft.) In PR 6 the docs-reference buttons (b) become Read deep links `?c=<name>&view=read&s=variant:<v>`; (a) and (c) stay on the handoff key — they carry content, not a pointer.

**Mode + target on load — one precedence rule, one fallback function** (both unit-tested in `docs/src/lib/playground-controller.ts` — pure, DOM-free, already exports `SOURCE_KEY` + `detectComponent`): view = incoming handoff → Edit; explicit `?view=` → that; persisted `lattice-docs-pg-view` → that; **else pristine/empty draft → Read, non-pristine → Edit** (a constant Read default would ambush every existing editor user, collapse their pane, and put a draft-replacing CTA in front of them). Target = handoff > URL > localStorage, then **every externally-persisted target resolves through one tested fallback**: unknown `c` → first catalog component with the picker opened + notice; unknown `s`/`v` (renamed variant, stale bookmark) → that component's title slide + non-blocking "that variant no longer exists" notice; never a blank frame or a throw. Unit tests feed unknown/renamed keys through load.

**Where the gallery decks come from — one plan function, zero drift, a defined miss path.** `renderGallery` (:318) is refactored around a new exported **`galleryPlan(m)`** in `build-component-docs.js` (joins module.exports :568 with `injectFooter`): ordered slides `[{kind: 'title'|'default'|'variant:<key>'|'stress'|'composition:<mod>'|'anti-patterns'|'see-also', caption, md}]` with the §2.5 caption-source table making `caption` total; `renderGallery` becomes `galleryPlan(m).map(s => s.md).join(...)` — PDF, slide map, and Reader consume the same walk, so the sequence cannot fork; a unit test asserts `galleryPlan(m).length === expectedGallerySlideCount(m)` for all 56. **Delivery:** the plan JSON is emitted by `docs/scripts/sync-playground-assets.mjs` (which computes the sha256 content hash over every staged byte, :133–140, and already imports `collectGalleryAssets` :46) via the same `createRequire`+`loadAll` pattern `playground.astro` uses (:31–34), writing `plans/<name>.json` into the staged tree — a prose change changes the bytes, the hash, the URL. The Reader lazy-fetches from `assetBase() + 'plans/<name>.json'` (`asset-version.mjs:80`), prefetching the next component. **The 404 path is designed, not hoped away:** the stager rewrites the whole versioned tree each deploy, so a tab open across a deploy WILL miss; on fetch failure the Reader re-checks the page's current asset version and surfaces a one-tap "site updated — reload" toast (never a dead Next button); the plan-consumption unit tests include the 404 case. Rendering goes through the **existing** pipeline (`window.LatticePlayground.render` → `deck-preview.js` → `sanitizeSlideHtml` on both patch and srcdoc paths, :263/:365) — zero new preview builders, zero new `SANCTIONED_PREVIEW_BUILDERS` entries, #22 untouched.

**Reading, not scrolling — degradation-safe stepping.** Read mode toggles a reader class on the persistent filmstrip iframe (chrome-level class + CSS injected with the runtime scripts *after* sanitization, like the FIT agent — no HTML enters the frame): non-current slides dimmed, one page per step. **The baseline step is programmatic `scrollTo({behavior:'instant'})` computed from the FIT agent's *scaled* geometry** (deck-preview.js:96–105 — transform scales the paint, not the layout box, so snap points must derive from painted heights); `scroll-snap-type` CSS is a feature-detected *enhancement*, never the mechanism — on engines where mandatory snap fights programmatic scroll (iOS WebKit), stepping still lands exactly. Edit mode keeps the plain filmstrip.

**Walkthrough model.**
- *Within a component:* Walk bar shows `‹ Prev · slide 3 of 9 · Next ›` + a caption line fed by `galleryPlan` — always shown (the only narration on `silent` slides, and the legible channel at phone width). Keyboard ← / →; thumb-sized targets at 390.
- *Across components:* on the last slide `Next` becomes **"Next component: <name> →"** (catalog order: bucket, then A–Z); Shift+←/→ jumps components. "Walk through all components one by one" is one continuous read. "Start walkthrough" joins the site `CommandMenu` (`docs/src/components/site/CommandMenu.tsx`).
- *Variants:* in Read mode the Variant select is a jump list — picking `dense` snaps to `variant:dense` (select and Walk bar both derive from `galleryPlan`). In Edit mode it keeps today's behavior.
- ***Mobile legibility — the thesis survives 390px honestly.*** A 1280×720 slide at ≤390px is a *preview*, not a reading surface (~0.28 scale); pretending otherwise would be the design's own #23 violation. At ≤560px the Walk bar caption gains a **"Read this slide's copy" disclosure**: a parent-DOM panel (plain React text, no frame, no #22 surface) rendering the current plan slide's text content — headings, items, captions — at body size, extracted from `galleryPlan.md`. The slide shows the *form*; the transcript carries the *words*; the chrome caption narrates. Phone users read everything, just not off the thumbnail.

**Selection/search redesign** (each confirmed jank fixed at its source):
- `ComponentPicker.select()` stops clearing the query (`ComponentPicker.tsx:39–43`); query + lens lift into persisted state owned by `PlaygroundApp` (picker controlled). Reopening restores the last search with the current component checked.
- `syncPickers` clear case per the two-state rule above — stale component impossible, persisted pointer untouched.
- Variant snap-back: picker sync on the same 220ms debounce as the render, overwriting a user-chosen variant only when parsed `_class` tokens actually changed.
- "Reset to example" / "Insert skeleton" read `detectComponent` at click time; **when it is null they fall back to `readerComponent`, named in the arm-to-confirm** ("Insert the `kpi` skeleton?") — defined behavior in exactly the state the clear-case fix creates, never a dead button.
- `.pg-status` hidden ≤560px: render errors light a badge on the Walk bar / tab strip opening the full message in a `Sheet`.

**State model.** localStorage: `lattice-docs-pg-source` (existing; never written by Read mode; every writer guarded + backed up), `lattice-docs-pg-source-backup`, `lattice-docs-pg-inserted-hash`, `lattice-docs-pg-handoff` (one-shot, consumed on apply), `lattice-docs-pg-component`, `lattice-docs-pg-search`, `lattice-docs-pg-lens`, `lattice-docs-pg-view`, plus existing palette/mode/split/tour keys. **URL params are NEW — the playground reads none today** (verified: no `URLSearchParams`/`location.search` in `playground.astro`, `PlaygroundApp.tsx`, or `playground-controller.ts`); PR 6 introduces the scheme whole: `?c=<component>&view=read&s=<plan-kind>` (`s` is the **stable kind key** — `variant:dense`, `stress` — never an index, so links survive variant *additions*; *removals/renames* resolve through the fallback function above) and `?c&view=edit&v=<variant>` (guarded seed). Written via `replaceState` while walking.

**Responsive.** 1440: Read mode collapses the editor pane via the existing `useSplit` API (`collapse`, `ui/split.tsx:183`); Edit is today's split. 820: Edit keeps the Edit/Preview tabs; Read is single-pane. 390: reader-first — Walk bar pinned bottom, transcript disclosure, full-width picker trigger. Evidence at all three widths via `tools/screenshot.js` (#23).

**Tour.** `docs/src/playground/playground-tour.js` is rewritten for the reader (picker → Walk bar → variant jump → Edit escape hatch → Galleries → Deck setup); the stale Drawing Board/Workbench outro (:69) is deleted. **Every step declares the mode (and pane) its target needs, and `onReveal` switches the surface to it before highlighting** — the most common first visit arrives via "Open in Playground", i.e. a handoff forcing Edit, where Read-mode chrome isn't mounted; without mode-aware reveal the tour would spotlight nothing. A unit test walks the step list against both modes' mounted element ids and fails on any unreachable selector; the handoff entry path is a named manual drive in PR 6. The shared engine `guided-tour.js` is **untouched** (Studio-succession freeze). Production-only, first-visit, same prefs key.

## 7. Risks & open questions

- **Composition slides can't self-narrate their modifier** — they reuse `sample`. Mitigation: the composition footer (:315) names the modifier; a per-modifier `compositionNote` is a cheap follow-up. Open question for the user.
- **`silent` slides never render their caption footer.** Accepted: their own contract bars footer chrome. Narration = self-identifying copy + the Reader's chrome caption; PR 2's anchor-trio rasterize check confirms no visual change.
- **Specimen voice within existing budgets is real authoring work** — 19 components must *shrink* copy while becoming didactic. Mitigation: the caption channel carries the teaching (element copy only demonstrates); where a component genuinely can't fit, it goes to `VOICE_EXEMPT` with a reason — never a quiet `density` bump (blocked pattern, §2.4). If exemptions exceed a handful, that's a signal to revisit budgets *via the calibrator*, surfaced to the user as its own decision.
- **`specimenVoice` attests process, not prose quality.** The stale-entry check forces flag + debt deletion into the fan-out-reviewed diff; the flag makes the record reviewable, the fan-out judges the prose.
- **`galleryPlan` refactor risk**: PR 1 commit A lands byte-identical with the committed tree as oracle; the map fix and per-group caption switch-ons are the only intentional deltas, each pinned by page-count + plan-length assertions and reviewed by that PR's fan-out.
- **Hall-of-mirrors sameness across 55+ decks.** Editorial §Specimen voice mandates concrete, varied framing; the per-PR fan-out scores exactly this; the curated six keep narrative contrast.
- **`countPrimaryCollection` is approximate** for some layouts. The band check applies only where `capacity` is declared; a genuine mismatch moves the component to `VOICE_EXEMPT` with the reason.
- **iOS Safari stepping**: cannot be verified from this sandbox. Per #23 it ships **UNVERIFIED** — but degradation-safe (instant scroll from scaled geometry is the baseline; snap is enhancement) and **scheduled**: PR 6 links a tracked issue with an owner and a verify-by date. UNVERIFIED is a work item, not a permanent disclaimer.
- **Handoff-guard regression risk**: pristine drafts auto-apply (identical UX on the common path); the fingerprint model is immune to catalog rewrites; unit tests + manual drives of all three flows named in PR 5.
- **Migration authoring cost** (56 components of prose) is the big line item — and the product, per the thesis. Three PRs, named debt, one fan-out per slice.

**Rejected attacks** (red-team points answered with evidence rather than design change):
- *"7 defaults fail the at-sweet rule"* — that reading is retired, not rebutted-by-wish: the gated rule was and is ≤ `soft`, and **all 15 capacity-holders pass it today, measured**; `sweet` is explicitly advisory in §Specimen voice. The gate ships with 0 violators.
- *"cards-stack forces a bogus VOICE_EXEMPT forever"* — no: the closed band `[min(soft+1,hard), hard]` makes soft==hard mean "stress at exactly the ceiling"; cards-stack's n=4 stress slide **passes today**, measured. No exemption needed.
- *"Double PDF churn is waste"* — accepted in substance, dissolved in structure: caption footers now gate on `specimenVoice`, so every deck is regenerated exactly once, inside the PR whose fan-out reviews it. The separate footer PR no longer exists; there is nothing left of this attack to reject.

## 8. Why this is 10/10

Every brief item lands with an automated gate you can point at — and every gate arrives with its violator count *measured as compliance, not field presence*. Variant coverage is a `validate()` error the day PR 1 lands because the tree has exactly one violator and PR 1 fixes it (`chart/map`, whose `world` variant is silently dropped by the generator's own filter at build-component-docs.js:320) — and the gate ships with its authoring path, so it can't strand a contributor into committing "TBD". Word budgets are blocking with the truth on the table: 53 violations across 19 components exist today, so they enter `VOICE_DEBT` under a mechanical `budget` predicate whose stale-entry check makes both regression and unrecorded progress test failures; the rule binds immediately everywhere else and everywhere, by PR 4. The stress band is never vacuous (`[min(soft+1,hard), hard]` — cards-stack's at-ceiling slide passes, measured), the default-≤-soft gate has 0 violators (measured), and `density` can only ever be loosened by the calibrator, never by deadline pressure. Bucket galleries cannot drift because the md-drift test **already in the tree** (`bucket-galleries.test.js`) asserts on-disk equals `composeBucketGallery` output. The walkthrough cannot diverge from the PDFs because both consume the same exported `galleryPlan(m)` — staged by `sync-playground-assets.mjs` *inside* the existing content hash, with the 404 path unit-tested rather than undiscovered in production. Every rendered footer ships through a fan-out because captions switch on per-deck inside the migration PR that reviews that deck — which also halves the committed-PDF churn. The Playground fixes each confirmed jank at its named line (`ComponentPicker.tsx:39`, `PlaygroundApp.tsx:326`'s `if (!det) return`) under a two-state model that makes the clear-case fix and the persisted component provably non-colliding; closes all three draft-clobber paths with an apply-consumed, fingerprint-guarded, backup-and-undo handoff; and survives its own success — catalog rewrites can't dirty pristine drafts, renamed variants can't blank shared links, a deploy can't kill a mid-walk tab, and the phone user gets the words at body size instead of a 0.28-scale promise. Zero new preview builders, zero new #22 sanctions, zero edits to freeze-shared tour machinery, all 13 buckets scheduled, one honest UNVERIFIED (iOS touch) shipped degradation-safe with an owner and a date. If any of those claims is false, a gate in the merged tree fails; that is the falsifiability the boardroom bar demands.
