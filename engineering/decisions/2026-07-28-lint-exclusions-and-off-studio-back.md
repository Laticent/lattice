# Lint exclusions earn their reasons, and back works off the Studio too

**Date:** 2026-07-28
**Status:** shipped
**Closes:** #1223
**Follows:** `2026-07-28-back-not-close.md`

---

## 1. Every lint exclusion says why it exists (#1223)

**The rule:** nothing but vendor code, generated code, or source a standard parser cannot
read may be excluded from lint.

`biome.json` had **29 exclusions and zero reasons.** Nothing distinguished *"generated,
generator at `tools/build-playground.js`"* from *"we gave up on this one"*, and nothing
noticed when an entry stopped matching anything.

Two failed the rule and both are instructive:

- **`docs/src/components/ui`** — 31 tracked files of *house source*. shadcn is
  copy-in-and-own, not a dependency: six of those files carry in-tree
  `DEVIATION from the vendored shadcn base` blocks citing real issues, and two
  (`panel.tsx`, `pill-tabs.tsx`) are wholly house-authored. `panel.tsx` grew by **222
  lines** during the drawer work without once passing through `npm run lint`.
- **`examples/**/*.json`** — matched **zero** tracked files. Dead, and silent by
  construction: an exclusion that covers nothing can never announce itself.

A third case needed a category the rule did not have. `.claude/workflows` is
hand-written, house-authored, and load-bearing (HARD RULE #27's gate reads it) — but
Biome *cannot parse it*: Workflow scripts run inside an async wrapper with injected
globals, so their top-level `return`s are legal for the runtime and a hard parse error
for a standard parser. **House source in a non-standard dialect** is a third class, and
the rule now says so.

### What shipped

`biome.jsonc` — `.jsonc` purely so each entry can carry prose above it — with a class per
exclusion: `dependency` · `build-output` · `transient` · `vendor` · `not-code` ·
`` generated by `<path>` `` · `unparseable: <why>`.

`checkLintExclusions` in `tools/check-ownership.js` keeps those statements true, in the
shape of `SANCTIONED_MARGINS` / `SANCTIONED_PREVIEW_BUILDERS` / `SANCTIONED_LAYER_BLOCKS`
(HARD RULES #20, #22, #26) — the lint config was the one allowlist in the repo with
**neither** a justification nor a staleness check. It fails on:

1. an exclusion with no reason;
2. a reason whose class is unrecognized;
3. a named generator that does not exist;
4. an entry matching **zero tracked files** — except `dependency` / `build-output` /
   `transient`, which are legitimately absent from a clean checkout.

All four were demonstrated to fail before being kept, using the real dead entry from the
issue for the staleness case.

### What linting the directory actually found

18 diagnostics, 12 mechanical. The six manual ones were worth the exercise:

| finding | fix |
|---|---|
| unused `React` namespace import ×2 | deleted (modern JSX transform) |
| `breadcrumb.tsx` — `role="link"` with no `tabIndex` | **DEVIATION**: the current page is not a link. Dropped `role="link"` + `aria-disabled`; `aria-current="page"` is the whole of what AT needs |
| `breadcrumb.tsx` — `useSemanticElements` | same fix, same cause |
| `use-resizable-split.ts` — extra dep ×2 | `biome-ignore` with a reason: `configKey` is a **re-run trigger**, documented as such in that file's own header, and removing it is behavior loss |

The a11y pair is the payoff: a keyboard-unreachable `role="link"` had been sitting in a
shipped component, invisible because the folder was excluded.

**Verified** by planting a violation in `panel.tsx` and watching `npm run lint` fail — it
would have passed silently before. Coverage went 1216 → **1249** files.

## 2. Back closes off-Studio sheets too

The guard shipped for the Studio's drawers, and `FeedbackSheet` is a `PanelSheet`, so it
registered from day one. The raw `Sheet`s around it did not. The result was a **mixed
stack**: back closed the feedback sheet, and the next back left the site with the nav
sheet still open underneath it.

A mixed rule is worse than either rule applied evenly, so the site nav, the Playground's
Deck-setup and Galleries sheets, and `MetricDetail` now register too. `MetricDetail`'s
phone branch had to become *controlled* first — it was an uncontrolled Radix sheet with
only a `SheetTrigger`, and an uncontrolled sheet cannot tell the guard whether it is open.

`useIsPhone` moved from `components/ui/panel.tsx` (private, one consumer) to
`lib/use-breakpoint.ts`. Four new call sites each re-deriving
`bp === 'mobile' || landscape` is how the app got five ad-hoc height rules in the first
place (#1211).

## 3. The latent race, closed

`history.back()` is asynchronous. Between firing it and its `popstate`, the stack is
un-owned — and a push landing in that window creates an entry the in-flight traversal
pops **instead**, leaving the controller believing it owns an entry it does not. That is
verbatim the failure that got the first implementation reverted, triggered across two
commits rather than within one.

Nothing in the UI reached it: the drawer's own close-and-open hand-off coalesces into a
single reconcile, so the window never opened. Which means the safety margin was **React's
scheduling**, not anything the module enforced. `reconcile` now defers while
`pendingPops > 0` and `onPopState` re-schedules when the traversal lands — deferring must
never mean dropping, and there is a test for exactly that.

## What was deliberately NOT built

**Panel deep-linking**, which was on deck as *"the real fix for the post-reload
residual"*. The framing was wrong.

> Restore state on reload only if that state is **addressable**.

On the web, refresh is the universal "reset this" gesture. A restored overlay with no URL
cannot be shared, bookmarked, or escaped by re-entering the address. Native mobile does
restore navigation stacks, which is why the instinct feels right; the web convention is
the opposite — GitHub, Linear, Figma and Notion all drop the dialog on refresh unless it
is a route. It would also have needed an opt-out list so "Delete everything" did not
restore the sheet that had just wiped the workspace — a tell that the mechanism is
fighting the platform.

The residual is a **symptom** of the sentinel being a synthetic entry that corresponds to
no URL, and such an entry can always be orphaned by something outside our control. The
cure is to make panels routes, which *retires* this mechanism rather than extending it.
Filed as **#1231**, framed as URL-addressable panels rather than state restoration.
