# The generated bundles are built, not committed

**Follow-on from #1686.** Supersedes the design in
`2026-08-17-bot-owned-bundles.md`, which is retained as the record of a route not
taken and of why it was not taken.

## 1. The problem

`dist/` and the docs-site bundles were generated, committed, and regenerated by
any two PRs that touch `lib/`. Measured on `main`:

| | |
|---|---:|
| Commits touching `dist/` | **43 / 50** |
| Commits touching `dist/lattice-emulator{,.min}.js` | **28 / 50** |
| `dist/lattice.min.css` | 61 lines / 586 KB — **~9.6 KB per line** |
| Tracked files removed here | **194** |
| `npm run build` | **~16 s, no browser, byte-deterministic** |

A file with ~9.6 KB on a line cannot three-way-merge: any two branches that touch
it touch the same line. The merge queue rebases onto a `main` the PR has never
seen, cannot resolve the conflict, and ejects — **and an ejection silently clears
auto-merge**, so the PR then sits green, approved and un-queued with nothing
saying so. #1686 took three rebase cycles to land a change that was already green.

## 2. What shipped

`dist/`, `docs/public/playground/`, `docs/src/playground/*.generated.js` and
`docs/src/lib/*/dist/` are in `.gitignore`. `npm run build` produces them.

| Surface | How it gets them |
|---|---|
| **npm consumers** | Unchanged. `files` in package.json whitelists `dist/`, which **beats `.gitignore`** — verified: `npm pack --dry-run` lists **135 `dist/` files**, including the 6.8 MB `bin`. A new `prepack` runs the build so they exist at pack time. |
| **jsDelivr `/npm/` URLs** | Unchanged — they serve the npm tarball. |
| **CI** | Every job that loads the engine gains a `npm run build` step (unit, integration, golden-diff, docs-build, studio-smoke). |
| **The docs site** | `docs.yml` builds them before deploying. This is strictly *fresher* than before — see §5. |
| **A fresh sandbox** | `session-start.sh` builds them after `npm install`. |
| **The release** | `release.js` no longer stages `dist` (a silent no-op once ignored); the tarball is where they ship. |

`build:check` becomes `build.js --check --exclude-uncommitted`, skipping the 25
of 39 generators whose outputs are no longer committed. **This scoping is
required, not an optimization:** the gate's question is "did you commit the
regenerated artifacts you own?", which only has meaning when compared against a
checkout. Running `npm run build` first would make every file on disk fresh and
every check pass vacuously — so CI must not, and a checkout has no `dist/` for
those generators to compare against.

The surviving 14 generators keep their **own** `--check` semantics, which is
load-bearing: `build-decisions-index.js`'s is deliberately weaker than a byte-diff
(#1547) so two decision-doc PRs can share the queue.

## 3. The route here, because it is the actual lesson

This is the *first* thing that was recommended. It was abandoned, and the
abandonment was wrong.

**The objection.** `dist/marp-kit/` is a copy-and-go folder people browse and
download, and the `.min` files' stated purpose is "Production / CDN drop-in",
where jsDelivr's `/gh/` route serves any public repo path **without anyone
declaring it**. So an unknown number of external pins might 404, silently. That
was written down as **"UNVERIFIABLE from here (HARD RULE #23)"**.

**What followed.** An entire alternative was designed on that premise — keep the
bundles committed, forbid PRs from carrying them, add a workflow to rebuild them
on `main`. Two new tools, a workflow, a step-tagging scheme, two test files,
changed hooks and CI. An independent checker returned **do not merge** with three
reproduced blockers; it was rebuilt; a Munger inversion pass then asked the
question nobody had asked.

**The premise was never unverifiable.** jsDelivr publishes a free, unauthenticated
stats API:

```
GET https://data.jsdelivr.com/v1/stats/packages/gh/SlideWright/lattice?period=year
  → {"hits": {"total": 2}}
GET .../versions?period=year
  → [{"type":"commit","version":"471359d…","hits":{"total":2}}]
```

**Two hits, lifetime — and both against an immutable commit SHA, a pin that keeps
resolving forever no matter what `main` does.** Branch-pin fetches, the only kind
uncommitting could break: **zero**. Corroborating, all cheap: 1 star, 0 forks,
0 subscribers; **0 tags** (no release has ever been cut, so `/gh/` has no version
to resolve); `README.md` documents every entry point as `@workwel/lattice/…`, the
npm package; and `dist/marp-kit` appears in **no user-facing document** — only in
internal `engineering/` notes.

**HARD RULE #23 was read backwards.** It forbids *claiming* verification without
an artifact from the surface. It does not license treating an unmeasured hazard as
established and building around it. "I cannot verify this, therefore I must assume
the risk is real, therefore I will build machinery to avoid a reversible
decision" is the inversion of the rule, and it cost a full design cycle.

**The pattern, stated plainly because it has now recurred five times.** Across
this whole line of work — the render-cost assessment and both follow-ons —
*every measurement held and every assertion about a mechanism was wrong*: two
refuted explanations for the `networkidle0` wait, a "font-subset ordering" churn
cause that never churned, six wrong figures in prose, a boundary too greedy caught
only by measuring generator write sets, a freshness gate a reviewer rejected
outright. The remaining error always sat wherever measurement was skipped. Here it
sat in the premise.

## 4. What this fixes that the alternative did not

- **The ejection.** Both designs fix it.
- **History growth.** ~280 MB of derived blob churn over a 50-commit window stops
  accruing. The bot-owned design explicitly did not touch this.
- **The docs-site skew.** The alternative *introduced* one; this removes an
  existing one (§5).
- **`main` stays self-consistent.** Under the alternative, ~64% of commits would
  have carried bundles that did not match their own source, with the correction
  landing in a later commit — quietly breaking `git bisect` for anything
  bundle-mediated. Here every commit is consistent because the bundles are derived
  on demand.
- **No new machinery to carry.** No ownership boundary, no PR gate, no rebuild
  workflow, no per-merge queue traffic. `sync-backlog.yml`'s own header records
  that this repo already priced per-event queue trips and chose nightly instead;
  the alternative would have added ~20 a working day.

## 5. The docs site gets FRESHER, not staler

`docs.yml` triggers on `push: main` and previously ran only `npm ci`, deploying
whatever bundle happened to be committed. Its own comment warns about the
consequence: *"an engine/theme PR silently leaves the live playground on the
previously-deployed assets."* That was a real, live staleness. Building at deploy
time makes the deployed bundle match the deployed engine by construction.

## 6. What this costs — stated, not buried

- **A fresh clone is not immediately runnable.** `node dist/lattice-emulator.js`
  does not exist until `npm run build` (~16 s). Covered for the sandbox by
  `session-start.sh` and for CI by explicit build steps; a human cloning by hand
  meets it once. This is the real trade and it is the reason the decision looked
  close at the start.
- **~16 s added to five CI jobs**, browser-free.
- **The agent-facing catalog** (`dist/docs/components.*`, which `CLAUDE.md` tells
  agents to grep) is now built rather than checked out. The SessionStart hook
  builds it; an agent in an environment without that hook must build first.
- **Anyone with a `/gh/` branch pin breaks.** Measured at zero today, and the two
  historical hits are SHA-pinned and unaffected. **Reversible in one commit** if a
  consumer ever surfaces — which is the property that made this the right way to
  be wrong.

Gates: `npm run lint`, `npm test`, `npm run build:check`, `npm run test:integration`
— recorded in the PR.

**UNVERIFIED:** no CI job has actually run this. The build steps, the docs deploy
and `prepack` are reasoned and locally exercised, but a GitHub Actions run is the
real surface and it has not happened yet.
