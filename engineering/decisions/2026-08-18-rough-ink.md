# Rough ink — the sketch finish stops faking its lines

**Date:** 2026-08-18
**Status:** shipped
**Supersedes (in part):** `2026-06-11-sketch-finish.md` §"The load-bearing constraint: PDF fidelity"
**Related:** `2026-08-13-sketch-mermaid-hand-drawn.md`, `2026-08-12-sketch-label-voice.md`

---

## What was wrong

The `sketch` finish shipped in June with two faked primitives, because the real
thing was believed to be unavailable:

| Intent | How it was faked |
|---|---|
| a hand-drawn **box** | asymmetric `border-radius` + an offset `box-shadow` + an `nth-child` micro-rotation |
| a hand-drawn **line** | `--sketch-wave` — one sine path used as a **tiling** `mask` at 140×7px |

Rendering `examples/sketch.md` and looking at a table showed four separate
problems in one object:

1. **The wave is a sine, not a stroke.** Constant amplitude, constant frequency,
   mathematically periodic. It reads as a word-processor squiggle. A pen wavers
   at low frequency with varying amplitude and bows gently over a long run.
2. **The tile re-phased at every column seam.** The rule was a `td::after`, so
   each cell restarted the 140px tile at its own left edge and a single row rule
   visibly broke mid-span.
3. **Three line languages inside one table.** The frame was a *smooth* rounded
   rectangle with perfectly straight edges; the `thead` underline was a precise
   two-pixel `--spectrum-structure` gradient strip; only the horizontal row
   rules got the ripple.
4. **The offset "ink" read as a drop shadow** — gray, uniform, down-right. A
   material signal, not an ink one.

And separately, on every masthead slide, **two rules stacked**: `section.sketch
h2` drew its own bent underline under the words, and
`section.form .cell-masthead` drew a machine-straight `1px solid var(--border)`
hairline about 50px below it.

## Why rough.js is available now, and was not in June

The June record vetoed the authentic look for a **specific and correct** reason,
validated by a spike: an SVG `filter` — `feTurbulence` + `feDisplacementMap` —
renders on screen but **collapses the print-scale transform**, so the slide
shrinks into a corner of the PDF page.

That finding stands. It just does not reach rough.js.

**Rough.js uses no filter.** It emits plain `<path d="…">`. The June note
generalized a filter result into "the authentic rough.js look depends on exactly
that risky primitive", and that inference was wrong — rough.js's whole method is
to *generate wobbled path geometry*, not to distort a rendered raster.

The counter-evidence was already in the repo, one slide away. Since
`2026-08-13-sketch-mermaid-hand-drawn.md`, `mode: sketch` flips Mermaid to
`look: 'handDrawn'`, which is rough.js (mermaid 11.14 bundles roughjs 4.6.6) —
so a sketch deck was rendering a genuinely hand-drawn flowchart on page 10 and a
CSS-faked table on page 11, both through the same Chromium → PDF pipeline.

`roughjs` is now a direct dependency (MIT, 28KB ESM, ~9KB gzipped). It was
already in the tree transitively via `@mermaid-js/mermaid-cli`.

## The technique, and where it comes from

Modeled on [`rough-table`](https://github.com/h-kono-it/rough-table) (MIT), which
solves problem 2 above directly. Its load-bearing idea is its `solid` mode:

- a row rule is **one** line spanning the whole structure — `rc.line(0, y, W, y)`
  — not one segment per cell;
- a column rule is **one** full-height line per unique x, deduped through a Set;
- the real CSS borders are switched off and an absolutely-positioned SVG carries
  every line.

One stroke per boundary is what makes a hand read continuous.

**Lattice differs in one place, deliberately: it does not wrap each structure in
a container.** `rough-table` wraps the `<table>` in a positioned `<div>`; doing
that here would insert a wrapper between `section.X` and its `> table` / `> ol`
and silently break every direct-child component selector in the engine. Instead
there is **one overlay per `<section>`** — the slide is already
`position: relative` + `isolation: isolate` (`base.elements.css`) — and each
structure's paths are translated into section coordinates by `shiftPath`.

## Shape

Three steps, split across two modules so the two render paths share one
implementation without sharing one runtime:

```
measureRoughInk(structures)   lib/core/rough-ink-dom.js   reads laid-out DOM  → plans (plain JSON)
pathsForPlan(plan)            lib/core/rough-ink.js       runs rough.js       → path d strings
paintRoughInk(paints)         lib/core/rough-ink-dom.js   writes one SVG per section
```

- **`lattice-emulator.js`** measures in the Chromium page, ships the plans back
  to Node, **generates there** (rough.js is a normal `require`, DOM-free), and
  paints back in the page. Rough.js never enters the export's browser context —
  nothing to inject, nothing to bundle, no second copy to keep in step.
- **`lib/runtime/index.js`** does all three in one tick with rough.js bundled in,
  re-running through the shared `schedulePostMutation` dispatcher.

Both call the same three functions in the same order, so a line's shape cannot
drift between the Playground and the exported PDF (HARD RULE #1).

### Enrollment is CSS-driven

The selector registry (`ROUGH_INK_STRUCTURES`) is only a cheap prefilter. What
decides whether a structure is inked is a non-empty **`--rough-ink-stroke`** on
it, with `--rough-ink-width` for weight.

That indirection is load-bearing for the masthead, whose rule has a four-way
answer already owned by `base.accent-finish.css`: the band's `border-bottom`
under `rule-full`, a real `<hr class="masthead-rule">` under `rule-short` /
`rule-accent`, and nothing under `rule-none`. Asking the cascade "is there a rule
here, and what color" keeps that answer in the one file that owns it. Deriving it
in JS from `border-bottom-style` cannot work anyway — see the next section.

It also lets a *pseudo-element* rule be inked without measuring the pseudo. The
agenda ledger's active-row rule is an `::after` pinned `left:0; right:0;
bottom:0` on the row, so the row's own bottom edge is the rule's line; the
`progress-N` + `nth-child` chain in `base.sketch.css` enrolls exactly one `li`
out of the broad prefilter. Every other row keeps its dotted leader, which is a
*different mark* and reads fine in the hand.

### The borders go transparent, never away

`base.sketch.css` hides a replaced line with `border-color: transparent`, never
`border: none`. A removed border changes the box model, so the structure would
resize the instant the ink applied and every measurement behind the overlay would
be one border-width stale — then the re-measure would find a different box, and
repaint, and shift it again.

### Progressive enhancement, and where it bites

The ink is painted by script after layout settles. `paintRoughInk` stamps
`rough-inked` on `<html>` when it has run, and every fallback rule in
`base.sketch.css` is gated on `:root.rough-inked` — so a document that never runs
the runtime still shows rules, just the old periodic ones, rather than a
borderless table.

**Which artifacts carry the ink:** PDF, PNG, PPTX, and `--player` (its DOM bake
runs *after* the ink pass, which is why the pass sits where it does). **Which do
not:** the plain `.html` sidecar and the `.html` deliverable, which are written
from the server-side `cleanDocHtml` string and ship no runtime. Those fall back
to the wave. Not a regression — it is what they showed before — but it is a real
gap, and closing it means giving `.html` the live-DOM bake the player already has.

### Determinism

Every `rough.js` call passes an explicit `seed`, derived (FNV-1a) from the
structure's key plus the line's index. Two renders of one deck are byte-identical,
while two lines in one table still get different hands. **Never call
`rough.newSeed()` on this path** — the committed PDFs, `tools/pixel-check.js` and
the screenshot tier all diff renders of the same deck, and an unseeded call would
not fail a build, would not look wrong, and would make every sketch baseline
permanently dirty.

## Two things the first cut got wrong

Both were caught by rendering and looking, and both are worth recording because
neither would have failed a gate.

**1. It invented column rules.** The first `grid` implementation drew every
column boundary, and a horizontally-ruled comparison table became a spreadsheet.
Checked afterwards: **none of the three table components rules columns** —
`compare-table` and `glossary` declare no vertical border at all, and
`obligation-matrix`'s only one is a `6px double var(--accent)` fold marker that
carries *meaning* and must never be flattened into a plain ink line. This broke
the finish's own governing rule, stated at the top of `base.sketch.css`: *the
finish roughens lines the deck draws; it never invents one.* Columns are now
opt-in per component via `--rough-ink-cols: 1`, and nothing sets it.

**2. Bowing is not normalized by line length.** Rough.js computes the mid-point
displacement as `bowing * maxRandomnessOffset * (x1 - x2) / 200`, so it scales
**linearly with span**. A `bowing` that looks like a pleasant curve on a 150px
segment became a ~30px sag across a 1700px slide rule — and because the stroke is
drawn twice, the two passes bowed apart and closed at the ends, leaving a
lens-shaped gap down the middle of every rule, sagging through the text above.
Shipped values (`roughness: 1.8`, `bowing: 0.5`) hold total deviation to roughly
3–4px whatever the span, with proportionally more character on a short line than
a long one — which is also what a hand does.

A third, smaller one: the masthead rule was first drawn in `var(--border)` at
1px, faithfully matching the hairline it replaced. At the palette's lightest
structural gray a rough stroke is indistinguishable from a straight one, so the
slide simply lost its heading underline and gained nothing visible. It is now the
sketch ink at 55% via `color-mix` — a pen stroke, still quieter than the heading.

## The stroke is validated at the crossing

Found by asking "does this need the adversarial trio?" and probing rather than
reasoning.

`--rough-ink-stroke` is read out of the cascade and written into an SVG `stroke`
attribute. A deck author's own `<style>` block participates in that cascade, and
`stroke` takes a `<paint>` — which includes `url(…)`. Measured in a `--fluid`
export opened in Chromium with request interception:

```
stroke attrs:  ["url(https://beacon.invalid/t.svg#p)", …]
outbound:      ["https://beacon.invalid/t.svg"]
```

One request per opened copy — the beacon HARD RULE #22 names as the harm off the
docs site, where there is no key to steal and the payload rides in every copy the
*recipient* opens.

**It is not a bypass, and the capability is not ours to close.** The same probe
against plain author CSS — `background-image: url(https://…)`, nothing to do with
this feature — fires the identical request today, and
`lib/core/sanitize-style-text.mjs` says so in terms: *"it is not a CSS sanitizer
and must not become one … everything a stylesheet can do AS a stylesheet (fetch a
font, repaint a token) it is meant to be able to do."*

What this module must not do is add a SECOND route to it. Taking a value back OUT
of the cascade and re-injecting it as a DOM attribute is precisely the third shape
#22's docblock warns about — the one no gate sees. So the value is checked at the
crossing with `CSS.supports('color', …)` (the browser's own parser, the only thing
guaranteed to agree with what the attribute will accept), and a non-color falls
back to `currentColor`. A hostile deck loses the ink's COLOR, never its rules —
skipping the structure would leave it with no lines at all whenever something else
on the slide inked and tripped the `:has(> svg…)` gate. Re-measured after the
guard: `stroke="currentColor"`, zero outbound requests.

The pre-existing author-CSS beacon is logged here rather than fixed: it is off the
path of this change, and closing it is a decision about `sanitize-style-text.mjs`'s
stated scope, not about the sketch finish.

## What is still faked

**Boxes.** Cards (the `CARD_STYLE_LAYOUTS` family), blockquotes,
`actors` / `checklist` / `list` bordered rows, and the agenda's rings, cards and
check boxes all still bend a `border-radius` and carry an offset `box-shadow`.
They are the announced next slice; the two mechanisms are not layered where they
overlap, because stacking a blur under a wobble reads as neither.

**The agenda rail** (`agenda.rail > ol::before`) keeps `--ag-rail`, its own
vertical tiled wave. Unlike the active-row rule, its geometry is not derivable
from a real element's box.

**Chart marks.** Unchanged and still deferred to the chart-family SVG work, per
the June record.
