# A QR plugin (2026-10-16)

Status: proposed. The owner's open decisions are in §6. Sibling: `2026-10-16-media-plugins.md` (the `video`
plugin is the QR service's third caller). Parents: `2026-09-27-plugin-system.md` (the contract, including
`services` and a component's `plugins.optional`), `2026-10-14-plugin-inline-door.md` (`@kind{…}`),
`2026-07-01-qr-authoring-grammar.md` (the `qr` variant and its postfix-key bullets, which this note keeps).

## 1. The answer

- **One plugin, `qr`, owns QR codes.** It holds the encoder (`lib/engine/qr.js` today), the payload rules
  (`qr-payload.js`), the card kernel (`connect/_qr-card/qr-card.js`) and the QR styles. The engine stops
  importing `qrcode`.
- **Any slide can carry a code**, written as a Segno record in inline code:

  ```md
  `@qr{https://laticent.com/join, caption="Scan to join"}`
  `@qr{mailto:team@example.com, sm}`
  `@qr{"Plain text to encode", ec=H}`
  ```

  A paragraph holding only the record renders as a block figure, beside or below the slide's content. A
  record inside running text renders as a small inline code.
- **The layouts that draw a code today keep their syntax and call the plugin's service.** `wifi` and
  `contact` declare `plugins.requires: ["qr"]`; `video` declares `optional: ["qr"]`, so a video slide without
  the plugin still shows its poster. The `qr` variant (`closing qr`, `divider qr`, `split-panel qr`) stays as
  authored and requires the plugin.
- **A deck with no code loads none of it**, the way icons and avatars work.

## 2. What exists today

Checked against the source on 2026-10-16.

| Piece | File | Role |
|---|---|---|
| Encoder | `lib/engine/qr.js` (76 lines) | `qrSvg(data, {ecLevel, margin, label})`: wraps `qrcode`'s synchronous SVG renderer and makes it palette-blind (`currentColor` modules, `transparent` ground) |
| Card kernel | `lib/components/connect/_qr-card/qr-card.js` | parses `- value \`key\`` bullets and builds the two-zone card for `wifi` and `contact` |
| `qr` variant | `_qr-card/qr-general.transform.js`, adapter `lib/transformers/qr-general.js` | adds a `<figure class="qr-figure">` to `closing`, `divider` and `split-panel` |
| Payload rule | `_qr-card/qr-payload.js` | `PAYLOAD_URL_RE` (`https?:`, `mailto:`, `tel:`, `WIFI:`, `BEGIN:VCARD`), shared with `lint-core.js:4423` |
| Lint | `lib/authoring/lint-core.js:4417-4447` | `qr-missing-payload`, `qr-empty-payload`, `qr-duplicate-payload` |
| Styles | `_qr-card/qr-general.css`, bundled always by `tools/build-css.js:176,570` | the QR figure and caption |
| Tokens | `--qr-ink`, `--qr-paper` (`tools/check-ownership.js:12380`) | per-deck module and quiet-zone colors |
| Callers | `wifi`, `contact`, `video` (`video.transform.js:97`), the `qr` variant | four layouts, one encoder |

**Cost today:** `lib/transformers/registry.js:50` requires `qr-general`, which requires the encoder, which
requires `qrcode` at module load. Measured here: requiring `lib/engine` leaves `qrcode` in the module cache,
and `require('qrcode')` alone takes 31–36 ms cold (three runs). Every CLI render and every Studio engine
start pays it, with or without a code in the deck. The QR styles are in every deck's CSS bundle too.

**What an author cannot do today:** put a code on a slide whose layout is not one of those six. A
`statement`, a `chart` or a `team-profile` slide cannot carry one.

## 3. The model

**Manifest contributions** (`lib/plugins/qr/qr.manifest.json`):

| Contribution | What |
|---|---|
| `inline.qr` | the `@qr{…}` kind; no sigil (§6, decision 2) |
| `services` | `encode(data, opts) → svg`, `card(fields, layout) → html`, `payloadKind(value)`; the callers in §1 |
| `registers.qr` | a deck-level `qr:` register: `size` (`sm`, `md`, `lg`), `frame` (`framed`, `bare`), `ec` (`L`, `M`, `Q`, `H`) |
| `styles` | `qr-general.css` and the card styles, loaded only when the plugin is |
| `tokens` | `--qr-ink`, `--qr-paper` |
| `render` | `parity: "equivalent"`, `degradesTo: "source"`: a deck that switches the plugin off shows the payload as text |

**The record's fields:** the payload (first bare value; a quoted string for text with commas),
`caption="…"`, `label="…"` (the accessible name, defaulting to the caption or the payload), `ec=`, and the
size words. A payload is encoded verbatim, as today: the encoder never rewrites what the author wrote.

**The payload is not a media source.** `@qr{asset:x}` encodes the text `asset:x`. A QR carries data to a
phone; it never loads anything at render time, so the sources registry in the sibling note does not apply.

**PDF, PNG and PPTX** get the same SVG they get today. The HTML player and the presenter can also make the
code a link to its own payload when the payload is a URL, as the video poster already is.

## 4. Build order

1. **Move, no visible change.** Create `lib/plugins/qr/`, move the encoder, payload rule, card kernel and
   styles into it, expose them as services, and switch the four callers to the service. Byte-identical output
   on the `connect` and `video` galleries, checked by the existing gallery renders. `npm run bench` before and
   after for the engine start (HARD RULE #19), since the point of the move is that a deck with no code stops
   paying for `qrcode`.
2. **`@qr{…}` on any slide**, the `qr:` register, lint rules for an empty or unencodable payload, Compose and
   autocomplete through the `@` trigger. Demo deck (HARD RULE #9).

One checker on slice 1 (it touches the transformer registry and the CSS bundle); slice 2 self-reviews with the
gates.

## 5. Options not taken

- **Leave the encoder in the engine and only add `@qr{…}`.** Every deck keeps paying for `qrcode`, and the
  code stays outside the plugin contract that icons and avatars already follow.
- **Make `qr` part of the `video` plugin.** `wifi` and `contact` have nothing to do with video.
- **Retire the `qr` variant in favor of `@qr{…}`.** The variant is a settled grammar
  (`2026-07-01-qr-authoring-grammar.md`) with three lint rules, and on those layouts it places the code where
  the layout expects it. The two forms coexist, and both call one service.

## 6. Open decisions (owner)

1. **Packaging alongside the media plugins.** The media packaging question is on hold; this note assumes `qr`
   is its own plugin whatever that question decides, because its callers are not all media.
2. **A sigil for `@qr{…}`.** `INLINE_TAGS` (`lib/plugins/resolve.js:419`) holds `~ ^ !` and the media note adds
   `>`. Recommendation: none for now, since codes are rarer than icons and the tag set is small.
