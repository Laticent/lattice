## 3. Lint behavior — what `unknown-class` actually checks (lib/authoring/lint-core.js:5128)

Accepts a token if it is: a component name; in `vocab.modifiers` = MODIFIER_GROUPS ∪ EVERY component's
effective variants ∪ FAMILY_MODIFIER_TOKENS ∪ image-card register (lib/authoring/lint.js:157-166);
a MODE_TOKEN; a DEPRECATED_CLASS (`full` `contain` `museum`); or starts with a MODIFIER_PREFIX.
Probed with `lintText` (probe2.js):

| Input | Result | Meaning |
|---|---|---|
| `statement no-heaer`, `with-anything`, `with-finsh`, `tone-blah`, `fill-xyz`, `checks-typo`, `treatment-foo`, `at-nowhere`, `finish-bogus`, `finishzz` | clean | open prefixes wave typos through |
| `kpi gallery`, `statement heat`, `statement canvas`, `statement briefing` | clean | any component's variant / family modifier / alias is accepted on any component |
| `tint-bogus` style | `unknown-treatment` | tint-/mark- are closed by treatments.js |
| `tint-corner top-left`, `tint-edge bottom` | `unknown-class` on the placement | treatments.js PLACEMENT_REQUIRED says `top-left`/`bottom` are equal spellings; CSS paints them (base.treatments.css:92, :158); lint flags them — contradiction |
| `statement print` | `unknown-class` | color-mode token; deck-only by design |
| `statement venue-hall` | `spot-scale` info | register class used per slide |

## 5. Phantoms and contradictions

Phantoms (documented, not defined): none found among live tokens. Every backticked `prefix-word` in
base.docs.md / base.registers.docs.md that is not in the vocabulary is a lint-rule name
(`marks-renamed`, `tag-budget`, `guards-renamed`) or a documented RETIRED spelling (`spectrum-on`,
`finish-none` at base.docs.md:954; reference/switches.md:91-102 retired list). `no-title` (base.docs.md:119)
is a `_pane` marker word, not a `_class` token — not a phantom but a third class-like vocabulary.
Stale references: lib/core/switches.mjs:68 says "the reserved-class vocabulary reads this" — tools/build-packages-index.js
never references SWITCH_TOKENS; `with-spine/-finish/-backdrop/-treatment` are absent from reserved names (covered only by the `with-` prefix).

Contradictions:
1. base.docs.md:960 "the full set is defined … as UNIVERSAL_GROUPS" vs index.js:504-537 (MODIFIER_GROUPS is the registry; 62 vs 343).
2. design/design-system.md:442 "Tier 1 — Universal (51 variants)" vs 62 in code; its table says Chrome (5) vs 11, Note (2) vs 3, Table (3) vs 9.
3. design-system.md Tier 4 lists `mirror`, `numbered` as layout-specific; base.docs.md:997/:1017 lists them under "Universal variants"; code: `aliases` group, offer:false, component-scoped but lint-accepted everywhere.
4. `light`: base.docs.md:972 "Universal variants"; index.js:447 "base modifier rather than a universal VARIANT"; MODIFIER_GROUPS `mood` (offered).
5. `silent`: base.docs.md:1105/1113 "header, footer, and pagination … equivalent to no-pagination + _header/_footer"; switches.mjs:40-45 + reference/switches.md: header, footer, page number AND rail.
6. `sketch`: base.docs.md:1119 "the hand-drawn finish"; it is a `mode:` token, and `finish:` is a different register.
7. Bare treatment placements: treatments.js PLACEMENT_REQUIRED accepts them; `unknown-class` flags them.
8. CLAUDE.md #6 routes "base modifiers" to base.docs.md, which never uses the phrase.
