# LFM 1.0 §2.3 lists `finish:` with the values that now belong to `mode:`

why now   — The spec page on the site tells a reader that `finish:` takes `boardroom | sketch | sketch-clean`; in the engine those are `mode:` values, and `finish:` is the backdrop register (atrium, halo, …). Appendix A's worked example writes `finish: boardroom`, which `lint:deck` flags. §2.3 also says `finish:` and `logo:` are "the complete LFM-added front-matter surface", while the engine reads about 60 keys (docs/src/content/docs/reference/front-matter.mdx lists them). The diagnostics registry has `unknown-finish` but no `unknown-mode`.
where     — spec/LFM-1.0.md:72 and Appendix A (~:405); spec/diagnostics.md:91. The site pages are generated by tools/build-spec-docs.js.
done when — The owner decides which keys LFM 1.0 standardizes (it is a normative document, so not an agent's call); §2.3, Appendix A and the diagnostics registry say that, with a version-history row; `npm run docs:spec` regenerates the site pages.
evidence  — Front-matter inventory on #2348: `resolve-mode.js:58` reads the boardroom/sketch values under `mode:`; `resolve-finish.js:67` reads backdrop names under `finish:`.
verify    — Appendix A's example deck lints clean.
