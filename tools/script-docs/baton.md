The relay baton (HARD RULE #31): may this session push to a relay branch now? `status|take|release [branch]` reads the newest first-parent commit's Relay-Actor / Claude-Session trailers plus the PR's `<!-- relay-handoff -->` comment; free only on `baton: released` (under the holder's own name, at the current tip) or with `--override` when a person said "take over"; no clock frees it. `rescue` pushes commits git rejected after a lost race to `relay-rescue/<branch>/<session>` (no force) and notes it on the PR; `status` lists waiting rescues; `release --pause` marks a usage stop (90%); `release` names this session in the comment's `holder:` line if it still names an earlier holder. `take` claims a free baton by pushing an empty commit with your trailers (no force), so of two takers one is refused at once; it refuses a branch with no open PR. `take` refuses a ready PR (park it first, even with `--override`) and a branch parked at the merge gate; `release --gate` parks it.
