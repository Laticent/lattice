Edge-shift sweep: does choosing a different spectrum-bar placement MOVE anything on the slide? Renders one deck (every component's skeleton in light and dark, plus plain slides carrying each state stamp) once per `spectrum-edge:` value with header, footer and page number on, measures every element's distance from each slide edge in Chromium, and reports any element whose position differs between placements. The bar is a real `border`, so it takes layout room. `check:jank` asks whether a layout stays put as CONTENT grows; this asks whether it stays put as the BAR moves. `--placements`, `--components`, `--limit`, `--family`, `--theme`, `--tolerance PX`, `--no-dark`, `--no-chrome`, `--detail`, `--json`, `--advisory`. `--variants` adds each component's manifest variants, `--classes "a b"` adds modifiers to every slide (`footer-inset`, `claim-bleed`, `safe`), `--each-class all` renders one slide per reserved class, `--front-matter "spectrum: off"` sets a deck-level register, and `--positions FILE` writes every element's position so two builds can be compared. The `finish:` backdrop is not measured: it ends where the bar begins by design. Exits 1 on any shift, 2 when it could not measure (no Chromium, or a placement that did not take effect, which would make it compare a deck with itself); on-demand, not a CI gate. Header of `tools/check-edge-shift.js` has the method.
