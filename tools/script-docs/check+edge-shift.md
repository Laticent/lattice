Edge-shift sweep: does choosing a different spectrum-bar placement MOVE or CROWD anything? Renders one deck (every component's skeleton in light and dark, plain slides carrying each state stamp and each of the thirteen stamp styles) once per `spectrum-edge:` value with header, footer and page number on, measures every element's distance from each slide edge in Chromium, and fails on: an element whose position differs between placements; a full-bleed frame whose overlay strips are malformed, or an opted-out component that draws a bar; text or chrome sitting inside the strip the bar occupies; a dark slide that steps from its light twin. `check:jank` asks whether a layout stays put as CONTENT grows; this asks whether it stays put as the BAR moves. Flags: `--placements`, `--components`, `--limit`, `--family`, `--theme`, `--tolerance PX`, `--no-dark`, `--no-chrome`, `--detail`, `--json`, `--advisory`, `--variants`, `--classes "a b"`, `--each-class all`, `--front-matter "spectrum: off"`, `--positions FILE`, `--bars`. The `finish:` backdrop is not measured. Exits 1 on a failure, 2 when it could not measure. Runs in the integration tier (test/integration/invariants/spectrum-edge-shift.test.js). Header of `tools/check-edge-shift.js` has the method.
