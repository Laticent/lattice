Jank sweep: does a component's layout STAY PUT as its content grows? Renders one slide per content step through the CLI (the deck built from the component's own manifest skeleton, so the documented chrome is in it, plus any per-slide directive only its sample carries, such as `topic`'s `_track`), measures the real geometry in Chromium, and reports the three failures every fit gate is blind to — anchor DRIFT (a mark that wanders as the heading wraps), silent COLLISION (an absolutely positioned box and a flex-centered one reach each other and NEITHER overflows, so no ⚠ OVERFLOW line, no ring, no clipped tag) and CROWDING (ink into the section's padding, inside the frame, untagged). Everything else in the repo asks does it FIT; this asks does it STAY PUT. `--anchor 'h2::after'` names what must hold still; `--max-growth PX` also fails a mark that changes SIZE (DRIFT deliberately ignores edge-pinned growth); `--axis heading|count|words`; `--style` injects CSS so a fix can be proved by sweeping with it neutralized; `--json`. On-demand, not a CI gate (a Chromium sweep in the merge train is a flake generator); exits 2 with no Chromium, never a silent pass. engineering/jank.md.
