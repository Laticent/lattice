A seeded fuzz of how the web-reference scanner reads Mermaid diagrams, against the real Mermaid drawing them, in Chromium, WebKit and Firefox. It generates Markdown with one fenced diagram (test/fixtures/mermaid-ref-fuzz.js: backticks or tildes, three to six, a language with attributes or none, indented, quoted or in a list) carrying an `img:` shape, an `<img>` label, `themeCSS` with a `url()` or a `click … href`, the address spelled with entity codes, Mermaid's `#58;`, a dropped tab, capitals or `//host`. Each input is rendered by the real engine; the blocks the runtime draws (the plugin registry's `DRAWN_FENCE_CODE`) are drawn with the vendored Mermaid at the runtime's config and every drawn link is clicked in a frame of its own, against a loopback server. The control draws everything; the scanned arm draws only what `blockWebImages` lets through and fails on any request. `--seed`, `--count`, `--from`, `--engines`, `--json`; `--ref <git ref>` or `--scanner-file <path>` scans with another scanner (`test/fixtures/naive-diagram-scanner.js` is the failing arm). On-demand (HARD RULE #22).
